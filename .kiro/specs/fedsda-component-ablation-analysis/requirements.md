# 要件: 現行FedSDAの構成要素比較

## 目的・範囲
混合予測・FIFO30・共通時間尺度T120を基準に、研究室サーバで実行中の6構成を、既存のT120結果と対応付けて比較する。精度低下の許容幅は未設定で、採否は人が判断する（2026-10-17ユーザー決定）。学習・設定・goldenを変更せず、結果の読取りと分析成果物の作成だけを行う。

## 1. 比較可能性
1.1 CLIは基準構成ディレクトリとアブレーション実験ディレクトリを受け取り、format_version=2のrun JSONを読む。対応するNPZの安全な単一ファイル名と存在を確認し、生配列は読まない。
1.2 CLIは明示したdataset、seed、集約間隔、client数、標本数の期待格子を使う。既定は6データセット・seed0–4・間隔50/100/200/500・10client・5000標本である。
1.3 対象runは同じ実行条件で対にする。完全なrun設定を現行の構成builderで生成した設定と照合し、不一致・重複・不正JSON・欠損NPZを診断し、そのrunを比較しない。期待格子外のrunは除外数と理由を出す。
1.4 比較するrunの数値環境が一致し、来歴が有効かつcleanであることを確認する。基準と異なるcommitまたは動作基準版を使う場合は明示オプションによる確認を要求し、許可しても実際の来歴と注意点を報告する。同じ設定でも異なるコードの同等性を自動認定しない。

## 2. 数値比較
2.1 dataset×間隔×構成×指標ごとに基準と変更構成の平均・標本標準偏差、同seedの差の平均・標準誤差・最小・最大・改善/同値/悪化件数を出す。データセットを横断する総平均は出さない。
2.2 全体精度・安定期精度は百分率とpercentage point差で示す。通信量・計算量は総量と標本当たりを扱い、モデル数・検出指標も補助情報として示す。スイッチ遅延を精度回復時間と呼ばない。
2.3 null・非有限値・非数値は0に置き換えず、指標ごとの有効対数と欠損を示す。1対だけなら標準偏差・標準誤差は未定義とする。
2.4 不足・比較不能を含む場合も利用可能な対を報告するが、完了扱いにしない。指標別の欠測は全runの欠落とは区別する。

## 3. 出力・研究上の判断
3.1 CLIはMarkdownとseed単位のCSVを新規のanalysisディレクトリに保存し、入力成果物を上書きしない。stdoutモードではファイルを作らない。入力誤りはexit2、run不足/比較不能はexit1、run格子の比較が完全ならexit0とする。指標の未定義だけではexit1にしない。
3.2 報告は実行コマンド、分析日時、入力絶対パス、対象格子、全入力来歴・環境、除外理由、欠けた対、指標の単位・差の向き・対数を含む。NPZ内部や失敗履歴の検証は行わず、run欠落を実験失敗と断定しない。
3.3 報告と手順は許容幅未設定・自動採否なし・探索的な5seed比較を明示する。独立モデル構成は複数要素の変更として注意する。現行の要素比較と、未使用seedによる最終比較、追加ベースラインの評価を分離する。
3.4 実験の実在パスや実行revisionが未提供なら捏造せず、適用手順と記録項目を示す。

## 入出力の契約例（公開境界: main）
| 条件 | 許される結果 | 検証 |
|---|---|---|
| 全期待runが一意・設定一致・環境一致 | exit0、全対を報告 | complete_grid |
| 期待seedの変更runなし | exit1、存在する対と欠けたキーを報告 | missing_run |
| 来歴差あり・許可なし | exit1、その対を除外 | provenance_difference |
| 同じ条件の正しい基準が二つ | exit1、恣意的に選ばない | duplicate_baseline |
| 指標がnull | その指標の有効対数を減らす、0にしない | undefined_metric |
| 存在しない入力ルート | exit2、分析ファイルを作らない | invalid_input |
| stdout | 入力ディレクトリを変更しない | stdout_read_only |

性質: 入力列挙順を変えても統計値は同じ。基準と変更が同じ値なら全差は0。対のないseedは平均に混入しない。エラー文言・小数桁・Markdownの装飾は自由である。

### Requirement 4: 共通検証からの研究用解析の分離
4.1. The analyzer shall 共通Ruff登録・通常pytest収集・共用freshから独立した研究用CLIとして保持する。
4.2. The analyzer shall 既存の解析計算・入力/出力形式を維持し、tools/research_component_ablation内から実行・明示検証できる。過去の結果は変更しない。
