# 学習要求の記録と保有モデルの共同学習 — 要求 revision3

研究者が、標本ごとの学習要求から保有モデルの共同学習と学習量の計数までが旧と同じに進むことを確かめられるよう、完了済みの部品をつなぐ。

## 境界

最終構成（共有部も更新する共同学習、標本数加重平均の勾配）。完了済みの部品（学習要求の件数管理、共同学習の反復、保有モデルの学習状態、モデル別の標本、モデル別の学習量の計数）をつなぐ。各部品の中の処理は変更しない。学習要求の件数管理には、保留が更新間隔に達したかを状態を変えずに読む操作だけを足す。

これらの処理を標本1件の処理・警報の前・ラウンド境界のどこで呼ぶか、共有部を凍結する診断用の学習方式、計算量・所要時間・勾配の診断、新client・全体runは除外する。並行更新は保証しない。

## 1. 学習要求と学習

- 1.1 When 学習要求を1件受けたとき, the Training Request Handling shall 要求を記録し、保留中の要求が更新間隔に達していなければ学習を行わずに空の結果を返す。
- 1.2 When 学習要求を受けて保留中の要求が更新間隔に達したとき, the Training Request Handling shall 保留中の全要求のぶんの回数だけ保有モデルを共同学習し、保留を0件にして、完了した共同更新の損失を順に返す。
- 1.3 When 保留中の要求の学習を明示的に求められたとき, the Training Request Handling shall 更新間隔に達していなくても保留中の全要求のぶんを同じ手順で学習する。保留が0件なら、学習へ渡す値を読まず、何も変えずに空の結果を返す。
- 1.4 When 一要求あたりの共同更新回数が0であるとき, the Training Request Handling shall 学習を行わず、1.2・1.3と同じ条件で保留を0件にする。
- 1.5 The Local Training Request Schedule shall 保留中の要求が更新間隔に達しているかを、状態を変えずに返せる。その結果は、一要求あたりの共同更新回数に依らない。

## 2. 学習量の計数

- 2.1 When 共同更新が1回完了したとき, the Training Request Handling shall 次の共同更新より前に、参加した各モデルについて、学習した標本数（batchの件数）と更新回数（1）を計数へ加える。参加するのは、保有していて、標本がbatchの件数以上あるモデルである。
- 2.2 While 共同更新が完了しなかった回では, the Training Request Handling shall 計数を変えず、計数の項目も作らない。
- 2.3 The Training Request Handling shall 保留の消化を、全回の共同更新と計数の後に行う。割当概念の計数、標本、損失統計、現在の学習帰属は変えない。

## 3. 検査と失敗

- 3.1 If 学習要求の件数管理・保有モデルの学習状態・モデル別の標本・学習量の計数のownerの型が不正であるとき, the Training Request Handling shall 要求の記録を含むどの状態も更新する前に拒否する。
- 3.2 If 共同学習が途中で失敗したとき, the Training Request Handling shall 保留中の要求を消化しない。失敗より前に完了した共同更新と、そのぶんの計数は残す。記録済みの要求は取り消さない。完了済みの共同更新の巻戻しと自動の再試行は行わない。
- 3.3 3.1の範囲は、本処理が読むowner 4つとする。学習へ渡すだけの値（batchの件数、乱数生成器、学習の設定、共有部とそのoptimizer）は共同学習の反復が検査し、学習へ進まないとき（保留が間隔に達していない、保留が0件、一要求あたりの共同更新回数が0）は検査されない。学習へ進んでも、参加するモデルがない回では、共同更新の入力（学習の設定、共有部とそのoptimizer）は検査されない（旧も、参加するモデルがない回は共有部に触れない）。

## 4. 対照

- 4.1 When 同じ正常入力・固定環境で同じ要求と消化の列を実行したとき, the Training Request Handling shall 実旧clientの学習step（`train_step`・`flush_pending_updates`と共同学習）の後の、全モデルのparameter・grad・optimizerの状態、乱数の状態、モデル別の学習標本数と更新回数、保留中の要求の件数と一致させる。共同更新の合間で失敗した場合の、完了済みの更新・計数・保留の件数も一致させる。
- 4.2 The change shall 固定旧実装とgoldenを変更せず、既存の全回帰を維持する。
