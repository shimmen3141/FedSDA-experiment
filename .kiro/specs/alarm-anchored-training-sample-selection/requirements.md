# Requirements Document

## Project Description (Input)
- 誰が困っているか: FedSDAの精度を、FedDrift・FedAvgと比べている研究者（ユーザー）。
- 今の状況: 保有モデルの学習batchの抜き出し方として、全履歴・直近K件・指数減衰αを選べる（held-model-training-sample-recency）。直近K件とαは、データの変化の速さに合わせる調整値で、変化の時点は使わない。一方、sea2では、警報の後もFedSDAが同じモデルを使い続ける（警報57.5回のうち、ほとんど）。このとき、検出器は「概念は変わったが、同じモデルで続ける」ことを知っている。
- 何を変えるか: 警報の後に同じモデルで続けると決まった時点を、そのモデルの保存に区切りとして残し、区切りより後の標本を重く使う抜き出し方を、選べる設定として足す（区切りより前を使わない形と、αで減衰させる形）。既定の動作と値は変えない。

## Introduction
2026-10-14〜15の会話で、ユーザーは、直近K件・指数減衰αの実装（held-model-training-sample-recency）の次に、警報を区切りに使う方法を実装し、研究室サーバの本規模の掃引で比べると決めた。K・αの本規模の掃引（seed 0〜4、240 run）は、サーバで実行中で、その結果を見て、区切りより前の扱い（使わないか、αで減衰か）のどちらを本規模で比べるかを選ぶ。このspecでは、両方を設定の水準として足す。

## Boundary Context
- 対象: 保有モデルの学習標本の保存（区切りの記録、ID の付け替えと統合での扱い）、区切りを付ける2つの警報の後の処理、抜き出しの関数の2つの新しい抜き出し方、設定の許す値、掃引の軸の書き方、文書。
- 対象外: 区切りの付け方のほかの案（モデルを切り替えたとき・候補を採用したとき）、FedDrift、既定の変更、比較script。
- 仮定（ユーザーが決めていない点）: 区切りは、そのモデルごとに最新の1つだけを持つ。モデルの統合で、複数のモデルの列がつながったときは、区切りを消す（つながった列のどこが新しい概念かが決められないため）。区切りが無いモデル（警報の後に同じモデルで続けたことがまだ無い）は、全履歴から一様（区切りより前の標本と同じ扱い）とする。区切りは、同じモデルで続けると決まった時点で付けるので、候補の検証の間に別の警報が来て、保留の全部（検証の窓の標本を含む）を今のモデルへ足したとき、それらは区切りより前になる（候補の検証が始まることは少なく、影響は小さいと見る。最初の警報の位置を検証に持たせる形は、変更の範囲が広がるので採らない）。なお、候補の検証の間は、保存の列の順が時間の順と一致しない部分ができうる。原因は2つある。(1) 検証の間に別の警報が来ると、保留の全部（検証の窓の標本）を今のモデルへ足し、検証の区間の標本は、検証の確定で後から足す。このとき、区切りは確定の吸収の前に付くので、検証の窓の標本の後・区間の標本の前になる（窓の件数や容量に依らず起きる）。(2) 検証の窓の件数が保留の容量を超えると、検証の間に、保留から古い標本が今のモデルへ足される。既定（窓10件・容量30件）では(2)は起きないことを前提とする。区切りを付けない結果: 別のモデルの再利用、候補の採用、短い警報、候補の検証の間の警報、runの終わりの検証の打切り。別のモデルへ切り替えたモデルの区切りは、古い時点を指したまま残り、そのモデルに後で足された標本は、その区切りより後として扱われる。

## Requirements
### Requirement 1: 区切りを記録する
**Objective:** As a 研究者, I want 警報の後に同じモデルで続けると決まった時点が、そのモデルの保存に残ること, so that 抜き出しが、変化の後の標本を見分けられる。
#### Acceptance Criteria
1. When 警報の区間の評価で、今のモデルが選ばれた（今のモデルを維持）とき, the FedSDA system shall 警報の区間の標本をそのモデルの保存へ足す直前の保存の長さを、そのモデルの最新の区切りとして記録する。
2. When 候補の検証の後に、候補が退けられた、または参照に今のモデルが選ばれた（今のモデルに戻る）とき, the FedSDA system shall 検証の標本をそのモデルの保存へ足す直前の保存の長さを、そのモデルの最新の区切りとして記録する。
3. When モデルのIDが付け替わったとき, the FedSDA system shall 区切りを新しいIDへ移す。When 統合で複数のモデルの列が1つにつながったとき, the FedSDA system shall つながったモデルの区切りを消す。1つの列がIDだけ変わったときは、区切りを移す。
4. The FedSDA system shall 区切りの記録で、既定の抜き出し方の乱数の使い方と結果の値を変えない。

### Requirement 2: 区切りを使う抜き出し方を選べる
**Objective:** As a 研究者, I want 区切りより後の標本を重く使う抜き出し方を選べること, so that 調整値の無い（または少ない）新しさの重み付けを比べられる。
#### Acceptance Criteria
1. When 区切りより後から一様（`uniform_after_latest_alarm_boundary`）が選ばれたとき, the FedSDA system shall 各モデルのbatchを、最新の区切りより後の標本から、重複なしで一様に抜き出す。区切りより後の標本がbatchの件数より少ないときは、列の末尾からbatchの件数の標本から抜き出す。区切りが無いモデルは、全部の標本から一様に抜き出す。
2. When 区切りより前を指数減衰（`recency_decayed_before_latest_alarm_boundary`、α）が選ばれたとき, the FedSDA system shall 各モデルのbatchを重複なしで1件ずつ選び、各回、まだ選んでいない位置の中で、区切りより後の位置の重みを1、区切りより前の位置の重みをα^（区切りから数えて何件前か。区切りの直前が1）として、重みに比例する条件付き確率で選ぶ。区切りが無いモデルは、全部の位置の重みを1とする。1件あたりの手数は、列の長さに依らず、選んだ件数だけで決まり、αがどれほど小さくても決まった手数で終わる。
3. If 設定の値が不正（区切りより後から一様にαを指定した、区切りより前を指数減衰にαを指定しない・範囲外）, the FedSDA system shall runを始める前に拒否する。

### Requirement 3: 掃引の軸
**Objective:** As a 研究者, I want 掃引で、区切りを使う抜き出し方も並べられること, so that K・αと同じ掃引で比べられる。
#### Acceptance Criteria
1. The sweep command shall 抜き出し方の軸の書き方に、`alarm`（区切りより後から一様）と`alarm-decay:<α>`（区切りより前を指数減衰）を足す。一覧の表の列も、同じ書き方で表す。

### Requirement 4: これまでの照合を保つ
**Objective:** As a 開発者, I want 既存のgoldenと照合が値を変えずに通ること, so that 既定の動作が変わっていないと確かめられる。
#### Acceptance Criteria
1. The validation shall 基準版1〜5のgoldenと、実旧との照合を、値を変えずに通す。

### Requirement 5: 文書
**Objective:** As a 研究者, I want 文書が新しい抜き出し方を説明すること, so that 掃引のコマンドを正しく書ける。
#### Acceptance Criteria
1. The documentation shall 実験の入口の文書の抜き出し方の表と、研究バックログの7に、区切りを使う2つの抜き出し方と、区切りを付ける時点を書く。
