# Requirements Document

## Project Description (Input)
- 誰が困っているか: FedSDAの精度を、FedDrift・FedAvgと比べている研究者（ユーザー）。
- 今の状況: FedSDAの保有モデルの学習は、そのモデルへ割り当てた全部の標本を上限なく保存し、学習要求ごとに、その全履歴から一様にbatchを抜き出す。1つのモデルが複数の概念を受け持つsea2では、モデルが履歴全体の平均へ合わせられ、FedDrift・FedAvgより精度が低い。直近300件から抜き出す試作（手元、実行の中だけの差し替え）で、sea2の精度が+0.3〜0.5ポイント上がった（研究バックログの7）。
- 何を変えるか: 学習のbatchの抜き出し方を、設定で選べるようにする（全履歴から一様＝今の既定、直近K件から一様、新しい標本ほど選ばれやすい指数減衰）。掃引のコマンドで、この選び方を軸として比べられるようにする。既定の動作と値は変えない。

## Introduction
2026-10-14の会話で、ユーザーは、直近の範囲指定と減衰係数αの重み付けを実装し、手元で当たりを付けてから、研究室サーバで掃引すると決めた。警報を区切りに使う方法は、次のspecで扱う（このspecの結果を見て、区切りの前の重みを決める）。

## Boundary Context
- 対象: FedSDAの保有モデルの学習（学習要求の処理の中の共同更新）のbatchの抜き出し、その設定、掃引のコマンドの軸と一覧の表の列、goldenの照合での新しい設定の項目の扱い、文書。
- 対象外: 候補の学習・事前学習・FedDriftの学習（同じ抜き出しの関数を使うが、選び方は今のまま）、標本の保存（上限は設けない。保存の順は今のまま）、警報を区切りに使う方法、比較scriptと分析script、既定の変更。
- 仮定（ユーザーが決めていない点）: 新しさは、保存した順（そのモデルの標本の列の位置）で測る。モデルの統合で列がつながった直後は、保存の順が観測の順と一致しない（研究バックログの7に記録済みの限界）。

## Requirements
### Requirement 1: 学習のbatchの抜き出し方を選べる
**Objective:** As a 研究者, I want 学習のbatchを、全履歴・直近K件・指数減衰のどれで抜き出すかを選べること, so that 新しさの重み付けがFedSDAの精度に効くかを比べられる。
#### Acceptance Criteria
1. The FedSDA system shall 抜き出し方の設定を持ち、既定は全履歴から一様（今の動作）とする。既定のとき、乱数の使い方と結果の値は、今と同じ。
2. When 直近K件が選ばれたとき, the FedSDA system shall 各モデルのbatchを、そのモデルの保存した標本の列の末尾K件から、重複なしで一様に抜き出す。
3. When 指数減衰が選ばれたとき, the FedSDA system shall 各モデルのbatchを、重複なしで1件ずつ選び、各回、まだ選んでいない位置の中で、列の末尾から数えてa件前（a=0が最新）の位置が、αのa乗に比例する条件付き確率で選ばれるようにする（0<α<1）。標本の列の長さに比例する追加の記憶や計算を持たず（1件あたりの手数は、選んだ件数に比例し、列の長さに依らない）、αがどれほど小さくても、決まった手数で終わる。
4. If 設定の値が不正（Kがbool以外のbuiltin intでない・batchの件数より小さい、αがbuiltin floatでない・0以下・1以上・有限でない、選び方と値の組合せが合わない）, the FedSDA system shall runを始める前に、設定の検査で拒否する。
5. The FedSDA system shall 学習に使えるモデルの条件（保存した標本がbatchの件数以上）を変えない。

### Requirement 2: 掃引で、抜き出し方を軸として比べられる
**Objective:** As a 研究者, I want 掃引のコマンドで、抜き出し方を複数並べて実行できること, so that 研究室サーバで1回の掃引で比べられる。
#### Acceptance Criteria
1. The sweep command shall FedSDAの構成について、抜き出し方の一覧（`uniform`、`recent:<K>`、`decay:<α>`）を軸として受け、全部の組合せを実行する。FedSDAの構成を含まない計画では、拒否する（引数の誤り、終了コード2）。
2. The run summary table shall FedSDAの構成の行に、抜き出し方の列を持つ。この項目を持たない前の要約の行は、表から外さず、空の欄にする。
3. When 軸を指定しないとき, the sweep command shall 今と同じ条件の計画（既定の抜き出し方だけ）を作る。FedSDAのrunの識別子は、run設定の保存の形が変わるので、変わる（案Yの既定の変更のときと同じ。前の結果のrunは、新しい計画の済んだrunとして扱われない）。

### Requirement 3: これまでの照合を保つ
**Objective:** As a 開発者, I want 既存のgoldenと照合が値を変えずに通ること, so that 既定の動作が変わっていないと確かめられる。
#### Acceptance Criteria
1. The validation shall 基準版1〜5のgoldenと、実旧との照合を、値を変えずに通す（新しい設定の項目は、どの版でも既定の値であることを確かめてから、比較から除く）。
2. The validation shall 直近K件で、Kが標本の列の長さ以上のとき、既定と同じ標本の集合から抜き出すこと（乱数の使い方の違いは許す）を確かめる。

### Requirement 4: 文書
**Objective:** As a 研究者, I want 文書が新しい設定と掃引の軸を説明すること, so that サーバのコマンドを正しく書ける。
#### Acceptance Criteria
1. The documentation shall 実験の入口の文書で、掃引の軸と、抜き出し方の意味（Kとαの目安: 影響が届く範囲は約1/(1−α)件）を書き、研究バックログの7に、実装したことを書く。
