# 要求

## 1. 成果物の保護
- 新版を専用worktreeの `docs/overview/fedsda-processing-flow-v2.html` として作成する。既存HTML、元checkout、実験コード、既存完了specを変更しない。stage・commit・pushしない。

## 2. 図の表現
- 一画面の固定SVG、対象の濃淡、コマ送り・再生・直接選択を維持する。
- 最短15図単位の接続でも、矢尻だけでなく連続した軸が見える。矢尻を線幅に連動して巨大化させず、短い線は破線アニメーションを使わない。
- サーバ配布時モデル0/1/2と、対応するローカル更新モデル0′/1′/2′を上下で対に示す。バックボーンにも配布時／更新後のパラメータ状態を示す。学習では配布時側を薄く、更新後側を濃くし、配布時側へ学習矢印を入れない。
- 長い用語は初出・凡例で示し、図では「配布時」「更新後」を使う。混合予測を既定とする（今後の既定というユーザー指示。参照コードの既定とは区別）。

## 3. 共通列と分岐
- 横一列の段階で予測→監視/FIFO→警報判定→警報応答→将来標本の検証→サーバ共有を示す。分岐の選択肢は縦並び。現在の段階・選択枝・対象外の段階を判別できる。
- 平時／警報待ち／警報成立を選択でき、平時と待ちは共通コマを共有し、待ちのみA01/W01を追加する。既存再利用／候補作成は警報成立後の分岐とする。
- 候補を作った場合のみ、将来標本での予測→検証確定→監視/FIFO/学習を続ける。既存再利用／採用／棄却の選択を提供する。候補は検証中に学習しない。
- サーバ共有はラウンド境界の別時間であると示し、表示／省略を選べる。採用後の待機・新規登録は採用枝だけに表示する。その他の共有は周期的なラウンド例として示す。
- 分岐・予測構成の変更は再生停止し、共通コマ上ならそのコマを維持、消えた枝上なら最長共通prefixの末尾へ戻す。最初から見るボタンと全体表示を別に持つ。

## 4. 検証
- 1440×900/1280×720で図と操作部全体が一画面。390×844では全図と明示拡大を提供する。
- 全分岐組合せ×3予測構成で順序・切替・コマ送り・再生停止・固定位置を実ブラウザで検査。短い矢印、対モデル、分岐操作を画像でも確認する。
- HTML/JSのみのためPython数値試験は実施しない。独立CLIの仕様・実装レビューを行う。
