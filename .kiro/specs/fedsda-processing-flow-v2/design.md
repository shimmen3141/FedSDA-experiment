# 設計

## スコープ
旧single-canvas版を入力にv2だけを作る。図の位置と既存frameのアルゴリズム意味を再利用する。旧表示のpathタブを段階列＋縦ラジオ群へ置換する。

## 合成するコマ列
既存single-canvas/design.mdのframe定義を参照する。PはP01..P07（単独構成ではP05を省略）、NtailはN03..N05。
1. P → N01 → N02。
2. 平時: Ntail。警報待ち: A01,W01,Ntail。警報成立: A01..A06 → 既存再利用A07、または候補作成C01..C03。
3. 候補作成のみ: **別の将来標本**のP → V01,V02,V03 → 採用/棄却ならV04 → V05,V06,N02,Ntail。V06は当該標本の監視なのでN01を重ねない。既存再利用ではV04を省く。
4. 共有表示時: 採用があるときのみR01,R02。その後R03..R11。非採用枝のR04は別clientの新規登録等で統合条件を満たした周期的ラウンドの例と明記する。同期は各標本の必須後処理ではなく別時間の例。

各要素は{frame,stage,epoch}。epochは最初の標本sample、候補作成後の将来標本future、共有ラウンドroundの3値で、その区切りだけで切り替える。同じP等が再登場してもepochを含む一意キーを持つ。選択変更で同じキーを維持、無いなら旧新列の最長共通prefix末尾（共通prefix無しは先頭）。旧V05でのadopt/reuse/reject契約を再利用。現行★は通過したA07/V05で変化し、R03だけで新規採用を捏造しない。

## 図
中央のモデル枠内、3列それぞれ上が配布時0/1/2、下が更新後0′/1′/2′。両方が残差アダプタ＋分類ヘッドを持つ。バックボーンactor内も2状態の箱を持つ。既存models/backbone actorの外枠は固定し、内側状態はframeに応じて濃淡を制御。学習矢印は下側境界へ入り、配布時行を通らない。配布で更新後へ受け渡し→R10で配布時写しを保存する順序を維持。予測欄も同じ対応記号を出す。
矢尻はmarkerUnits=userSpaceOnUse、6×6図単位程度、refX=6。線の長さ<45または最後の区間<12は短線としsolid、その他は旧破線アニメーション。短線は静止でも方向が読み取れる。

## 操作・レイアウト
上部を2行に分ける。第一行は予測構成・全体/先頭・再生/送り。第二行は6段階の横方向rail（高さ約94px）、各段に縦ラジオ。選択結果で無効化される段は対象外ラベル、disabledラジオとする。段名ボタンで該当段先頭へ移動（全体表示からも可能）。初期は警報成立→候補→採用→共有の例、図は全体O01から始める。初回次送り/再生で合成列先頭へ。
上のrail増加分をSVGの上下余白縮小で吸収する。1280×720で図の主ラベル12px/補助10pxを下回る場合はSVGviewBoxの空き上下をトリミングし、余白だけ削る。狭幅railは横スクロール。図は一画面fit＋明示拡大。

## 検証方針
既存headless Chrome CDP runnerをv2用に分離。選択枝3×応答2×検証3×共有2×予測3を走査（無効枝の重複は許容）。P重複はepoch付きで検査。通常/低モーション、keyboard、直接移動、分岐の共通位置保持とprefix帰還、再生終端、短線の実計測とCSS、学習時の配布時減光、全画面fit、旧HTMLのhash不変を確認。HTML外へ通信しない。
