# Design Document

## Overview
旧HTMLは一枚の固定SVGにモデル・ストア・監視・検証・serverを置き、複数目的の矢印を同時に載せている。全体図（何がどこにあるか）と処理別のコマ（いつ何を渡すか）へ分離する。入力・正解・予測結果の時系列を最初に示し、重み更新用・監視用の損失を別の用途として説明する。

## Boundary Commitments
- 所有: 専用spec、作業コピー`docs/overview/fedsda-processing-flow.html`、検証後の元checkoutの同名HTMLへの反映。
- 対象外: Python source/test/golden、既定や実験結果の変更、他worktreeのspec/resume編集、保留HTMLのstage/commit。
- 許す依存: インラインHTML/CSS/JSとSVG。外部font/CDN/library/storage/fetchなし。
- 再検証条件: 説明基準の実装変更、各処理順/登録/予測重みの契約変更、図の配置・操作変更。

## Architecture
全体図は静的HTMLで、clientとserverの境界、モデル構造、予測と学習の関係を示す。詳細は6章（予測、平時、警報、候補検証、同期、必要なら全体への復帰）のうち、全体を含む6つのナビ（全体・予測・平時・警報・候補検証・同期）。モデル構造は全体に常設。章ごとのカードの位置はコマ間で固定する。

コマは説明レコード（タイトル、本文、活性ノード、送り元・受け手、受渡しラベル、結果、注意）から描画。詳細図は交差しない直列の機構カードを基本とし、予測のみ同期・局所の二つのレーンを隣接配置する。矢印はカード間の専用余白に置く。込み入る戻りは遠い矢印で接続せず、次のコマで受け手を明示する。文章による同一の受渡し表示を図の直下にも置く。

選択状態は章・予測構成・警報分岐・検証結果・現在コマ・timerのみ。選択変更時はtimer停止→コマ先頭→図/説明/ステップを再描画。次/前は範囲内に留める。最終コマで再生停止。フォームとリンクの操作中にキー入力を奪わない。非表示の予測構成でも監視と学習は局所側のまま。

### 表示内容の契約
| 項目 | 表示 |
|---|---|
| 入力 | 全体で特徴xと正解yを定義。各章の受渡し文でも意味を併記。複数の入力トークンを出現させない |
| モデル | 共有バックボーン→モデル別残差アダプタ→分類ヘッド。モデルA/Bは概念の真値でなく保有モデルの例 |
| 混合 | 同期/局所の同じモデル重み→各結合確率→二者の重みで確率を混ぜる→出力→正解で次回重み更新 |
| 損失 | 1−正解クラス確率。モデル別重み更新は同期側、二者は各結合確率、検出は局所現行モデル。学習の勾配用損失と区別 |
| 写し | 配布後に保持。局所更新では不変。写しのない新規モデルの固有部は局所側、共有特徴は利用できる同期写しから |
| 警報 | 合図だけでは不足時に警報としない。非警報と同じ容量超過分の帰属と学習。前区間の取込み、既存維持/再利用、候補開始 |
| 検証 | 初期学習済み候補と固定参照を新着標本で比較。評価→候補も初期学習後は追加学習しない。既存再適合を先に調べ、その後前半/後半の優位で候補採否 |
| 登録 | 現行として待つ方針。別モデルが現行なら待ち停止。連続の待ちへ勝手に言い換えない |
| 同期 | 新規登録可能時のみ統合を有効化、集約対象複数も必要。生データではなくモデル・統計・損失評価結果。配布→写し更新→FIFOでモデル重み再較正。二者重みは保持 |

## Testing Strategy
- 実装前: 仕様群の独立CLIレビュー。taskグラフはinlineのbounded sanity確認後、同じ仕様レビューで独立に確認する（内蔵子エージェントは使わない）。
- 構造: HTML parserでID一意、内部リンク解決、全コマに起点/受け手/受渡し/結果、外部通信なし、JS構文。
- 操作: DOMを使うブラウザで全章・3予測構成・警報/検証分岐、前後と直接移動、再生停止・終端停止・変更時停止、キーボード、エラーなし。
- 視覚: 広い画面と狭い表示で、文字の切れ、カード重なり、矢印の交差、フォーカスと選択、低モーションを確認する。ブラウザ機能の制約があれば実施範囲を記録する。
- 数値の新規検証は不要（説明専用、Python変更なし）。全pytestは実行せず、その事実とソース無変更を記録。実装後の独立CLIには内容と構造/操作検証の証拠を渡す。このHTML専用scopeの適用を仕様レビューで確認する。
- 最後にClaude側HEADの差分を確認し、説明関連の変更があれば反映・再検証する。元HTMLはバックアップsha256と照合して他者編集がないことを確認して反映する。

## 処理別の詳細な行き先
- 警報なし（待つ扱いを含む）: FIFOへ足した後、容量超過の最古標本を現行モデルのストアへ一度だけ割り当て、局所学習要求を記録して期限の更新を行う。
- 警報あり: 先に保留中の局所学習要求を消化→FIFOの推定変化点前を現行ストアへ吸収・評価標本保存→変化区間を既存評価。維持/再利用なら変化区間を選んだモデルのストアへ、候補開始なら変化区間をsessionの帰属保留へ移す。通常の容量超過の解放は同じ標本では実行しない。保持中の検証に重なる警報では、新しい候補を重ねて作らずFIFOを現行へ吸収する既存経路を補足する。
- 検証: session開始の標本より後の規定件数で、初期学習済み候補と警報時点の固定参照を評価（候補も検証中の追加学習なし）。規定到達時は今も利用できる既存モデルの履歴許容に基づく再適合を先に調べ、あればそのモデルを維持/再利用し帰属保留をそこへ。なければ最小損失の参照に対する候補の平均損失の改善を時系列前半/後半でともに要求。採用なら候補を保有集合へ加え現行にし帰属保留を新ストアへ、棄却なら現行ストアへ。現在到着した検証標本は損失の記録後に同じ標本の通常監視/FIFO処理へ進む。sessionの帰属保留（警報時の変化区間）と将来評価標本を混同しない。規定未到達の終端は候補を採用せず帰属保留を現行へ回収する。
- 同期条件: 全clientの通常同期は間隔の境界で行う。新規登録可能フラグでクラスタリングを有効化し、そのうえで登録後の集約対象モデルが複数ある場合だけクロス評価・統合を実行する。条件を満たさなくても集約・配布・再較正は行う。複数でも判定が統合不可なら別モデルのまま。
- 同期写しfallback: 同じID/同じ分類器の写しがあればその固有部を使い、なければ局所の固有部を使う。共有特徴は利用できる同期写しの最小IDのモデルから計算し、利用できる写しが一つもなければ最小IDの局所モデルから計算する。
