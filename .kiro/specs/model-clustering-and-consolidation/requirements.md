# Requirements Document

## Project Description (Input)

誰の問題か: FedSDAとFedDriftの比較実験コードをリファクタリングしている研究者（主担当と、後で読む人）。

現在の状況: サーバは、登録・集約・クロス評価・配布・集約後の再較正を、部品として行える。旧の最終構成のサーバは、新規モデルがあるラウンドで、クロス評価の結果からモデルをクラスタリングし、同じクラスタのモデルを1つへ統合して、モデルIDの対応を配布へ渡す。新には、クラスタリングと統合がなく、ラウンド全体をつなぐ処理もない。

変えたいこと: クラスタリングと統合を、旧と同じ順序・数値で行い、サーバの1ラウンドの同期（登録→集約→［クロス評価→クラスタリング→統合］→配布→全clientの再較正）を1つの呼出しにする。

調査で確かめたこと（固定旧748c3aa。最終構成は、判定`class_functional_confidence`、linkage `average`、後処理`merge`、信頼水準0.95）:

- ラウンド（`servers/fedsda.py`の`run_round`、`servers/shared_backbone.py`の`run_round`）: 登録→集約→（クラスタリングが有効なら）`_cluster_and_consolidate`→配布（ID対応つき）→全clientの再較正。クラスタリングが有効かどうかは、実験の枠が、登録の前に、送信できるモデルを持つclientがいるかで決める。
- `_cluster_and_consolidate`: 対象（全clientが保有する非負のID。昇順）が1つ以下なら、何もしない。クロス評価→クラスタリング→診断の記録。クラスタの数が、対象の数より減らなければ、空のID対応。減れば、統合して、ID対応を返す。
- クラスタリング（`servers/clustering.py`の`perform_hierarchical_clustering`）: 対（対象の列の順で、前のID・後のID）ごとに、(1)診断として、真の概念の一致（両方のモデルに、割当の最多の概念が一意にあるとき）と、概念固有部のパラメータの相対距離を求める。(2)4つの損失の統計（自分どうし2つと、互いの2つ）の件数が、どれかでも下限（`CLUSTER_MIN_EVAL_N`=5）未満なら、この対は判定しない。(3)距離＝互いの平均損失の増加の、大きいほう。(4)対の正誤の集計がなければ、判定の値を持たない。あれば、判定の値＝クラス別の、片方だけが正解した割合の、同時信頼下限の最大（件数が下限以上のクラスだけを使う。そのようなクラスがなければ全体を使う。左右とクラスの数でBonferroni補正したWilsonの片側下限）。(5)判定の値と閾値（`distance_threshold`）で、average linkageの逐次統合を行う。
- average linkage（`clustering.py`の`_agglomerative_linkage`）: 1モデル1クラスタから始め、クラスタの対のうち、全部のモデル対に判定の値があるものについて、値の平均を求め、（平均、左のクラスタ、右のクラスタ、位置）の最小の対を選ぶ。その平均が閾値を超えたら終わり。そうでなければ統合して、クラスタの列を並べ直す。
- 診断の記録（`model_lineage.py`の`record_clustering`）: 距離を持つ対ごとの観測（距離、判定の値（なければ距離）、同じクラスタか、真の概念の一致、パラメータの距離）と、モデルごとの観測（最も近いモデルと距離、代表、クラスタの大きさ、クラスタ内の最大の距離・距離を持つ対の数・ありうる対の数、統合に加わったか、吸収されたか）。
- 統合（`servers/fedsda.py`の`_merge_clusters`ほか）: クラスタごとに、代表（最小のID）へ、全メンバーのIDを対応させる（1モデルのクラスタは、自分自身への対応）。2モデル以上のクラスタは、パラメータを、集約の件数（学習データの総件数）での加重平均にし（件数がすべて0なら、代表のパラメータのまま）、損失統計を、統計を持つメンバーの、件数での加重平均にする（件数の合計が0なら、変えない）。代表でないIDの、グローバルモデルと統計を消す。
- 配布は、ID対応が空でなければ、軽量メッセージを数える。ID対応は、自分自身への対応を含む。

## Introduction

研究者が、クラスタリングと統合、および、サーバの1ラウンドの同期の全体を、旧と同じ結果になる呼出しで行えるようにする。これで、サーバのラウンドを、クラスタリングを含めて、旧の`run_round`そのものと照合できる。

## Boundary Context

- **In scope**: 判定の計算（Wilsonの下限、クラス別の同時信頼下限、average linkage）。クロス評価の結果からの、対ごとの距離・判定の値・診断値の計算、クラスタリング、診断の記録、統合（パラメータと統計の加重平均、代表でないモデルの削除、ID対応）。クラスタリングの診断の記録のowner。グローバルモデルのownerの、モデルを外す操作。clientの、モデルの割当概念の計数を返す操作。サーバの1ラウンドの同期の関数。
- **Out of scope**: 最終構成でない判定・linkage・後処理（距離だけの判定、標準化した増加、真の概念による判定、connected・complete、パラメータの共有、非劣性の検証）。実行の枠のサーバの操作の実体と、全clientとサーバの準備、全体runの接続（次のspec）。診断の記録の保存と集計。
- **Adjacent expectations**: 登録、集約、クロス評価、配布、受取り、再較正は、移植済みの部品をそのまま使い、中の処理を変えない。

## Requirements

### Requirement 1: 判定の計算

**Objective:** As a 研究者, I want モデル対の判定の値とクラスタが、旧と同じ式で求まってほしい, so that 統合されるモデルが旧と同じになる

#### Acceptance Criteria

1. When 成功数・標本数・信頼水準を与えたとき, the Clustering Calculation shall Wilsonの片側信頼下限（0未満は0）を返す。
2. When モデル対の、全体とクラス別の「評価した標本数・それぞれの側だけが正解した数」を与えたとき, the Clustering Calculation shall 標本数が下限以上のクラス（なければ全体）について、左右とクラスの数で補正した信頼水準でのWilsonの下限を、両方の側について求め、その最大を、判定の値として返す。
3. When モデルIDの列・対ごとの判定の値・閾値を与えたとき, the Clustering Calculation shall average linkageの逐次統合（全部のモデル対に値があるクラスタの対だけを候補にし、値の平均が最小の対を、平均が閾値以下の間、統合する）で、決定的なクラスタの列を返す。
4. If 入力が、決まった型と範囲でないとき, the Clustering Calculation shall 拒否する。

### Requirement 2: クラスタリング

**Objective:** As a 研究者, I want クロス評価の結果から、旧と同じ対だけが判定され、旧と同じクラスタになってほしい, so that 統合の対象が旧と同じになる

#### Acceptance Criteria

1. When クラスタリングを求められたとき, the Clustering shall クロス評価したモデルIDの列の順の、全部の対について、4つの損失の統計の件数がすべて下限以上の対だけに、距離（互いの平均損失の増加の、大きいほう）を与える。
2. When 距離を持つ対に、正誤の集計があるとき, the Clustering shall 判定の値を与える。集計がなければ、判定の値を与えない（距離だけを持つ）。
3. The Clustering shall 判定の値を持つ対と閾値から、average linkageでクラスタを求める。
4. The Clustering shall 診断として、対ごとに、真の概念の一致（両方のモデルについて、全clientの割当概念の計数を足し合わせたときの、最多の概念が一意にあるときだけ）と、概念固有部のパラメータの相対距離を求める。これらは、判定に使わない。

### Requirement 3: 診断の記録

**Objective:** As a 研究者, I want クラスタリングの診断の記録が旧と同じになってほしい, so that クラスタリングの診断を旧と比べられる

#### Acceptance Criteria

1. When クラスタリングを行ったとき, the Clustering shall 距離を持つ対ごとに、（小さいID、大きいID）の順で、距離、判定の値（なければ距離）、同じクラスタか、真の概念の一致（なければなし）、パラメータの距離を記録する。
2. When クラスタリングを行ったとき, the Clustering shall モデルごとに、渡された列の順で、最も近いモデルと距離（距離が同じなら小さいID。距離を持つ対がなければなし）、代表のID、クラスタの大きさ、クラスタ内の最大の距離（なければなし）、クラスタ内の距離を持つ対の数とありうる対の数、統合に加わったか、吸収されたかを記録する。
3. The 診断の記録 shall クラスタの数が減らなかった（統合しなかった）クラスタリングでも、記録を足す。

### Requirement 4: 統合

**Objective:** As a 研究者, I want 同じクラスタのモデルが、旧と同じ値の1つのモデルへ統合されてほしい, so that 統合の後のグローバルモデルと、clientの状態が旧と同じになる

#### Acceptance Criteria

1. When クラスタの数が、クラスタリングしたモデルの数より少ないとき, the Consolidation shall 全メンバーのIDを、クラスタの最小のID（代表）へ対応させたID対応（1モデルのクラスタの、自分自身への対応を含む）を返す。そうでなければ、空のID対応を返し、グローバルモデルを変えない。
2. When 2モデル以上のクラスタを統合するとき, the Consolidation shall 代表のパラメータを、メンバーのパラメータの、集約の件数での加重平均（件数が0のメンバーは除く。件数がすべて0なら、代表のパラメータのまま）にする。
3. When 2モデル以上のクラスタを統合するとき, the Consolidation shall 代表の損失統計を、統計を持つメンバーの、件数の合計と、件数での加重平均の平均損失（偏差平方和は0、クラス別はなし）にする。件数の合計が0なら、代表の統計を変えない。
4. When 統合したとき, the Consolidation shall 代表でないメンバーの、グローバルモデルのパラメータと損失統計を外す。次の正式IDと来歴は変えない。
5. The Consolidation shall 計算を、グローバルモデルの最初の更新より前に済ませる。

### Requirement 5: サーバの1ラウンドの同期

**Objective:** As a 研究者, I want サーバの1ラウンドの同期を、1つの呼出しで、旧と同じ順に行ってほしい, so that 実行の枠から呼べる

#### Acceptance Criteria

1. When 同期を求められたとき, the Server Round Synchronization shall 登録→集約→（クラスタリングが有効で、集約の対象のモデルが2つ以上なら）クロス評価→クラスタリング→統合→配布（ID対応つき）→全clientの再較正（渡されたclientの順）、の順に行う。
2. When クラスタリングが無効か、集約の対象のモデルが1つ以下のとき, the Server Round Synchronization shall クロス評価・クラスタリング・統合を行わず、空のID対応で配布する。
3. The Server Round Synchronization shall 各段の結果（登録、集約、クロス評価、統合、配布、再較正）を返す。

### Requirement 6: 実旧との一致

**Objective:** As a 研究者, I want クラスタリングを含むラウンドが、旧のサーバの`run_round`と同じ結果になってほしい, so that 全体runの接続へ進める

#### Acceptance Criteria

1. When 同じ初期モデル・統計・設定・標本列・乱数を与えたとき, the 同期 shall 実旧のサーバの`run_round`（クラスタリングは、登録の前に、送信できるモデルを持つclientがいるラウンドだけ有効。再較正の方式は`fifo_replay`）と、実`__init__`で作った実旧のclient複数に対して、ラウンドごとに、サーバの全状態（グローバルモデル、統計、次の正式ID、来歴、通信量）、クラスタリングの診断の記録、各clientの全状態、乱数の状態が一致する。
2. The 対照 shall 2モデルの統合、3モデル以上が1つへ集まる統合、統合しないクラスタリング、距離を持たない対（評価の件数が足りない）、統合の後のラウンド（clientが付け替わった状態で進む）、同じrunでの2回めのクラスタリング、2値と多クラスを通る。
3. When 判定の計算へ同じ入力を与えたとき, the Clustering Calculation shall 実旧の対応する関数（Wilsonの下限、クラス別の同時信頼下限、average linkage）と、同じ値を返す。

### Requirement 7: 拒否

**Objective:** As a 研究者, I want 不正な入力が、状態を変える前に拒否されてほしい, so that グローバルモデルが、途中まで統合されたまま残らない

#### Acceptance Criteria

1. If clientの列、owner、クロス評価の結果、集約の件数、判定の基準、ラウンドが、決まった型と範囲でないとき, the Clustering and Consolidation shall どの状態も変える前に拒否する。
2. If 同期の途中の段が失敗したとき, the Server Round Synchronization shall 後の段へ進まない。済んだ段は残る（巻戻しなし）。
3. The Clustering and Consolidation shall 並行した呼出しでの結果を保証しない。

### Requirement 8: 新実装だけで動くことと依存の向き

**Objective:** As a 研究者, I want クラスタリングを含むラウンドが、旧実装なしで動いてほしい, so that 後続のspecへ進める

#### Acceptance Criteria

1. When 共用のfresh processの確認を実行したとき, the 共用script shall 旧実装とtestのmoduleを読み込まずに、サーバの代役が、ラウンドごとに同期の関数を呼び、クラスタリングが1回以上行われ、記録が足されたことを確かめられる。
2. The クラスタリングと統合 shall 新しいmoduleの依存を、既存と同じ形で登録した許可の範囲に収める。
