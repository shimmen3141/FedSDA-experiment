# 警報1回ぶんの処理の接続 — 要求 revision1

研究者が、警報が起きた標本での処理を1つの呼出しとして追えるよう、完了済みの部品（警報応答、完了処理、適応記録、候補検証sessionの保持、診断通知）を決まった順に1回ずつ実行する。

## 境界

最終構成（固定参照による候補検証、検出episodeは無効）。完了済みの5つの部品を呼び出してつなぐ。それらの中の処理（区間の準備、吸収、再利用評価、候補検証の開始、監視の再開、保留位置の消費、記録の変換、保持の規則、診断証拠の再始動）は変更しない。

警報の検出、推定変化点と推定区間長の算出、保留標本の組立、検出位置の記録、保留中の学習更新の消化、予測側の警報hook、検出episodeの制御、候補検証の進行と確定（および確定に伴う診断通知）、警報のない標本での帰属確定と学習、標本1件の処理全体、設定登録、新client・全体runは除外する。並行更新は保証しない。上流の部品が更新を始めた後の失敗の巻き戻しは、上流の既存契約のとおり行わない。

## 1. 接続

- 1.1 When 警報1回ぶんの処理を求められたとき, the Alarm Occurrence Handling shall 警報応答、完了処理、警報応答の適応記録、session保持への反映、学習帰属変更の診断通知を、この順に1回ずつ実行する。
- 1.2 The Alarm Occurrence Handling shall 警報応答へ、保持中の候補検証session（なければなし）を進行中のsessionとして渡し、警報位置を候補の提案位置として渡す。
- 1.3 The Alarm Occurrence Handling shall 完了処理と保持への反映へ、直前の警報応答の結果そのものを渡し、適応記録へ完了処理の結果そのものを渡し、診断通知へ警報応答が行った学習帰属の変更（なければなし）を渡す。
- 1.4 The Alarm Occurrence Handling shall 完了した応答の情報と、追加した適応記録を返す。
- 1.5 The Alarm Occurrence Handling shall 検出episodeの判断を行わず、受け取ったepisode ID（なければなし）を警報応答・完了処理へそのまま渡す。5つの部品を通す以外の状態更新を行わない。

## 2. 検査

- 2.1 If 保持・適応記録・診断証拠・損失監視・保留位置のownerの型が不正であるとき, the Alarm Occurrence Handling shall 警報応答を呼ぶ前（どの状態も更新する前）に拒否する。
- 2.2 If 警報位置・検出器名・推定変化点・episode IDが適応記録の規則に合わない、または警報位置が保留位置の最終観測位置と一致しないとき, the Alarm Occurrence Handling shall 警報応答を呼ぶ前に拒否する。
- 2.3 2.1・2.2の範囲は、警報応答より後の部品だけが検査するownerと値、および本処理が自分で読む保留位置のownerとする。警報応答が自分の更新より前に検査する引数（現在の学習帰属、損失統計ほか）は、警報応答の既存の検査に任せる。
- 2.4 If いずれかの部品が失敗したとき, the Alarm Occurrence Handling shall それより後の部品を実行しない。

## 3. 対照

- 3.1 When 同じ正常入力・固定環境で実行したとき, the Alarm Occurrence Handling shall 警報応答5種類について、実旧clientの警報解決の後の状態（適応イベント、切替位置、再利用件数、保留、検出器、学習状態、乱数、候補検証sessionの有無）と、実旧の帰属変更hookによる診断用AdaHedgeの再始動の後の状態に一致させる。
- 3.2 The change shall 固定旧実装とgoldenを変更せず、既存の全回帰を維持する。
