# 実装タスク

既存Python/torch/NumPy/pytest・固定条件型を使用する。環境追加なし。実行単位は以下3つ、順次TDD→Lunaレビュー→主担当再検証→commitで進める。

- [x] 1. 利用可能な既存モデルの将来損失適合性を分離する
  - 明示loss・履歴・現存ID・現行ID・許容値を検証し、入力順の平均と現行優先/代替同率の選択を実装する。
  - 不正入力を理由付きで拒否し、入力不変を確認する。
  - 現行優先・代替適合・欠落/消えた参照・負ID・同率・閾値等号が旧pure関数と完全一致する対象検証が通る。
  - _Boundary: 損失入力による既存参照適合選択_
  - _Requirements: 1.2, 1.3, 2.1, 2.2, 2.3, 4.2, 5.1_

- [x] 2. 完了済み将来損失で候補の二分区間採否を確定する
  - 既存採否条件と明示改善量を受け、全参照sumによる初期比較と適合参照の優先置換を統合する。
  - 前半/後半の採否とmargin理由を旧演算順で独立計算し、immutable診断結果を返す。
  - 奇数/偶数、適合優先、消えた初期参照、同率順、両方向の丸め不一致、全診断値が旧finalize decision captureと完全一致し、不正入力不変を確認する。
  - _Boundary: 候補採否とimmutable損失診断_
  - _Depends: 1_
  - _Requirements: 1.1, 1.2, 1.3, 3.1, 3.2, 3.3, 3.4, 4.1, 4.2, 5.1_

- [ ] 3. public観測後損失へ接続し依存境界と全回帰を検証する
  - モデル出力からpublic有界損失を取得し観測順の列として評価へ渡す。モデル呼出や収集sessionは実装に持ち込まない。
  - 入力/共有乱数/defaultdtype/device不変、反復評価独立、frozen結果とkeyword契約を検証する。
  - exact評価moduleにtorchと同機能設定だけを許可し、全src ASTと上位/隣接/旧/別module注入拒否を確認する。
  - 全refactoringとschema・旧11/最終3goldenを含む全tests、旧importなし独立smoke、旧production/golden差分なし、全15条件・設計・blockedなしの統合証拠が揃う。
  - _Boundary: public損失接続・候補評価・依存検査の統合_
  - _Depends: 1, 2_
  - _Requirements: 1.1, 1.2, 1.3, 2.1, 2.2, 2.3, 3.1, 3.2, 3.3, 3.4, 4.1, 4.2, 5.1, 5.2, 5.3_
