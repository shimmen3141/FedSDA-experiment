# Requirements Document

## Project Description (Input)
FedHASPの論文の表2を作る研究者が、学習の割り当てと予測を2×2で比べるため、空いている「柔らかい学習＋現在のモデルだけで予測」の構成を追加する。構成名の案は`fedsda-soft-training-single-model-prediction`。学習は`fedsda-soft-training`、実際の予測は`fedsda-single-model-prediction`、その他の方式は`fedsda`を引き継ぐ。

本書群は2026-11-07の下書きを、同日の独立レビュー（GPT-6 Luna、FAIL）に従って修正したもの。実装・実験・再レビュー・承認はこの修正依頼では行わない。既存soft specの判断・承認記録は変更しない。

## Boundary Context
- 対象: 構成1つ、学習責任度のための重み管理と単体予測の接続、設定の宣言・検査、既存記録の利用、回帰検証、200 runの実験・対の集計の計画。
- 対象外: 既存構成の変更、旧実装への追加、反復EM、一様責任度への変更、真の概念を学習へ使うこと、既存結果の上書き、新しいgoldenによる既存値の置換。
- 隣接する期待: 柔らかい学習は予測重みを責任度の事前重みに使う。単体予測はその重みを更新しないため、単純な設定合成では成立しない。D1・D2は主担当の判断（2026-11-07）として案Aを採り、2026-11-07にユーザーが確定した。要求・設計・task・命名は案Aに揃える。仕様レビューの承認までは実装しない。

## Requirements

### Requirement 1: 2×2の新構成
**Objective:** 研究者として、学習方式と予測方式を明示した比較をしたい。
#### Acceptance Criteria
1. The system shall 新構成を明示的に選択でき、既存の全構成の名前・相対順序・保存設定・runの識別子・goldenを変えず、一覧の末尾に新構成だけを追加する。
2. When 新構成で標本を予測する, the system shall その時点の現在のモデルの局所パラメータだけで予測し、`fedsda-single-model-prediction`と同じ実際の予測と記録の意味を持つ。現在のモデルを責任度の最大値で選び直さない。
3. When 保留標本を学習ストアへ放す, the system shall `fedsda-soft-training`と同じ式・時点・局所パラメータで責任度を求めて固定し、同じ参加条件・復元抽出・共同更新・柔らかい件数による集約・ID対応を使う。
4. The system shall 警報、FIFO、MDLによる選択、候補作成と候補学習、統合の判断と処理順を`fedsda`から引き継ぐ。学習によるモデルの変化後に、各構成の選択やイベントの実現値が一致することまでは要求しない。

### Requirement 2: 学習用重みと予測の分離（案A、2026-11-07にユーザーが確定）
**Objective:** 研究者として、単体予測に替えても柔らかい学習の定義を保ちたい。
#### Acceptance Criteria
1. While 新構成を使う, the system shall 学習用のFixed-Share重みを実際の予測と分離して保持し、既存の柔らかい学習と同じモデル損失の定義・観測順・モデル集合変更の規則で更新する。実際の予測のone-hot重みを責任度へ渡さない。
2. When 集約・統合・配布を反映する, the system shall 学習用重みを既存の柔らかい学習と同じ保留標本と局所モデルで再較正し、実際の単体予測には重みの再較正を適用しない。固定済みの責任度は再計算しない。
3. If 学習用重みの方針と学習・予測の組が契約外である, the system shall 設定時に拒否する。既存構成の設定の受理・拒否を変えず、新しい組だけを明示的に受理する。
4. The system shall 学習用の追加順伝播・同期モデル保持・再較正に必要な計算と経過時間を計測へ含め、単体予測の計算削減だけを新構成の総費用として扱わない。

### Requirement 3: 記録と検証
**Objective:** 研究者として、予測の意味と柔らかい学習の動作を別々に確認したい。
#### Acceptance Criteria
1. The system shall 新構成で責任度の実効モデル数、更新の参加モデル数、batchの重複割合、コンセプト別の学習量を既存の柔らかい学習と同じ形式で保存し、単体予測の実効モデル数1と混同しない。
2. The validation shall 固定状態での単体予測、学習用重みの逐次更新と再較正、責任度・集約の数値、現在モデルの変更とID対応を、既存の実行関数を対照として確かめる。
3. The validation shall 小さい全体runで複数モデルの柔らかい更新と単体予測が両方働くこと、未来のラベルを使わないこと、学習用の計測が実際の予測・監視の記録を置換しないことを確認する。
4. The validation shall 既存全構成の設定・順序・識別子の固定照合、基準版1〜16のgolden、旧回帰2本、依存境界、全pytestと品質検査を通し、未検証は未検証として記録する。

### Requirement 4: 既存結果を再利用する200 runの比較
**Objective:** 研究者として、既存3構成を再実験せず、同じ条件で4マスを対にして集計したい。
#### Acceptance Criteria
1. The experiment shall 新構成のみ10データ×集約間隔50・500×seed 0〜9、10 client×5000標本/clientの200 runを計画し、既存3構成を比較対象として再利用する。
2. Before 対の集計を始める, the analysis shall データ・間隔・seed・client数・標本数の全200キー、保存設定の許された差、環境、コードと基準版の来歴、成功・重複・欠損を検査し、不整合を黙って除外しない。
3. The analysis shall 4構成の精度、対の差と95%信頼区間、上下通信量、計算量とMAC、経過時間、保有モデル数、利用可能な期間別・概念別指標と柔らかい学習の診断を、同じ単位と平均方法で示し、未保存の値を0として補わない。
4. The documentation shall 新構成の意味、学習用重みの補助費用、設定参照の再生成、再利用先と照合結果を記載する。実験開始時の台帳と結果README、結論時の分析への参照を残す。

## 受け入れ条件の具体化（レビュー反映）

以下は上記条件の検査範囲を定める。検査の対照・固定入力・合格条件はdesign.mdの「照合と費用の検査契約」とtasks.mdに対応する。

- 1.4・3.2: 4構成の監視損失は、当該標本のラベル開示後・解放と学習前に計算する現在モデルの局所有界損失とする。予測の混合確率・同期写し・補助損失列を検出器へ渡さない。同一状態で監視損失列を照合する。学習軌跡が異なった後の数値一致は要求しない。
- 2.1: 予測をラベル利用前に確定し、ラベル開示後、観測時点の保有集合と同期写し（未収録IDは既存の選択規則）からモデル別損失を得て学習用重みを更新する。解放時は、その時点の局所確率と更新済みの重みから責任度を固定する。観測時の確率の再利用はしない。
- 1.3・2.2・3.2: 既存softの実経路を対照に、同期損失列と解放時の局所確率を別に照合する。重み・q・参加ID・抽出確率・重複を含むbatch・集約入力と結果・再較正前後の重みと固定済みqを検査し、集合変更・登録・統合のID対応を含める。
- 2.4・3.3: 追加評価は共有部・概念固有部の推論件数と推論MAC、局所処理・同期処理の内訳、run総計と経過時間へ含める。同期写しの保持をMACと混同せず、メモリの未測定はN/Aとする。追加通信は行わず、固定した送受信イベントで上下byteを既存経路と比較する。
- 3.3・4.2: run所有のPython Random・NumPy RandomState・torch CPUと呼出元global Python・NumPyの初期状態と所有者を固定する。補助評価前後の全状態、初期化数・生成順、client別の特徴・ラベル・概念・標本順を照合する。学習による正当なPython乱数消費の違いと、入力生成の変化を分ける。
- 1.1・3.4: 実装前HEADの全構成の順・保存設定・識別子を固定fixtureにし、新構成のみ末尾追加を照合する。goldenは`tests/refactoring/behavior_regression_goldens/v1/`〜`v16/`の環境別保存値と関連乱数fixtureを更新せず比較する。実行検査名・件数・skip・未実施理由を記録する。
- 4.2: 保存入力系列の照合と生成経路の不変testを集計前の証拠とする。画像digest等が未保存なら直接照合未実施と明記する。
