# 要求 revision1

## 1. 警報応答の記録

1.1 When 警報応答の完了情報を記録するとき、システムは警報位置・検出器名・結果種別・変更前後の学習帰属ID・推定変化点・episode IDを持つ不変な適応記録を一件追加する。
1.2 When 記録対象が候補検証中・変化区間不足・保有モデル再利用・現行モデル維持・候補検証開始のいずれかであるとき、システムは対応する結果を区別して保存し、入力順に履歴を返す。
1.3 When 保有モデル再利用を記録するとき、システムは警報位置を切替位置へ追加し、他モデル再利用件数を一つ増やす。When 現行モデル維持を記録するとき、現行モデル適合件数だけを一つ増やす。他の結果では両件数と切替位置を変えない。

## 2. 検査と所有

2.1 If 入力の型・位置・検出器名・結果種別・結果と帰属IDの対応が不正であるとき、システムは履歴・切替位置・計数を一切更新せずに拒否する。
2.2 When snapshotを取得するとき、システムは履歴・切替位置・両件数を不変の値として返し、後続の記録で取得済みsnapshotを変えない。
2.3 When 完了情報を記録するとき、システムは監視・FIFO・学習帰属・標本・モデル・torch/Python/NumPy乱数・候補検証sessionを変更しない。

## 3. 固定旧との対応

3.1 When 固定旧と同じ正常な警報応答を記録するとき、システムは旧イベントの全field・切替位置・再利用計数と対応する値を生成する。旧actionの別名を新APIへ追加しない。
3.2 When 本部品を検証するとき、システムは既存の旧11・最終3goldenを変更せずに成功させる。新全体run・候補検証の到達時/終端記録・sessionの保持/解除・episode操作・予測への通知は本specの完了に含めない。
