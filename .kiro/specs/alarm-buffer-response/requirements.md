# 警報時の保留標本への応答 — 要求 revision1

研究者が旧の警報処理を追えるよう、候補検証の有無と変化区間の件数から保留標本への応答を選び、完成した結果と後始末に必要な情報を受け取る。

## 境界

CPU float32の既存分類器、最終の固定参照による候補検証構成。警報自体は呼出側で検出済み。位置付き保留標本、現在の学習帰属、任意の進行中候補検証、推定変化区間件数・最小件数、区間解決に必要な設定を受ける。

実際のFIFO消費、検出器reset、イベント/通知・切替位置/再利用計数の台帳、sessionの保持/解除、警報許可episode制御、設定登録、計算量診断、新client/全体runは除外。並行更新、非公開状態改変、OOMや委譲先の処理途中失敗の全体rollbackは保証しない。前区間処理後に区間解決が失敗した場合、完了した前区間の更新は残る。全設定・payloadの全体事前検査を新たに約束しない。

## 1. 応答経路

- 1.1 While 候補検証が進行中のとき, when 警報への応答を求められたとき, the Alarm Buffer Response shall 保留全件を保留順で現行モデルへ吸収し、同じ候補検証を引き続き返す。区間分割、評価保存、再利用評価、新候補の開始は行わない。
- 1.2 When 候補検証がなく警報への応答を求められたとき, the Alarm Buffer Response shall 既存の区間準備に従い前区間の評価保存と吸収を終えてから、変化区間の件数を最小件数と比較する。
- 1.3 When 変化区間が最小件数未満のとき, the Alarm Buffer Response shall 不足の結果を返し、変化区間の評価・吸収・候補開始を行わない。空保留も不足とする。
- 1.4 When 変化区間が最小件数以上のとき, the Alarm Buffer Response shall 準備済み変化区間だけを既存の区間解決へ渡し、再利用・現行維持・新候補検証開始の結果を返す。解決には前区間吸収後の統計を使用する。

## 2. 結果と保持状態

- 2.1 When 応答を完了したとき, the Alarm Buffer Response shall 進行中検証への吸収・不足・再利用・現行維持・候補開始を区別できる不変結果を返し、準備と区間解決の結果を該当経路で保持する。
- 2.2 When 応答を完了したとき, the Alarm Buffer Response shall 保留位置と最終観測位置を変更せず、呼出側が後でFIFOを消費すべきかを結果から判別可能にする。不足時だけ保持を指示し、その他は消費を指示する。
- 2.3 While 候補検証が進行中のとき, the Alarm Buffer Response shall その候補・参照・検証履歴・保留検証標本を変更せず、現行帰属と評価標本を維持する。空FIFOの吸収も検証を置換しない。

## 3. 拒否・対照

- 3.1 If 進行中検証の型、保留位置列と供給標本の対応、または本応答で使用する件数の型/値が不正であるとき, the Alarm Buffer Response shall 状態と乱数の更新前に例外で拒否する。候補検証中は区間件数と最小件数を使用せず検査しない。
- 3.2 When 同じ正常入力・固定環境・初期乱数で実行したとき, the Alarm Buffer Response shall 実旧警報処理の標本・統計・帰属・候補検証・評価標本・乱数の最終状態と一致させる。FIFO後始末と記録/resetは比較時に境界を明示する。

各標本の意味上の位置対応は供給側が保証する。候補検証中の吸収に必要なowner/payloadは既存公開吸収契約、不在時の準備と区間解決の入力はそれぞれの既存公開契約で検査する。未使用の候補学習設定を進行中検証の経路で読み取らない。
