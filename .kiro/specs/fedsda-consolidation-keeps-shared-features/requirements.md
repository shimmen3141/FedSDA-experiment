# Requirements Document

## Project Description (Input)
- 誰が困っているか: FedSDAの通信量を、FedDrift・FedAvgと比べている研究者（ユーザー）。
- 今の状況: 基準版8（クロス評価で配布するモデルを使う扱い）の本規模の再測定（2026-10-20、uranium、480 run）で、精度は版7と同じだったが、SEA2・SEA4の下りの通信が最大で約19%増えた。手元の診断で、原因は、統合（同じクラスタのモデルを1つへまとめる処理）が共有部も件数で加重平均するため、もともとビット単位で同じ共有部の値が、浮動小数点の誤差（約1e-7）だけ変わり、版8の数え方では、共有部を全clientへ送り直したことになるためと分かった（SEAでは、統合1回の送り直しの約67%）。
- 何を変えるか: 統合で、メンバーの共有部がビット単位で同じなら、平均せずに代表の値をそのまま使う扱いを足し、既定にする。数学的には同じ値で、浮動小数点の誤差だけを無くす（ほぼ不具合の修正）。基準版9を足す。

## Introduction
集約（`aggregate_client_models_into_global_models`）は、全グローバルモデルに同じ集約後の共有部を入れる。統合は、そのラウンドに集約したモデルだけを対象にするので、統合の前のメンバーの共有部は、ビット単位で同じ。同じ値を件数で重み付けて足して割ると、数学的には同じ値だが、浮動小数点では変わりうる。2026-10-20の会話で、ユーザーはこの修正を進めると決めた。

## Boundary Context
- 対象: 統合の加重平均の共有部の扱い、それを選ぶ設定（新しい項目）、最終構成の既定、旧と比べる設定の入口、基準版のgolden（版1〜8の明示と、版9の追加）、既定に依るtest、文書。
- 対象外: 概念固有部の加重平均、損失統計の加重平均、クラスタリングの判定、集約、通信量の数え方（版8のまま）、FedDrift・FedAvg、固定旧と旧golden、研究室サーバ用のgolden。

## Requirements
### Requirement 1: 統合で、同じ共有部を平均せずに保つ扱いを選べる
**Objective:** As a 研究者, I want 統合が共有部の値を浮動小数点の誤差で変えない扱い, so that 統合のたびに共有部を送り直さずに済む。
#### Acceptance Criteria
1. The FedSDA system shall FedSDAの参加者の設定に、統合での共有部の扱いを選ぶ項目を持つ（値は「概念固有部と一緒に平均する」——今の扱い——と「同じなら平均せずに保つ」の2つ）。
2. When 「同じなら平均せずに保つ」が選ばれていて、加重平均に参加する（正の件数を持つ）メンバー全員の共有部が、代表（クラスタの最小のID）の共有部とビット単位で同じ, the FedSDA system shall 代表の共有部を、平均せずにそのまま使う（概念固有部は、今と同じ加重平均）。代表の件数が0でも、この条件を満たせば同じ。共有部を持たない構造では、共有部が空どうしで同じとみなす（平均するものが無いので、結果は今と同じ）。
3. When 「同じなら平均せずに保つ」が選ばれていて、上の条件を満たさない（代表が、件数が0で、ほかのメンバーと違う共有部を持つ場合を含む）, the FedSDA system shall 今と同じく、共有部も加重平均する。件数がすべて0のクラスタは、今と同じく代表のパラメータを使う。
4. When 「概念固有部と一緒に平均する」が選ばれている, the FedSDA system shall 今と同じ値・同じ計算回数で統合する。

### Requirement 2: 既定を「同じなら平均せずに保つ」にする
#### Acceptance Criteria
1. The FedSDA system shall 最終構成の既定の、統合での共有部の扱いを「同じなら平均せずに保つ」にし、FedSDAの全部の構成が引き継ぐ。全部の構成の組立てが例外を出さず、実験のコマンドの引数を変えない。

### Requirement 3: これまでの基準と照合を保つ
#### Acceptance Criteria
1. The validation shall 実旧との照合test（部品・全体run・構成）を、変わらず成功させる。旧と比べる設定の入口と、実旧との照合に使う設定の組は、「概念固有部と一緒に平均する」に明示する。
2. The validation shall 基準版1〜8のgoldenを、「概念固有部と一緒に平均する」で、値を変えずに照合し続ける。

### Requirement 4: 新しい既定を基準版9として足す
#### Acceptance Criteria
1. The validation shall 新しい既定での値を、基準版9のgoldenとして、Windowsの基準環境とWSLの両方で足す（ケースは版8と同じ）。
2. The validation shall 版8と9の差を、全ケースで確かめる: FedDrift・FedAvgのケースと、統合が起きないFedSDAのケースは、指標・記録の表・最終のパラメータ・経路の記録が版8と同じ（設定は、新しい項目を除いて同じ）。統合が起きたFedSDAのケースは、差があってよい（共有部の約1e-7の差が、後の学習へ伝わるため）。統合が起きたFedSDAのケースが少なくとも1つある。
3. The validation shall 統合が起きることを新旧の両方の実行で確かめた全体runで、新しい既定では統合の後の共有部の送り直しが1回も数えられず、旧の扱いでは少なくとも1回数えられることを確かめる。

### Requirement 5: 文書を合わせる
#### Acceptance Criteria
1. The documentation shall 基準の文書（版9）、指標の文書（通信量の注記）、実験の入口、研究記録、再開案内で、新しい扱いと、版8の本規模の結果のSEAの通信量が、この誤差の分だけ多く数えられていたことを書く。
