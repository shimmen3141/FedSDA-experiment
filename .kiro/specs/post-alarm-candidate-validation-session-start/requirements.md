# 警報後の候補検証session開始 — 要求 revision2

切り出し済み学習区間・選択済み初期値・保有モデルと履歴を与えて、未確定候補の警報後検証を開始する。最終提案構成の固定参照方式を対象にする。

区間と保留標本は借用し、呼出し側が寿命と非並行更新を管理する。保持するbindingは固定するが、候補の学習状態と損失収集は後続で更新できる。途中の内部故障・数値overflow・OOM・非公開状態改変・並行更新の原子性は対象外。

## 1. 検証開始

- 1.1 When 正常な開始入力を受けたとき、the Session Start shall 独立候補の生成、指定方式での候補学習、警報時点の保有参照の固定、空の将来損失収集の開始を順に実行し、新しいsessionを返す。
- 1.2 When sessionを返すとき、the Session Start shall 提案標本位置、推定変化点位置（未推定を含む）、検出episode（未採番を含む）、検出器名、開始時の学習帰属ID、学習区間、保留標本の順序、候補の学習量、固定参照と履歴平均を保持する。
- 1.3 While 候補検証を開始するとき、the Session Start shall 保有モデル・optimizer・学習帰属・統計・借用区間・保留標本を変更せず、候補と参照を保有モデルから独立させる。

## 2. 旧挙動と後続接続

- 2.1 When 正常入力で開始したとき、the Session Start shall 旧固定参照方式と同じ候補parameter・grad・optimizer・参照値/順序・履歴平均・学習量・終了時乱数状態を得る。
- 2.2 When 後続の検証観測にsessionの候補・参照・損失収集を渡したとき、the Session Start shall 提案の次の標本から既存の規定件数判定へ接続でき、候補の継続学習中も固定参照は変わらない状態を提供する。

## 3. 契約と範囲

- 3.1 If 開始入力の事前検査で契約違反を検出したとき、the Session Start shall 候補生成・候補学習・参照生成による乱数消費と外部状態変更の前に拒否する。位置は0始まりの非負整数、推定変化点は提案位置以下、episodeは非負整数または未採番、検出器名は空白だけでない文字列を受理する。設定・初期値・区間は既存の生成/学習契約に適合し、保留標本は同じ入力幅/クラス範囲の1標本、保有モデルは非空で現在の帰属IDを含み、同じ入力幅/クラス数の有限値の分類器であることを前提にする。具体的な検査項目と拒否時不変の対応を設計に固定する。
- 3.2 While 本機能を実行するとき、the Session Start shall 検出・区間切出し・初期値選択・参照の学習・採否確定・登録/採番・通信・外部診断更新・既存active sessionの置換を行わない。
- 3.3 When 本specを完了とするとき、the Session Start shall 方式/クラス/optimizer別の実旧対照、拒否時不変、検証観測との接続、依存境界、基準環境の全回帰を証拠として残す。新client/全体runの完成は主張しない。
