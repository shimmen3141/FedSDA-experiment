# 要求 revision1
## 1. 診断証拠の保持
1.1 When 診断状態を作るとき、システムは空のglobal証拠一つを作り、他の保持集合から独立させる。
1.2 When 真の概念IDの証拠を要求するとき、システムは初回だけ空の証拠を作り、同じIDへ同じ状態を返す。異なるID/globalとは共有しない。
1.3 When 作成済み概念IDを読むとき、システムは作成順の不変な値を返し、未作成IDの状態を作らない。
## 2. 帰属変更通知
2.1 When 変更前後の学習モデルIDが異なる通知を受けるとき、システムはglobalの累積損失とgapを消去し、概念再始動件数を一つ増やす。globalの集合変更件数と全oracle証拠・作成済みIDは保持する。
2.2 When 変更情報がないか、変更前後のIDが等しいとき、システムは診断状態を変更しない。
2.3 If 保持集合/変更情報の型、変更前後のモデルID、真の概念IDが不正であるとき、システムは状態を更新せず拒否する。IDは負値を含むbuiltin int、boolを受理しない。
## 3. 対応と境界
3.1 When 保持と通知を行うとき、システムは予測・学習・候補session・FIFO・Python/NumPy/torch乱数を変更しない。
3.2 When 固定旧と同じ取得・損失更新・帰属変更列を与えるとき、システムはglobalと概念別の全証拠・計数・重みを一致させる。旧11/最終3goldenは変更しない。本specの完了は新全体runや保存診断全体の一致を含まない。
