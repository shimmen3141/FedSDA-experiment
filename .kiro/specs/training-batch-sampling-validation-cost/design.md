# Design Document: training-batch-sampling-validation-cost

## Overview

**Purpose**: 学習標本の抽出の、1回あたりの費用を、保持する標本の数に依らないようにして、本番の規模の実験を、実用の時間で実行できるようにする。

**Impact**: `learning/training/held_model_training_batch_sampling.py`の、標本の中身の検査を、抽出の後の、抽出した標本だけにする。完了済みのspec（held-model-training-batch-sampling）の契約「抽出に入らない標本も、乱数を進める前に検査する」を、変える。

## 変更の前後

| | 変更の前 | 変更の後 |
|---|---|---|
| 入れ物の検査（ID、列の型、重複、件数、生成器） | 乱数を進める前 | 同じ |
| 標本の中身の検査（型、tensor、形、有限性、特徴数の一致） | 乱数を進める前に、保有モデルの、件数の足りる列の、全部の標本 | 抽出の後に、抽出した標本だけ |
| 不正のとき | 乱数を進めずに、拒否 | 乱数の状態を、呼出しの前へ戻して、拒否（例外の種類に依らず、戻す） |
| 抽出に入らなかった、不正な標本 | 拒否 | 気づかない（その標本は、その回の学習に使われない。後で抽出されたときに、拒否する） |
| 1回の費用 | 保持する標本の数に比例 | 抽出する件数に比例 |

- 乱数の呼出し（`python_random_generator.sample(標本の列, 件数)`を、参加順に1回ずつ）は、変えない。正しい入力では、結果と、乱数の進み方が、同じ。
- 乱数の状態の保存（`getstate`）と復元（`setstate`）は、呼出しごとに1回（費用は、保持する標本の数に依らない）。
- 特徴数の一致は、同じモデルの、抽出した標本の間で確かめる（変更の前は、列の全部の標本の間）。
- 標本を入れる側（`ModelTrainingSampleStore`）は、変えない。

## 保持へ入る標本は、入口で検査されている

保持（`ModelTrainingSampleStore`）へ入る標本は、どれも、観測標本の処理を通ったもので、その入口で、状態を変える前に、検査されている:

- 型と、1標本の形: `runtime/observed_sample_processing.py`の`_validate_observed_sample_processing_inputs`。
- 特徴の有限性、ラベルのdevice・dtype: 処理の最初に行う予測（`runtime/observed_sample_prediction.py`の入口の検査）。
- 特徴の数とdtype（共有特徴抽出部）、ラベルの有限性・範囲・整数値（`learning/prediction/classifier_bounded_loss_evaluation.py`）: 同じく、予測と損失の評価の中。
- 拒否のtest: `tests/refactoring/test_observed_sample_prediction.py`（NaN・無限大・dtypeほか。状態を変える前に拒否する）。

したがって、変更の前の、抽出のたびの全数の検査は、入口の検査と重複していた。抽出の中の検査が意味を持つのは、入口の後で、標本が書き換えられた場合だけである。

## 残る制約（独立レビューの指摘）

- 1回の学習の要求は、共同更新を、複数回、繰り返すことがある（`runtime/held_model_training_request_handling.py`）。入口の後で書き換えられた標本が、何回目かの繰り返しで、初めて抽出に入ると、それまでの繰り返しの更新と計数は済んだまま、例外で止まる（変更の前は、最初の繰り返しの前に、全数の検査で拒否していた）。本番の流れでは、標本を書き換える処理はないので、起きない。起きた場合も、不正な値は、学習へ入らない（その回の抽出で拒否する）。
- クロス評価（`runtime/client_model_cross_evaluation.py`）は、同じ保持の標本を、検査せずに読む（変更の前から）。変更の前は、書き換えられた標本があれば、次の学習の呼出しが止まった。変更の後は、その標本が抽出されるまで、止まらない。これも、入口の後の書き換えがある場合だけ。

## 検証の方針

- 既存のtest（`tests/refactoring/test_held_model_training_batch_sampling.py`）を、新しい契約へ直す: 入れ物の不正は、乱数を進める前に拒否。標本の中身の不正は、抽出に入る位置へ置いて、拒否と、乱数の状態の復元を確かめる。抽出に入らない位置の不正は、拒否せず、結果が、正しい入力と同じ。検査の回数が、保持する標本の数に依らない。
- 実旧の抽出との照合（参加順、抽出したtensor、終端の乱数の状態）は、そのまま。
- 全体runの照合（goldenの3ケース、小さい条件）と、全pytest。
- 速度: 変更の前後で、同じ条件（client 10・標本500・sine2・集約間隔50）の実行時間と、プロファイル。本番の規模の1 run。
