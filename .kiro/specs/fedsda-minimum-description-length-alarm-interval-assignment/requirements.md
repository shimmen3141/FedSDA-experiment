# Requirements Document

## Project Description (Input)
- 誰が困っているか: FedSDAの手法を設計・評価している研究者（ユーザー）。
- 今の状況: 警報（変化の検出）の後に「保留していた標本のどこからが新しい区間か」と「その区間をどのモデルに帰属させるか（現在のモデルのまま、ほかの保有モデルの再利用、新しいモデル）」を決める処理が、検出器の推定した変化の長さと、固定の閾値（区間の平均損失≦そのモデルの履歴の平均損失＋0.1）で行われている。検出が統計的なのに、その直後の帰属の判定だけが経験的な閾値で、手法の説明と合わない。2026-10-20〜21の研究（[IMPROVE-021](../../../docs/research/improvement-candidates/improve-021-statistical-test-for-held-model-reuse.md)、[帰属を1つの推論にまとめる案](../../../docs/research/fedsda-unified-concept-assignment-inference.md)）で、警報の後の変化点と帰属先を、最小記述長（minimum description length、MDL）の原理で選ぶ形（研究ツールの変種`default-detector-gated-segment-assignment`）が、固定の閾値を使わずに、本規模の10 seedで24条件のうち17で既定と同じか上回り、崩れるrunも無かった。
- 何を変えるか: 警報の後の変化点と帰属先を、最小記述長の原理（各仮説の符号長＝負の対数尤度の和＋切り替わりの符号長、を比べて最短のものを選ぶ）で選ぶ扱いを、製品の経路に正式な部品として足し、既定にする。基準版10を足す。

## Introduction
2026-10-21、ユーザーは、この扱いを既定にすると決めた（「この案は既定にしたいです。spec 作成は進めてください」）。理解しやすい語と、研究分野で一般的な語で命名するよう指示した（会話の中の造語を使わない）。

用語:
- **符号長（description length / code length）**: 標本の列を、ある予測の仕方で符号化したときの長さ。ここでは、各標本の真のクラスに予測が付けた確率の負の対数（対数損失、自然対数で単位はnats）の和。短いほど、その予測の仕方で標本をよく説明できている。
- **最小記述長の原理**: 複数の仮説のうち、符号長（仮説そのものを表す長さを含む）が最も短いものを選ぶ。
- **予測的（prequential）符号長**: 学習しながら予測する方式の符号長。各標本を、それまでの標本だけで学習したモデルで予測してから、その標本で学習する（新しいモデルの側の符号長に使う。学び始めの誤りの分が、新しいモデルを作ることの罰として働く）。
- **切り替わりの符号長**: 仮説の中で、帰属先が1回切り替わることを表す長さ。−ln(切り替わりの確率)＋ln(切り替わり先の数)。切り替わりの確率には、予測の重み（Fixed-Share）の切り替わりの率1/T（既存の値。T＝120標本）を使う。

## Boundary Context
- 対象: 警報の後の変化点と帰属先の選択（新しい部品）、それを選ぶ設定（新しい項目）、clientの標本の処理と警報の処理への受け渡し、最終構成の既定、構成の扱い（候補検証ありの構成は今の扱いのまま）、旧と比べる設定の入口、基準版のgolden（版1〜9の明示と、版10の追加）、既定に依るtest、研究ツールの変種の乱数の扱いの揃え（製品と同じ値になることの確認のため）、文書。
- 対象外: 検出器（e-SR・ClassESR・ADWIN）そのもの、帰属の保留（FIFO）、区間の準備と取込み、候補の学習と採用、登録、クロス評価、サーバのクラスタリングと統合（閾値0.1は残る。[IMPROVE-026](../../../docs/research/improvement-candidates/improve-026-server-clustering-by-description-length.md)）、予測、候補検証の処理、FedDrift・FedAvg、固定旧と旧golden。

## Requirements
### Requirement 1: 警報の後の変化点と帰属先を、最小記述長の原理で選べる
**Objective:** As a 研究者, I want 警報の後の変化点と帰属先を、固定の閾値ではなく、符号長の比較で選ぶ扱い, so that 検出と同じく統計的に説明できる判定にする。
#### Acceptance Criteria
1. The FedSDA system shall clientの設定に、警報の後の変化点と帰属先の選び方を選ぶ項目を持つ（値は「検出器の推定した変化の長さと、履歴の平均損失からの増加の許容量で選ぶ」——今の扱い——と「最小記述長の原理で選ぶ」の2つ）。
2. When 「最小記述長の原理で選ぶ」が選ばれていて、検出器が警報を出した, the FedSDA system shall 帰属の保留にある標本と警報の標本を古い順に並べた列について、次の仮説の符号長を計算し、最短の仮説を選ぶ。
   - 現在のモデルのまま: 列の全部を、現在のモデルの対数損失で符号化する。
   - 位置τで、ほかの保有モデルmへ切り替わる: τより前を現在のモデル、τ以降をmの対数損失で符号化し、切り替わりの符号長を足す。mは、損失の統計を持つ、現在のモデル以外の保有モデル。
   - 位置τで、新しいモデルへ切り替わる: τより前を現在のモデル、τ以降を予測的符号長で符号化し、切り替わりの符号長を足す。予測的符号長の学習者は、現在のモデルの写しの、概念ごとの部分（共有部の上のadapterと出力の層）を初期化し直したもので、共有部は更新せず、候補の学習と同じ損失とoptimizerの設定で、1標本ごとに1回更新する。
   - τの候補は、列の末尾からの長さが、最小の変化区間の件数（既存の値。5）の倍数になる位置。
   - 切り替わり先の数は、ほかの保有モデルの数＋1（新しいモデル）。
   - 同じ長さの仮説は、現在のモデルのまま、短い区間、保有モデル（保有の順）、新しいモデルの順に優先する（研究ツールの変種と同じ順）。
3. When 選んだ仮説が「現在のモデルのまま」, the FedSDA system shall 変化区間の長さを列の長さとし、現在のモデルを再利用する（今の扱いで、現在のモデルが合うと判定されたときと同じ処理）。ただし、現在のモデルが履歴の基準を持たない（今の扱いでも合うと判定できない）ときは、新しいモデルへ切り替わるときと同じく、候補の学習と採用を行う（研究ツールと同じ。設計の「警報の処理への接続」）。
4. When 選んだ仮説が「位置τで切り替わる」, the FedSDA system shall 変化区間の長さを列の末尾からτまでの長さとし（τより前の保留の標本は、今と同じく現在のモデルへ取り込む）、行き先が保有モデルならそのモデルを再利用し、新しいモデルなら、今と同じ候補の学習と採用を行う。
5. When 列の長さが最小の変化区間の件数より短い, the FedSDA system shall τの候補を持たず、変化区間の長さを列の長さとして、今の「短い警報は待つ」扱いに従う（警報としない）。
6. The FedSDA system shall 予測的符号長の学習者の初期化に、runの乱数（torch・Python・NumPy）を消費しない。初期化の乱数は、clientの番号・警報の標本の番号・τから決まるseedで作る（同じ設定なら、同じ値になる）。
7. When 「検出器の推定した変化の長さと、履歴の平均損失からの増加の許容量で選ぶ」が選ばれている, the FedSDA system shall 今と同じ値・同じ乱数の消費・同じ計算回数で処理する（最小記述長の選択の計算を呼ばない）。
8. When 「最小記述長の原理で選ぶ」が選ばれていて、選択を行った, the FedSDA system shall 選択ごとに、警報の標本の番号、選んだ仮説（現在のモデルのまま／保有モデルへ切り替わる／新しいモデルへ切り替わる）、変化区間の長さ、行き先の保有モデルのID、符号長を記録し、runの記録の表に含める（選んだ仮説と、その後に実際に行われた処理——再利用か新しいモデルか——を分けて確かめられるようにする）。

### Requirement 2: 既定を「最小記述長の原理で選ぶ」にする
#### Acceptance Criteria
1. The FedSDA system shall 最終構成の既定の選び方を「最小記述長の原理で選ぶ」にし、候補検証ありの構成（`fedsda-with-candidate-validation`）を除く、FedSDAの全部の構成が引き継ぐ。候補検証ありの構成は、今の扱いを明示する（候補検証との組合せは未検証のため）。全部の構成の組立てが例外を出さず、実験のコマンドの引数を変えない。

### Requirement 3: これまでの基準と照合を保つ
#### Acceptance Criteria
1. The validation shall 実旧との照合test（部品・全体run・構成）を、変わらず成功させる。旧と比べる設定の入口と、実旧との照合に使う設定の組は、今の扱いを明示する。
2. The validation shall 基準版1〜9のgoldenを、今の扱いで、値を変えずに照合し続ける。

### Requirement 4: 新しい既定を基準版10として足す
#### Acceptance Criteria
1. The validation shall 新しい既定での値を、基準版10のgoldenとして、Windowsの基準環境とWSLの両方で足す（ケースは版9と同じ）。
2. The validation shall 版9と10の差を、全ケースで、両方の版を実行した結果を比べて確かめる: FedDrift・FedAvgのケースと、候補検証ありの構成のケースは、指標・最終のパラメータが版9と同じ。記録の表は、版10の結果から選択の記録の表（Requirement 1.8）を取り除いて版9と同じで、取り除いた表は空（候補検証ありの構成のケース。FedDrift・FedAvgのケースは、この表を持たない）。経路の記録は、版10で足す項目（選んだ仮説ごとの回数）を取り除いて版9と同じ。新しい既定を引き継ぐFedSDAのケースは、設定が新しい項目だけ違う。
3. The validation shall 新しい既定を引き継ぐ大きい条件のケース（少なくとも1つ）で、最小記述長の原理の3種類の選択（現在のモデルのまま、保有モデルへ切り替わる、新しいモデルへ切り替わる）が、選択の記録（Requirement 1.8）で、それぞれ1回以上起きることを確かめる（経路の記録）。
4. The validation shall 基準版1〜9の照合（計算回数を含む指標の全部を比べる）と、今の扱いで最小記述長の選択の計算が呼ばれないことのtestで、今の扱いの値と計算回数が変わらないことを確かめる（Requirement 1.7）。

### Requirement 5: 研究で評価した値と同じであることを確かめる
#### Acceptance Criteria
1. The validation shall 研究ツールの変種（`default-detector-gated-segment-assignment`）を、Requirement 1.6と同じ乱数の扱いに揃え、製品の既定の全体runと、同じ条件で、精度・通信量・予測の記録が一致することを、複数のデータセット（MNISTとSINE2・CIRCLE2・SEAのうち少なくとも1つずつ）で確かめる。
2. The validation shall 研究ツールの変種の乱数の扱いを揃えたことで、研究で評価した本規模の結果（uraniumの240 run）と値が完全には一致しなくなることを、記録に書く。

### Requirement 6: 文書を合わせる
#### Acceptance Criteria
1. The documentation shall 手法の説明（最小記述長の原理による、警報の後の変化点と帰属先の選択）、基準の文書（版10）、実験の入口、研究記録、再開案内で、新しい扱いと、サーバのクラスタリングの閾値は残ることを書く。
