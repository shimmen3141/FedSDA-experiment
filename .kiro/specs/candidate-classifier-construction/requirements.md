# 候補分類器と学習状態の生成 — 要求 revision2

## 目的

移植中の候補検証に、選択済みの初期値を持つ独立した候補を供給する。学習方法と生成方法を分離し、旧実装の正常入力における生成順と乱数消費を維持する。

## 1. 独立した候補

- 1.1 When 構造の参照分類器と適合する初期parameterが与えられたとき、生成処理は同じ構造・同じ初期値の独立した候補分類器を返す。
- 1.2 When 候補を生成したとき、候補の全parameterと勾配は参照分類器・初期parameterから独立し、既存分類器・入力parameterの値と勾配を変更しない。
- 1.3 When 正常入力で生成したとき、生成処理は旧候補生成と同じ乱数を消費し、外部の乱数状態を復元・seedしない。

## 2. 候補専用の学習状態

- 2.1 When 候補を返すとき、生成処理は候補自身の共有特徴抽出部と概念固有部に対応する独立したoptimizer管理器を返す。
- 2.2 When 新規optimizerを返すとき、指定のAdam標準/AMSGradまたはSGD条件を反映し、学習履歴を引き継がず、parameter順を旧実装に一致させる。

## 3. 拒否と境界

- 3.1 If 参照分類器・共有部parameterが空の構造・初期parameterのキー/shape/dtype/device/有限性・optimizer設定が契約に違反するとき、生成処理はモデル生成による乱数消費と既存状態の変更より前に拒否する。候補専用の共有optimizerを必要とするため、隠れ層なしの分類器は本生成の受理範囲に含めない。
- 3.2 While この生成処理を実行するとき、処理は学習更新、初期値の選択、保有登録、採番、共有部の外部モデルへの接続、損失統計、参照モデル固定、session開始、通信、診断計数を行わない。
- 3.3 When 本specを完了とするとき、旧正常生成への対照と既存部品への学習接続、依存境界、基準環境の回帰を証拠として残す。新全体runの完成は主張しない。
