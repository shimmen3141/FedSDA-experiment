# FedSDAの新規モデル作成方針

FedSDAでは、ドリフト警報後に既存モデルが距離閾値を満たさなかった場合の処理を
`NEW_MODEL_CREATION_POLICY` で選択する。検出器、Cached/NoCached、初期化方法、
early stoppingとは独立した設定である。

ドリフト検出直後の既存モデル再利用では、適合モデルのうち区間平均損失が最小の
モデルを常に選ぶ。詳細は [model-reuse.md](model-reuse.md) を参照。

## 各方式

| 方針 | 学習データ | 検証データ | 新規作成の条件 | 確定の遅延 |
|---|---|---|---|---|
| `immediate` | 検知区間 | なし | 直ちに作成 | なし |
| `validated` | 検知区間の前半 | 同区間の末尾 | 候補が最良既存モデルより区間全体・直近半分の双方で良い | なし |
| `forward_validated` | 検知区間全体 | 警報後の新着 `N_forward` 件 | 候補が最良既存モデルより全 `N_forward` 件・直近半分の双方で良い | `N_forward` 件 |
| `forward_requalified` | 検知区間全体 | 警報後の新着 `N_forward` 件 | 全既存モデルが再適合に失敗し、かつ候補が相対比較にも勝つ | `N_forward` 件 |
| `forward_requalified_current_first` | 検知区間全体 | 警報後の新着 `N_forward` 件 | 現行モデルを優先して再適合を確認し、全既存モデルが不適合の場合だけ候補を比較 | `N_forward` 件 |
| `forward_persistent` | 検知区間全体 | 警報後の新着 `N_forward` 件 | 現行モデル優先の再適合に全既存モデルが失敗し、かつ候補が重複しない前半・後半の双方で良い | `N_forward` 件 |
| `sequential_tournament` | 検知区間全体 | 警報後の新着系列 | 候補または既存モデルが全対戦相手より良いという逐次e値が誤選択予算を超える | 証拠が十分になるまで |

`N_forward` は `NEW_MODEL_FORWARD_VALIDATION_SAMPLES` で指定する。論文・アルゴリズム記述で
1ラウンドのローカルステップ数を表す `K` とは異なる。
`sequential_tournament`は固定`N_forward`を使わず、`SEQUENTIAL_TOURNAMENT_ALPHA`だけを使う。

## 検知区間とFIFOの関係

検知区間は常に `N_FIFO` 件になるわけではない。検出器が推定した新概念側の長さを
`N_detector` とすると、モデル選択・新規モデル学習へ渡す長さは概念的に次で決まる。

```text
N_detection = min(FIFO内の保留件数, N_detector)
```

実装は新着サンプルをFIFOへ追加して検出した後、平時にだけ上限超過分を確定する。このため、
警報時点のFIFOは最大 `N_FIFO + 1` 件を含み得る。`N_FIFO` は平時に保留する件数であり、
検知区間の固定長ではない。検出器本来の候補開始点と、FIFO上限で打ち切った実際の開始点は
raw結果へ別々に記録する。

`validated` で検知区間が30件、検証割合が0.2の場合は、次のように時系列順で分ける。

```text
過去                                                     現在
|---------------- 学習部分 24件 ----------------|-- 検証部分 6件 --|
                                                   |前半3件|直近3件|
```

仮モデルは学習部分だけで学習し、検証部分全体とその直近半分の双方で同じ最良既存モデルを
上回る場合に採用する。検知区間が短い場合は検証用に最低2件、学習用に最低1件が必要である。
この末尾holdoutは警報以前の短い区間だけを使うため、小標本と推定開始点のずれに弱い。
`forward_*`方式はこの問題に対し、検知区間全体で候補を学習し、警報後の未観測データを
検証へ使う方式である。

## validated

検知区間を時系列順に学習部分と検証部分へ分割する。検証部分を学習へ混ぜないため、
同一区間を用いる `immediate` より過学習を抑えられる。一方、警報以前のデータだけで
採否を決めるため、区間が短い場合や推定変化点がずれた場合の標本不足を受けやすい。

## forward_validated

検知区間全体で仮モデルを学習し、警報時点の全既存モデルを固定して、以後の新着データを
同じ条件で評価する。全区間で最小損失の既存モデルを比較対象とし、仮モデルが全区間と
直近半分の両方で上回る場合だけ新規モデルとして登録する。採否確定まで、検知区間の
データは保留される。

## forward_requalified

`forward_validated` の相対比較だけでは、既存モデルも十分良いのに僅差で勝った仮モデルを
作成し得る。そこで次の順序で判定する。

1. 警報時点の各既存モデルについて、前向き区間の平均損失を計算する。
2. `前向き平均損失 - 履歴平均損失 <= γ` を満たすモデルがあれば、新規作成を棄却する。
3. 適合モデルのうち前向き平均損失が最小のものを維持または再利用する。
4. 全既存モデルが不適合の場合だけ、`forward_validated` と同じ仮モデル比較を行う。

ここで `γ` は既存の `FEDSDA_DISTANCE_THRESHOLD` であり、既存モデルへの適合判定と
意味を揃えている。統計的有意差の閾値ではない。クラスタリングでも同じ設定値を使用する
現行設計は維持される。

## forward_requalified_current_first

`forward_requalified` では、適合する既存モデルが複数あるとき、前向き平均損失が最小の
モデルを選ぶ。このため、現行モデルも十分適合しているにもかかわらず、僅かな損失差で
別モデルへ切り替わる可能性がある。

現行モデル優先版では、次の順序で判定する。

1. 現行モデルが再適合条件を満たす場合は、そのモデルを維持する。
2. 現行モデルが不適合の場合だけ、適合する別モデルのうち前向き平均損失が最小のものを再利用する。
3. すべての既存モデルが不適合の場合だけ、仮モデルの相対比較へ進む。

これはモデル切替にヒステリシスを持たせる処理であり、新しい数値ハイパーパラメータは
追加しない。従来の `forward_requalified` は比較実験の再現性を保つため残している。

## forward_persistent

`forward_requalified_current_first` と同じ順序で既存モデルを再適合させる。全既存モデルが
不適合の場合、警報後の新着 `N_forward` 件を時系列順に重複しない前半・後半へ分ける。
候補モデルが最良参照モデルより両区間で良い場合だけ新規モデルとして採用する。

従来の「全区間と直近半分」は区間が重複するため、後半だけの大きな改善で全区間の平均も
改善し、前半の悪化を隠せる。独立区間による持続性判定は、新しい数値ハイパーパラメータを
増やさず、一時的な損失改善による誤採用を抑えるための方式である。

## sequential_tournament

固定された前向き件数と既存モデル適合閾値γを使わず、警報後のpaired lossを逐次比較する。
警報時には、検知区間で学習した仮新規モデルと、警報時点の全既存モデルのshadowを候補集合とする。
各新着サンプルでは次の順に処理する。

1. 正解を見る前の各shadowで予測し、有界損失を記録する。
2. 全候補を同じサンプルで1回更新する。
3. 各方向付きモデル対について、「候補iがjより良くない」を帰無仮説とするe値を更新する。
4. 一つの候補が全対戦相手に勝った時点で確定する。

候補iとjの時刻tにおけるpaired loss差を

```text
d_t(i, j) = loss_j,t - loss_i,t  ∈ [-1, 1]
```

とし、複数の固定betting fraction λを混合したe-process

```text
E_n(i, j) = mean_λ product_t (1 + λ d_t(i, j))
```

を用いる。候補数をMとすると、方向付き全比較へBonferroni配分し、
`E_n(i, j) >= M(M-1) / α_tournament`を全jについて満たしたiだけを勝者とする。
この判定は監視時点を事前固定しないtime-uniformな方式であり、効果量γを導入しない。

仮新規モデルが勝てば新規IDを登録する。既存モデルshadowが勝てば、その更新済みshadowを既存IDへ
反映して再利用する。未確定中は現行モデルへのhard学習割当と実予測routingを変更しない。
実験終端まで決着しない場合は新規作成を棄却し、`insufficient_sequential_evidence`として記録する。
差が非常に小さい候補間では検証が長期化し得るが、これは任意の固定打切り長を隠れた
`N_forward`として導入しないための設計上のトレードオフである。

## 記録される診断値

Pareto CSVには仮モデルの採否数・損失差に加え、`forward_requalified` が既存モデルを
再適合と判定した件数と、前向き平均損失の履歴平均からの超過量を記録する。raw NPZには
各判定で用いた既存モデルの履歴平均も保存する。現行モデル優先版については、現行モデルを
維持した件数と、現行モデルが不適合で別モデルを再利用した件数も別々に記録する。
逐次トーナメントでは候補勝利数、既存モデル勝利数、終端まで証拠不足だった件数、
確定までの実サンプル数を記録する。
