# FedSDAのモデル統合

FedSDAでは、階層クラスタリングが統合候補を作り、その後の
`clustering_consolidation`がモデルrepositoryへ適用する操作を決める。

## 統合方法

- `merge`: 候補クラスタ内のモデルを加重平均し、代表IDへ統合する。
- `parameter_share`: IDを維持したまま、候補クラスタ内で加重平均パラメータを共有する。
- `noninferiority_merge`: 仮統合モデルを検証し、予測性能を保つ候補だけを代表IDへ統合する。

## 非劣性制約付きマージ

候補クラスタを \(C\)、その加重平均モデルを \(f_C\) とする。各元モデル
\(m\in C\) を保有するクライアント上で、同じ標本に対する損失差

\[
d_i = \ell(f_C(x_i), y_i)-\ell(f_m(x_i), y_i)
\]

を計算する。損失差の平均に対する片側信頼上限を \(U_m\)、許容する
非劣性幅を \(\varepsilon_{merge}\) としたとき、

\[
\max_{m\in C} U_m \leq \varepsilon_{merge}
\]

を満たす場合だけクラスタ全体を統合する。一つでも満たさない元モデルが
あれば、その候補は単独モデルへ戻す。このため、平均的な性能だけでなく、
repository内の各概念モデルに対する非劣性を要求する。

現在の信頼上限は対応あり損失差の標本平均・不偏分散に基づく片側正規近似で、
信頼水準には`FEDSDA_CLUSTERING_CONFIDENCE`、非劣性幅には
`FEDSDA_MERGE_NONINFERIORITY_MARGIN`を用いる。評価標本が不足する候補は
保守的に棄却する。

## 通信と計算

通常のクロス評価直後に検証するため、各元モデルはクライアントに直前に送信された
ものを再利用する。追加通信は仮統合モデルの下り転送、評価依頼、損失差統計の返送で
ある。元モデルと仮統合モデルの両方を同じ標本で評価するため、検証計算量は別途計上する。

主な診断指標は候補数、採択数、棄却数、比較数、評価標本数、採択率である。
raw NPZには各候補の損失差平均・片側上限・採否も保存する。
