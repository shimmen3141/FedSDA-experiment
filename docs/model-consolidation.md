# FedSDAのモデル統合

FedSDAでは、階層クラスタリングが統合候補を作り、その後の
`clustering_consolidation`がモデルrepositoryへ適用する操作を決める。

## 統合方法

- `merge`: 候補クラスタ内のモデルを加重平均し、代表IDへ統合する。
- `parameter_share`: IDを維持したまま、候補クラスタ内で加重平均パラメータを共有する。
- `noninferiority_merge`: 仮統合モデルを検証し、予測性能を保つ候補だけを代表IDへ統合する。

## 非劣性制約付きマージ

候補クラスタを \(C\) とする。ニューラルネットの単純なパラメータ平均は、
機能的に近いモデル間でも予測を壊すことがある。そのため、クロス評価結果から
各元概念に対する最大平均損失増加が最小となる既存モデルを代表候補 \(m^*\) に選ぶ。

\[
m^*=\arg\min_{j\in C}\max_{m\in C}
\left(\bar\ell_{j\rightarrow m}-\bar\ell_{m\rightarrow m}\right)
\]

各元モデル \(m\in C\) を保有するクライアント上で、同じ標本に対する損失差

\[
d_i = \ell(f_{m^*}(x_i), y_i)-\ell(f_m(x_i), y_i)
\]

を計算する。損失差の平均に対する片側信頼上限を \(U_m\)、許容する
非劣性幅を \(\varepsilon_{merge}\) としたとき、

\[
\max_{m\in C} U_m \leq \varepsilon_{merge}
\]

を満たす元モデルの部分集合を、代表候補のパラメータへ統合する。条件を満たさない
モデルは残余集合として再びminimax代表選択と非劣性検証を行う。これを残余が
singletonになるまで繰り返すため、大きなconnected clusterを「全統合」または
「全棄却」の二択にしない。各出力クラスタでは、平均的な性能だけでなく、含まれる
全概念モデルに対する非劣性を要求する。

対応あり損失差の十分統計は、クラスタ候補生成に使うクロス評価と同じ標本上で
同時に収集する。したがって、非劣性検証のために候補モデルをもう一度送受信する
必要はない。対象クライアントで十分統計を収集できなかった場合だけ、個別評価へ
フォールバックする。

共有バックボーン構成では、同じクロス評価内で各対象クライアントへ共有部を1回、
各概念ヘッドを1回だけ送信する。対象モデル対ごとに完全なモデルを再送しないため、
モデル数に対して二次的に増える評価計算と、実際のパラメータ通信量を区別して扱う。

現在の信頼上限は対応あり損失差の標本平均・不偏分散に基づく片側正規近似で、
信頼水準には`FEDSDA_CLUSTERING_CONFIDENCE`、非劣性幅には
`FEDSDA_MERGE_NONINFERIORITY_MARGIN`を用いる。評価標本が不足する候補は
保守的に棄却する。

## 通信と計算

通常のクロス評価直後に検証するため、各元モデルはクライアントに直前に送信された
ものを再利用する。追加通信は仮統合モデルの下り転送、評価依頼、損失差統計の返送で
ある。元モデルと仮統合モデルの両方を同じ標本で評価するため、検証計算量は別途計上する。

主な診断指標は候補数、採択数、棄却数、比較数、評価標本数、採択率である。
raw NPZには各候補の損失差平均・片側上限・採否も保存する。
