# FedSDAのモデルルーティング

## ハードルーティング

既存のFedSDAは、各クライアントが1個の`current_model_id`を選び、そのモデルだけで
予測する。ドリフト検知後は既存モデルの再利用または新規モデル作成によって、このIDを
離散的に切り替える。

## AdaHedgeによるソフトルーティング

`FedSDA_NoCached_ClassESR_SoftRouting`は、保持モデルをオンライン学習の専門家として扱う。
時刻`t`の予測前に、それ以前の累積有界損失からAdaHedgeの重みを計算し、各モデルの
予測確率を重み付き平均する。正解ラベルの観測後に各モデルの損失をルータへ追加するため、
prequential評価の順序は維持される。

AdaHedgeの学習率は累積mixability gapから自動決定される。このモード固有の学習率は
追加しない。サーバ配布・新規モデル作成・マージによって専門家ID集合が変わった場合は、
途中参加モデルに恣意的な累積損失を与えないようルータを一度一様状態へ戻す。

### 概念切替時に再始動する方式

`FedSDA_NoCached_ClassESR_RestartingSoftRouting`は、専門家集合の変更に加え、既存モデルの
再利用または新規モデル作成によるローカルなモデル切替が確定した時にもAdaHedgeを
一様状態へ戻す。通常のSoftRoutingは全期間で最良な固定モデルへのregretを小さくするため、
反復概念下では過去概念で蓄積した損失差によって新しい現行概念への追従が遅れる。
再始動方式は累積期間を推定概念区間に区切り、この履歴固定を緩和する。

単なる警報、現行モデル維持、新規モデル候補の棄却では再始動しない。したがって、
誤警報だけで予測重みを破棄せず、実際のモデル操作と再始動の意味を一致させる。

## 現段階の比較範囲

このモードで変更するのは最終予測だけである。次の処理は
`FedSDA_NoCached_ClassESR`と同一に保つ。

- ClassESRによる検出
- `current_model_id`に基づくデータストアとローカル学習
- 既存モデル再利用、新規モデル生成、forward検証
- サーバ集約、クラスタリング、モデル通信

したがって、通常ClassESRとの差は「誤ったモデルへ完全に切り替えず、複数モデルの予測を
混合する効果」を表す。モデル生成や通信量の削減まで同時に主張する方式ではない。
予測に全保持モデルを使うため、推論サンプル処理数は既存の計算量カウンタへ加算する。

この比較で精度・stable accuracyの改善が複数データで確認できた場合に限り、次段階として
ルータの累積regretを新規モデル生成条件へ利用する。改善しない場合は、検出・通信系へ
影響を広げない。
