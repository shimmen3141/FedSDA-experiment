# FedSDAのモデルルーティング

## ハードルーティング

既存のFedSDAは、各クライアントが1個の`current_model_id`を選び、そのモデルだけで
予測する。ドリフト検知後は既存モデルの再利用または新規モデル作成によって、このIDを
離散的に切り替える。

## 再始動AdaHedgeによるソフトルーティング

`FedSDA_NoCached_ClassESR_RestartingSoftRouting`は、保持モデルをオンライン学習の専門家として扱う。
時刻`t`の予測前に、それ以前の累積有界損失からAdaHedgeの重みを計算し、各モデルの
予測確率を重み付き平均する。正解ラベルの観測後に各モデルの損失をルータへ追加するため、
prequential評価の順序は維持される。

AdaHedgeの学習率は累積mixability gapから自動決定される。このモード固有の学習率は
追加しない。サーバ配布・新規モデル作成・マージによって専門家ID集合が変わった場合は、
途中参加モデルに恣意的な累積損失を与えないようルータを一度一様状態へ戻す。

専門家集合の変更に加え、既存モデルの
再利用または新規モデル作成によるローカルなモデル切替が確定した時にもAdaHedgeを
一様状態へ戻す。再始動しない方式は全期間で最良な固定モデルへのregretを小さくするため、
反復概念下では過去概念で蓄積した損失差によって新しい現行概念への追従が遅れる。
再始動方式は累積期間を推定概念区間に区切り、この履歴固定を緩和する。

単なる警報、現行モデル維持、新規モデル候補の棄却では再始動しない。したがって、
誤警報だけで予測重みを破棄せず、実際のモデル操作と再始動の意味を一致させる。

再始動しない方式は5000ステップ実験で過去概念のモデルへ重みが固定され、通常ClassESRより
一貫して精度が低かったため、公開実験モードから削除した。

## 現行モデル保護付きSoftRouting

`FedSDA_NoCached_ClassESR_ProtectedSoftRouting`は、再始動方式のモデル切替直後に生じる
一様混合の悪化を抑える。各時刻に次の順序で処理する。

1. 直前までの全専門家の累積有界損失からAdaHedgeの提案重みを計算する。
2. 提案重みによる累積損失が現行モデル単体の累積損失を厳密に下回る場合だけ、混合予測を使う。
3. 条件を満たさない場合は現行モデルだけで予測する。
4. 実際に使った予測重みにかかわらず、正解観測後はAdaHedgeの提案重みと全モデルの損失で
   ルータを更新する。

4により、ゲートが閉じている間も代替モデルを反実仮想的に評価できる。固定待機期間や
優位差の閾値は追加せず、累積損失が同値の場合はドリフト処理で選ばれた現行モデルを優先する。
ゲートの開閉はNPZの`history_routing_gate_open`へ保存する。

## 検出器との関係

SoftRoutingが変更するのは正解観測前の予測だけであり、ドリフト検出器、既存モデル再利用、
新規モデル作成、学習用データストア、通信処理は変更しない。この意味でルーティング方式は
ADWIN、e-SR、HDDMなどの検出方式から概念的に独立している。

現行コードでは比較軸を増やしすぎないためClassESRモードだけを公開している。共通の
`FedSDAClient`にあるモデル切替フックを使っているため、ADWIN等へ適用する場合も
ルータ部分を検出器非依存のmixinへ分離して組み合わせられる。ただし、検出器によって
モデル切替頻度と再始動頻度が変わるため、同じ効果が得られるとは限らず個別の実験が必要である。

## 現段階の比較範囲

これらのモードで変更するのは最終予測だけである。次の処理は
`FedSDA_NoCached_ClassESR`と同一に保つ。

- ClassESRによる検出
- `current_model_id`に基づくデータストアとローカル学習
- 既存モデル再利用、新規モデル生成、forward検証
- サーバ集約、クラスタリング、モデル通信

したがって、通常ClassESRとの差は「誤ったモデルへ完全に切り替えず、複数モデルの予測を
混合する効果」を表す。モデル生成や通信量の削減まで同時に主張する方式ではない。
予測に全保持モデルを使うため、推論サンプル処理数は既存の計算量カウンタへ加算する。

この比較で精度・stable accuracyの改善が複数データで確認できた場合に限り、次段階として
ルータの累積regretを新規モデル生成条件へ利用する。改善しない場合は、検出・通信系へ
影響を広げない。
