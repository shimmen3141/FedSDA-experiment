# FedHASPの部品を1クライアントで比べる予備実験（基準版16、計画 2026-11-17）

- 目的: 教授の指摘（「hard assignment と soft prediction が本質なら、連合学習ではなく1クライアントのコンセプトドリフト対応の論文にすべき」）を受け、1クライアントでも、(1) 学習を固い割り当てにする効果、(2) 予測を混ぜる効果が、連合学習の設定（10 client）より大きいか・同じか・小さいかを確かめる。結果で、1クライアント版の論文を主にするか、連合学習版を主にするかを決める材料にする（決めるのはユーザー）。
- 位置づけ: 予備実験。1クライアントの比較手法（ARF、DWM、CPFなど）とは、まだ比べない（段階2。この結果を見てから決める）。
- 背景の数値（連合学習、10 client、10データ×間隔50／500×seed 0〜9）: 学習を固くする効果は、混合の予測で+0.63／+0.30pp、現在のモデルだけの予測で+0.78／+0.80pp。予測を混ぜる効果は、固い学習で+1.97／+1.16pp。純度は固い0.900、柔らかい0.867（`docs/experiments/experiment-log.md`の2026-11-05・11-07の行）。

## 1クライアントでの扱い

- 製品の掃引の入口を`--client-count 1`で動かす。コードは変えない。2026-11-17に手元で、下の構成（`fedsda-local-parameter-prediction`を除く6つ。これは後で同じく確かめた）がSINE2・1000標本・間隔50と1000で動くことを確かめた（失敗0）。
- 1クライアントでは、サーバの集約はそのclientのパラメータをそのまま返すだけになる。残るのは、集約のときのサーバの統合（クラスタリング）と、同期のスナップショットの更新。そこで間隔を2つ置く。
  - 間隔50: 統合とスナップショットの更新を、50標本ごとの保守の手順として残す。
  - 間隔5000（＝ストリームの長さ）: ストリームの途中で集約が一度も起きない。統合が無く、同期のスナップショットは作った時点のまま。
- 柔らかい学習（`fedsda-soft-training`）は、各モデルについて責任度に比例して $B$ 件を抜いた平均の損失で更新するので、1回の更新の大きさは固い学習と同じ（`.kiro/specs/fedsda-soft-training-assignment/requirements.md`の要求1.3）。「柔らかい学習は実質の学習率が小さいだけ」という説明は、この構成には当てはまらない。

## 条件

- 10データ（SINE2、CIRCLE2、SEA2、SEA4、MNIST2、MNIST4、fmnist2、fmnist4、rotmnist2、rotmnist4）×間隔50・5000×seed 0〜29、1 client×5000標本。
- 1クライアントのストリームは5000標本で、コンセプトの変化は平均およそ5回（最小の間隔300、その後は1標本ごとに確率0.0015）。1 runのばらつきが大きいので、seedを連合学習の実験の10から30に増やす。
- 構成（製品の掃引、6構成、3,600 run）:
  - `fedsda-training-mass-diagnostics`: FedHASP（固い学習＋混合の予測）。挙動は`fedsda`と同じで、純度の記録を足したもの。
  - `fedsda-soft-training`: 柔らかい学習＋混合の予測。
  - `fedsda-single-model-prediction`: 固い学習＋現在のモデルだけの予測。
  - `fedsda-soft-training-single-model-prediction`: 柔らかい学習＋現在のモデルだけの予測。
  - `fedsda-local-parameter-prediction`: 固い学習＋混合の予測で、各モデルの予測に局所のパラメータだけを使う（同期の時点と局所の2つの版を混ぜない）。間隔5000では統合も版の混合も無く、純粋な1クライアントの手法に最も近い形になる（2026-11-17ユーザー判断で追加）。柔らかい学習とこの予測の組合せの構成は無い。
  - `fedavg`: 単一のモデル（参考）。
- 研究ツール`tools/research_oracle_concept_assignment`の変種`product-default-oracle-concept-assignment`（600 run）: 警報と帰属先を真のコンセプトに合わせたFedHASP。完全に特化させた場合の目安（精度の上限ではない。`docs/research/fedhasp-oracle-assignment-v16.md`の「論文での説明の限定」）。

## まとめ方（事前に決める）

- データ・間隔・seedで対にする。欠けたら止める。
- 20セル（10データ×2間隔）ごとに、次の差の30 seedの平均・95%信頼区間・seedの勝ち負けを出す。全体は20セルの平均を等しい重みで平均する（間隔ごとにも出す）。
  - 学習を固くする効果: 固い−柔らかい（混合の予測、現在のモデルだけの予測の両方）。
  - 予測を混ぜる効果: 混合−現在のモデルだけ（固い学習、柔らかい学習の両方）。
  - Oracle−FedHASP、FedHASP−単一のモデル。
  - 2つの版を混ぜる効果: FedHASP−`fedsda-local-parameter-prediction`。
- 診断: 純度（固いと柔らかい）、最後のモデルの数、警報と新しいモデルの採用の回数。標準指標として、計算量（MAC）と経過時間も併記する（1クライアントで集約が意味を持たないので、通信量は参考）。
- 判断の材料（判定はユーザー）: 1クライアントでの効果の大きさを、上の連合学習の数値と並べて示す。1クライアント版を主にする条件として話し合った3つ（固いと柔らかいの差がはっきり出る、標準の比較手法を上回る、理論）のうち、この実験が答えるのは1つ目だけ。
