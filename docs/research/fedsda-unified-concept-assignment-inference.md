# 帰属を1つの推論にまとめる案（案1）の設計と試作の計画

2026-10-21。ユーザーの指示（「案1を進めてみたい」）で書いた。**研究の設計で、採用の決定ではない。** 既定・学習コード・goldenは変えない。試作は研究ツール（`tools/research_*`）へ閉じる。

## 1. なぜ枠組みを変えるか

- 2026-10-20〜21の改善（[IMPROVE-021](improvement-candidates/improve-021-statistical-test-for-held-model-reuse.md)、[IMPROVE-024](improvement-candidates/improve-024-withdraw-released-samples-after-estimated-change-point.md)、[IMPROVE-025](improvement-candidates/improve-025-simplify-clustering-decision-to-loss-distance.md)）は、既定の部品を1つずつ替える形で、効果は良くても±0.3pp程度だった。1つの閾値を別の量に替えると、別の場所で偏る（再利用へ偏る、新しいモデルを作りすぎる、混ざりが自分を強める）。
- 今の帰属は、硬い判断の連鎖になっている: 検出（e-SR/ClassESR、α=0.001）→ 帰属の保留（FIFO、容量30。あふれた標本は現在のモデルへ確定）→ 警報の区間の解決（再利用か新規か。区間の平均損失≦履歴の基準＋0.1）→ サーバの統合（判定の値≦0.1）。判断の1つ1つが一度きりで、後の証拠で直せない（混ざりの87%は、FIFOからあふれた標本、[IMPROVE-021の4](improvement-candidates/improve-021-statistical-test-for-held-model-reuse.md)）。
- 一方、ablation（[基準版9](fedsda-component-ablation-v9-20261021.md)）で効いていたのは予測の側（全モデルの重み付け、混合、再較正）で、予測は既に「柔らかい」。帰属の側だけが閾値の連鎖。

## 2. 案1の考え方

概念の列を隠れ状態として、「同じ概念が続く／既存の概念へ切り替わる／新しい概念が生まれる」を1つの確率モデルで表し、**いつ切り替えるか（検出）**と**何へ切り替えるか（再利用か新規か）**を、そのモデルの比較から同時に決める。

- 状態: 保有モデル（それぞれ1つの概念）と、「新しい概念」。
- 各状態の、標本の説明の良さ: 保有モデルmは、そのモデルが真のクラスに付ける確率（対数損失）。新しい概念は、初期化した逐次の学習者の、予測してから学ぶ確率（[IMPROVE-021の8](improvement-candidates/improve-021-statistical-test-for-held-model-reuse.md)と同じ）。
- 切り替わりの事前の率: Fixed-Shareの分け合いの割合1/T（既存の値。T=120）。予測の重み（Fixed-Share）は、このモデルの「切り替わり先が一様」の場合の、予測の側の推論にあたる。
- 判断の遅れ: 帰属の保留の容量L=30（既存の値）。直近L標本の中で、切り替わりがあったかを判断する。

閾値（0.1）と検出の有意水準は、使わない。使う値は、既存の1/T、L、最小の変化区間（5）だけ。

## 3. 試作の判断の規則（窓の中の区分けの比較）

標本tを観測したら、直近L標本の窓W=[t−L+1, t]について、次の仮説の符号長（負の対数尤度。nats）を比べる。

- 続く: 窓の全部を現在のモデルcが説明する。符号長＝Σ_{i∈W} ℓ_c(i)。
- 切り替わる: 窓の中の位置τで、状態s（c以外の保有モデル、または新しい概念）へ切り替わる。符号長＝Σ_{i<τ} ℓ_c(i) ＋ Σ_{i≥τ} ℓ_s(i) ＋ （切り替わりの符号長）−ln(1/T)＋ln(状態の数−1)。新しい概念のℓ_sは、τから始めた逐次の学習者の損失。
- τの候補は、窓の中の、最小の変化区間（5）ごとの位置（新しい概念の学習者は、τの候補ごとに1つ。窓の長さ30なら6つ）。
- 切り替わる仮説のうち最小のものが、続く仮説より短ければ、**警報**とし、そのτを変化点、sを行き先とする。区間の解決は、既存の仕組みで、行き先だけをsに決めて行う（sが保有モデルなら再利用、新しい概念なら候補の学習と採用）。
- 続く仮説の方が短ければ、警報なし（今と同じく、あふれた標本を現在のモデルへ確定する）。

今の仕組みとの対応: 検出器（e-SR）の合図と、再利用の判定（閾値0.1）を、この1つの比較に置き換える。FIFO・区間の準備・候補の学習と採用・登録・統合・予測は、今のまま。

## 4. 研究ツールでの試作の方法（既定の経路は変えない）

- `tools/research_provisional_candidate_expert/run.py`へ、変種として足す（ほかの変種と同じく、実行の間だけ関数を包む）。
  - 損失の監視（`loss_change_monitor.observe_loss_after_label_observation`）を包み、合図（`drift_detected`）と推定の変化の長さ（`estimated_change_span_sample_count`＝t−τ+1）を、3の比較の結果で置き換える。
  - 再利用の評価（`evaluate_held_models_for_alarm_interval_reuse`）を包み、行き先sを返す（IMPROVE-021の案Aの変種と同じ包み方）。
  - 保有モデルごとの直近L標本の対数損失は、比較のために前向きの計算だけで持つ（runの状態は変えない）。新しい概念の学習者は、τの候補ごとに、写しの分類器で持つ（初期化の乱数はrunの乱数と分ける）。
- 確かめること: 精度（データ×間隔ごと）、通信量、最終のモデル数、警報の回数と遅れ（真の変化点からの遅れ。`change_point_estimation_metrics`）、判定の正しさ（IMPROVE-021の6と同じ数え方）、runの終わりの混ざり、所要時間。
- 比べる相手: 既定（`default`）。手元の2500標本・4データ×2間隔×3 seed（これまでの比較と同じ）と、案Aで崩れた本規模のrun（MNIST2・50のseed 8・9）。

## 5. 懸念と、試作で見ること

- **検出の力**: ablationでは、クラス別の監視（ClassESR）を全体の損失に替えると、CIRCLE2・MNISTで0.6〜2.2pp下がった。3の比較は、標本ごとの対数損失の和なので、クラス別の監視ではない。検出が遅れる・見逃す恐れがある。警報の回数と遅れを、既定と比べる。
- **新しい概念の学習者の不利**: 10クラスのMNISTでは、学習者は1標本あたり約ln10≈2.3から始まる。短い窓では、違う概念の保有モデルに負けやすい（IMPROVE-021の14の崩れと同じ形）。3では、窓の中の比較に、保有モデルの過去の水準を入れていない。崩れが出たら、IMPROVE-021の15〜17の知見（過去の水準を入れると作りすぎる）と合わせて考える。
- **計算量**: 標本ごとに、保有モデルの数とτの候補の数（6）の前向きの計算と、学習者の更新が要る。所要時間を測る。
- **固定遅れ平滑化までは行かない**: 3は、窓の中で区分けを比べるだけで、警報の後に、窓より前の帰属を直すことはしない（FIFOからあふれた標本を直すのは、IMPROVE-024で効かなかった）。窓の長さLの中で判断が付くことが前提。

## 6. 進め方

1. 3の規則を研究ツールの変種として実装し、小さい条件で動くことを確かめる。
2. 手元の比較（4データ×2間隔×3 seed、24 run）と、崩れたrunの確認（本規模、2 run）。
3. 見込みがあれば、本規模（uranium、seed 0〜9）。
4. 製品の経路へ入れるかは、ユーザーの判断（入れるなら、別のspecと独立レビューと基準版の更新）。

## 12. 既定への採用（2026-10-21）

ユーザーの判断で、8の形（「いつ」は検出器に任せ、警報の後の変化点と帰属先を符号長で選ぶ）を、製品の既定にした（基準版10。[spec](../../.kiro/specs/fedsda-minimum-description-length-alarm-interval-assignment/design.md)）。製品の名前は、研究分野で使われる語に揃えた: 設定の項目`TrainingDataAssignmentSettings.alarm_interval_assignment_policy`の値`minimum_description_length`（最小記述長の原理）、新しいモデルの符号長は予測的符号長（prequential code length）、切り替わりの符号長はFixed-Shareの切り替わりの確率1/Tから。今の扱いは`detector_change_span_and_mean_loss_increase_tolerance`として残し、構成`fedsda-with-candidate-validation`が使う。

- 残る固定の閾値: サーバのクラスタリングの閾値（γ=0.1。clientの許容量と同じ値であることを、参加者の設定の検査が求める）は変えていない。説明長で統合を決める案は[IMPROVE-026](improvement-candidates/improve-026-server-clustering-by-description-length.md)、検出も説明長で行う案は[IMPROVE-027](improvement-candidates/improve-027-calibrated-sequential-change-detection-by-description-length.md)に記録した。

- **増えた警報は、各clientの最初の概念の間（最初の約1000標本）の誤警報**。最小記述長の扱いは、その全部で正しく「現在のモデルのまま」を選ぶが、検出器は10〜20標本ごとに警報を出し続ける。
- **原因は、初期モデルの損失の統計が楽観的なこと**。初期モデルは、runの最初に概念0の標本で事前学習し、損失の統計を、学習に使ったその標本で取る（`runtime/initial_model_pretraining.py`）。統計の平均は約0.018で、流れの新しい標本での損失は約0.23（間隔100、最初の400標本の警報の区間の平均。約10倍）。検出器は、警報の後に、現在のモデルの履歴の平均を基準にしてやり直すので、基準が実際の水準に追いつくまで（流れの標本が統計に十分たまるまで）、警報が続く。
- **今の扱いで警報が少ないのは、最初の警報で新しいモデルを作るため**。区間の平均（約0.25〜0.35）が基準（約0.018）＋0.1を超えるので合わないと判定し、同じ概念の新しいモデルを作るとみる（結果の記録で、最初の警報が初期モデルから新しいモデルへの採用になっていることは確かめた。判定の値そのものは記録していない）。新しいモデルの統計は、その学習の損失から取り直されるので、誤警報が止まる。最小記述長の扱いの、登録・統合が少ないこと（11の、MNIST2の登録15→6、統合13→6）と合う。
- **影響**: 精度は下がらない（13の表で、MNISTは既定と同程度以上）。手元の実行時間は、最小記述長の方が短かった（seed 0で1257→1078秒、seed 1で1290→1111秒。候補の学習——最大30 epoch——が減るため）。警報の精度の指標が下がるのは、この誤警報のため。誤警報ごとの選択の計算は、計算回数の指標に数えられていない（[NEW-005](implementation-findings/new-005-minimum-description-length-selection-computation-not-counted.md)）。
- **直す案（未実施）**: (a) 最小記述長が「現在のモデルのまま」を選んだら、検出器の基準を、選択に使った列での現在のモデルの損失の平均でやり直す（変化が無いという判定を、その概念の損失の水準として使う。固定の閾値は増えない。変化を見逃した場合に基準が上がり、次の検出が遅れる危険がある）。(b) 初期モデルの統計を、学習に使っていない標本の損失（予測的な損失）で取る（全部の扱いに影響する）。
