# 現行モデル単体への優位と、混合予測の利得を分ける対照

2026-10-24の研究対照設計。本実装の採否を決めるspecではない。2026-10-25追記: AとBを独立研究ツールで実装・2500標本の検証を完了した（[A結果](fedsda-current-mixture-benefit-results-20261025.md)、[B結果](fedsda-adopted-candidate-removal-results-20261025.md)）。以下は設計時点の計画と受け入れ条件であり、検証済みの範囲は結果報告を参照する。

## 問いと根拠

[来歴追跡の本規模結果](fedsda-shadow-lifecycle-uranium-results-20261024.md)では488採用すべてに統合前の正重み予測があった。一方、122件は終了時も未登録で、359件の統合のうち339件は登録と同じ同期だった。したがって、候補の影響を「サーバ登録されたか」だけでは測れず、統合後の代表の係数を候補単体の効果ともみなせない。

[新30標本の採用保留対照](fedsda-reconnected-candidate-holdout-20261024.md)では、現行の学習帰属モデル単体に対する損失の優位を採用条件にしても、6入力すべてで改善できなかった。これは混合とのずれを調べる動機になるが、そのずれが原因と証明した結果ではない。候補の概念固有部の固定、待機、警報による中止、採用後の学習、短い窓の推定誤差も別の説明として残る。

調べたいことは二つある。

1. 同じ新標本で、候補が現行単体より良いことと、候補を既存の混合へ加えることの良さが一致するか。
2. 実際に採用された候補が、統合前の実際の混合予測をどれだけ改善・悪化させているか。

既存の来歴JSONは係数の集計だけを保存しており、標本ごとの確率・正誤や候補を外した確率は復元できない。今回の結果だけから、この二つの利得を算出してはならない。

## A: 同一の保留候補で比較対象だけを変える非介入計測（推奨）

### 参照経路と時系列

`research_reconnected_candidate_holdout`のwait30構成を参照にする。S1のD>0で保留を開始し、概念固有部は固定、共有部は現行共有部へ追随する。次の30標本で観測し、窓を完了して中止されなければ、スコアの符号にかかわらず採用する。警報・現行ID変更・置換による中止と終了時打切りは既存wait30と同じにする。

新たなスコアを実際の採否・予測重み・学習へ使わない。三つの比較を別々のゲートrunへ分けず、一つのwait30 runに載せ、全比較で候補・標本・採用後の経路を揃える。開始時の標本と候補の学習済み標本は窓へ含めない。

各標本では、ラベルによる重み更新・通常学習より前のモデルで確率を得る。ラベル観測後に、その確率から以下のスコアを計算する。保存はその後でもよいが、当該ラベルで更新された重みや分類器で確率を作り直してはいけない。候補の評価だけの標本を学習標本として数えない。

### 同じ標本で保存する確率とスコア

- `p_C`: 現在の学習帰属モデルの、局所パラメータによる単体予測。
- `p_H`: 保留候補の予測。概念固有部固定・現行共有部追随。
- `q`: 通常経路が実際に出した最終混合確率。同期モデル群の混合と局所モデル群の混合を、実際の外側係数で結合したもの。
- `q_alpha = (1-alpha) q + alpha p_H`: 候補を外側から加える仮想混合。主解析alpha=0.1。感度解析alpha=0.01、0.5も同時に保存し、結果を見て主解析を選び直さない。

主解析の損失Lは、既存wait30の`evaluate_classifier_per_sample_log_losses`と同じ対数損失（nats）とする。これは、外側の混合重み更新で使う`true_class_loss_of_prediction_probabilities`の有界損失（1−真クラス確率）とは異なる。既存ゲートとの比較で損失関数まで変更してしまわないよう、区別する。

具体的にはCPU float32の確率から、二値なら`abs(p−y)`、多クラスなら`1−p_y`の有界損失tensor Bを作り、`−torch.log(torch.clamp(1−B, min=1e-12))`とする。既存のclassifier用関数と同じdtype・演算順序・下限を全確率に適用する。p_C/p_Hの値とG_currentは元のwait30の保存値と一致することを検査する。補助的に有界損失差と0/1正誤も保存する。正の値が改善で統一する。

| スコア | 標本ごとの定義 | 答える問い |
| --- | --- | --- |
| 単体差g_current | L(p_C,y)−L(p_H,y) | 従来の現行単体との比較 |
| 混合との差g_mix_alone | L(q,y)−L(p_H,y) | 候補単体は実際の混合全体より良いか |
| 混合への追加利得g_add(alpha) | L(q,y)−L(q_alpha,y) | 指定した質量で候補を加えると良いか |

`g_mix_alone`と`g_add`を混同しない。候補単体の窓全体の対数損失がqより悪くても、相補的な予測なら追加が役立つ場合がある。これは窓の集計であり、一標本の真クラス確率について逆転すると主張するものではない。逆にp_Cを上回っても、qが既に良ければ追加が害になる場合がある。損失の改善とargmax正解率の改善も別に数える。

有界損失だけなら（丸め誤差を除き）`g_add(alpha)=alpha*g_mix_alone`であり、一定alphaを変えても窓の符号は変わらない。有界損失でこの二つを独立の証拠や相補性の発見と数えない。主解析を対数損失に揃え、仮想混合の正誤変化も直接数える理由である。

q_alphaは診断用の外側追加であり、製品の新ID追加・初期重み・同期snapshotsの動作を再現するものではない。「実際に採用したら得られる精度」と呼ばない。

### 窓の集計と選択の過適合を避ける扱い

各候補の同一完了30標本でG_current、G_mix_alone、G_addの和を求める。主表はG_current>0/≤0 × G_add(0.1)>0/≤0の四象限。0は非正に含め、厳密0件数も別記する。部分窓は完了窓と混ぜず、実標本数・中止理由を付けた補助表へ置く。

この30標本は評価器の一致・不一致を調べる窓であり、G>0を条件に選んだ同じ窓の正解率を「採用後の汎化性能」とは呼ばない。スコアで採否を変える効果の検証は、後段の別runか、選択に使わない新しい将来窓が必要。

標本ごとには損失差だけでなく、p_C/p_H/q/q_alphaの正誤、予測ラベル、真クラス確率、正解へ変わった件数・不正解へ変わった件数、qとp_Hの予測不一致を保存する。二値分類でも製品と同じ閾値・tie規則を使う。真概念は事後集計専用で、スコア・alpha・窓終了へ使わない。

全体は候補平均と標本平均を分け、dataset×stream×intervalごとのseed内集計→seed平均を主とする。候補ごとの標本を独立seed扱いした検定をしない。候補0件の条件は「対象なし」であり、改善0件・効果0とはしない。

## B: 実際の採用後、統合前の混合から候補だけを外す非介入計測

Aの仮想追加だけでは実際の採用時の重みを説明できない。その補助として、既存S1即時採用経路を全く変えず、採用後の標本で「実際の混合」と「候補だけを外した混合」を比較する。AとBは別run・別経路なので、候補を一対一対応した比較には使わない。

実際の内側重みをw_j、外側の同期/局所係数をa/b、各枝の候補予測をp_sync,j / p_local,jとする。候補jを外した各枝を、残りの内側重みで再正規化する。

```
q_sync_without_j  = (q_sync  − w_j p_sync,j)  / (1−w_j)
q_local_without_j = (q_local − w_j p_local,j) / (1−w_j)
q_without_j       = a q_sync_without_j + b q_local_without_j
g_remove          = L(q_without_j,y) − L(q,y)
```

正なら実際の混合に候補を含む方が良い。外側a/bは保持する。枝をまたいだ全係数をまとめて再正規化する別の除去方式とは区別する。実装では可能な限り残ったモデルから直接再結合し、減算の丸め誤差を避ける。残余質量が1e-12以下・残存モデルなしの場合は定義不能として件数を記録し、利得0に置き換えない。計算後の確率有限性・範囲・正規化を製品規則で検査する。

候補jに対応する負IDはclient内でscopeし、正式登録後はglobal IDへ追随する。最初の統合が起きた時点で単体の除去診断を止める。代表として残った場合も止める。以後は複数モデルのパラメータが混ざるため、元候補だけを取り除く演算ではない。最終同期の登録・統合による観測0件も打切りとして報告する。

負IDの保留モデル、登録後globalモデル、出自client/他client、採用後経過標本数別に集計する。統合前の実利用と、統合後代表の来歴は別表にする。同じ標本に複数候補があれば候補ごとに除去差を計測するが、候補別の差を足して実際の精度変化としない。相互作用があるためである。

Bも一標本で予測を差し替える診断であり、過去の学習・重み更新・共有部・通信・統合まで候補なしにした因果的ablationではない。候補採用による累積の精度差を説明し切るものではない。

## 実装可能性と必要なhook

`runtime/observed_sample_prediction.py`の`ObservedSamplePrediction`は、実際の最終`combined_prediction_probabilities`と、予測に使った内側`prediction_weights_by_model_id`を返す。外側係数は関数呼出し前に`mixture.snapshot_weights()`で取得できる（既存来歴ツールと同じ）。関数内部ではラベルによる重み更新があるため、返却後のownerから係数を読んではならない。

Aのqは返却された最終確率をコピーして使える。p_Cとp_Hは通常学習より前にno_gradで作る。Bでは返却された`prediction_probabilities_by_model_id`は同期側であり、局所側の全モデル確率は返却されない。既存返却値だけで両枝の除去ができると仮定してはいけない。研究ツール内の限定hookで通常の局所結合への入力確率をコピーするか、学習前の局所モデルで追加forwardを行い、再結合が実際のqと一致することを確認する。製品の返却型・通常経路は変更しない。

extra forwardはRNGを消費せず、train/eval状態・optimizer・パラメータ・共有部参照を変えない。必要なコピーとテンソルは標本単位で解放する。追加診断のMACを別計数し、標準のアルゴリズムMACから分離する。秒数は診断込みとして明示する。将来ゲートへ使う機能にする場合、そのforwardは実コストとして含める。

## 規模・受け入れ条件・判断

まずAだけを手元で実装・検証することを推奨する。SEA4/SINE2の通常・固定2種、間隔100、seed0/1、2500標本/clientを最低規模とする。既定とwait30の12条件24 runを保存し、計測なしwait30の同一環境結果と照合する。旧2500標本結果を再利用できるかは実行ソース・入力・環境と保存形式を確認して決める。未確認の段階で参照一致を保証しない。全ての比較スコアは同じwait30 runで取得する。

受け入れ条件は、計測なしwait30との全保存指標・予測digest・採用経路が秒と分離済み追加診断MAC以外一致すること、窓が開始後の新標本だけであること、当該ラベル更新前の確率・重みを使うこと、全候補でスコアの評価標本IDが一致すること。合成確率によって「単体は改善・混合追加は悪化」と逆の例、binary/multiclass、alpha=0の厳密一致、定義不能の除去、同期境界、取消、打切りを検査する。

標準報告は全構成の精度と既定からの差pp、上り/下りbyte、MAC（forward/backward推定の内訳と追加診断分）、秒数。現時点のA/Bのこれらの実測値はすべて未測定。来歴追跡の標準値は別報告に全12条件を記載している。

G_current>0なのにG_add≤0の候補が多ければ、比較対象を混合へ変更する根拠になる。ただし、その場のスコアを選別へ使っただけで精度改善を主張しない。不一致が少なければ、比較対象の変更を優先せず、待機中の頭部固定・採用後学習・短い窓の推定誤差へ調査を移す。Bで損失改善なのに正誤が変わらなければ、損失と精度のずれとして扱う。

AとBの実装・実験は別出力なら並行できる。おすすめはAを先に手元2500標本で確かめ、診断の必要性と保存量を確認してからuraniumの5000標本・10seed・64workersへ拡張すること。今回は設計のみなので、未実装CLIのサーバコマンドは提示しない。
