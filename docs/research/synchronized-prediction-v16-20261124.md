# 予測の版の比較: 同期の版だけ・手元の版だけ・混合（基準版16、2026-11-24、主担当）

- 問い: FedHASPの「同期の版と手元の版の混合」の利得（手元の版だけの予測に対して+1.6pp）は、単純な設定で見たとおり、全clientで平均した同期の版が良いことから来るか（[定理の記録](linear-concept-pool-theorems-20261124.md)の8・10章、[付録の下書き](theory-appendix-draft-20261124.md)の命題7）。指摘「1モデルで予測しても同程度以上」への答えの、神経網での確認。
- 入力:
  - 同期の版だけ: 既存の構成 `fedsda-synchronized-model-prediction`（予測に使うパラメータを最後の同期の時点のものにする）。`results/fedsda-synchronized-prediction-v16/20261124_165503_all-datasets-seeds0-9`（uranium、commit `c0d2595b`、未commitの変更なし、基準版16、120 workers、400 run・失敗0、1時間53分）。
  - 混合（FedHASPの既定 `fedsda`）: 6データは `fedsda-component-ablation-v16/20261029_231413_core-components-v16-seeds0-9`、新しい4データは基準版16の既定と同じ値の、基準版15のときの構成 `fedsda-every-sample-change-interval-search`（`fedsda-every-sample-change-interval-search/20261029_172159_new-datasets-seeds0-9`。[一致の確認](fedsda-component-ablation-v16-20261030.md)）。
  - 手元の版だけ（`fedsda-local-parameter-prediction`）: `fedsda-component-ablation-v16` の2つの掃引。
- 集計: 研究ツール `tools/research_post_change_accuracy_breakdown/synchronized_prediction.py`（追加の実験なし）。出力は `results/fedsda-synchronized-prediction-v16/analysis/`（`analysis_synchronized_prediction.md`・`synchronized_prediction_cells.csv`。Git管理外）。
- 確認: 10データ×間隔50・100・200・500×seed 0〜9の400組すべてで、3つの版の上りの通信量が一致した（予測だけが違い、学習が同じ）。新しい4データの既定は、間隔50・500の80 runで基準版16の既定（`fedhasp-oracle-v16` の `product-default`）と精度が一致した。各runで標本ごとの正誤の平均が要約の精度と一致した。
- 途中の誤りと訂正: 最初の集計で、新しい4データの既定に基準版15の `fedsda`（`new-datasets-v15`）を使い、基準版16の既定と80 runすべてで精度が違った（−1.10〜+0.85pp）。基準版16の `fedsda` に当たるのは基準版15の `fedsda-every-sample-change-interval-search` で、[以前の記録](fedsda-component-ablation-v16-20261030.md)のとおりだった（主担当の取り違え）。正しい結果に差し替えた。

- 変化の直後（各clientの真の概念の変化から集約の間隔I件）: 間隔50で、同期の版だけが混合より0.14pp高い（84.06対83.92、0/10）。間隔500で、混合−同期は+1.53、同期−手元は−0.62（同期の版が古く、変化の直後に手元の版が良い）。
- それ以外（変化の直後を除く）: 間隔50で、混合−同期+0.06、同期−手元+1.52。間隔500で、同期−手元は+0.08（区間が0をまたぐ）。
- データ別（全標本、混合−同期）: 間隔50では−0.13〜+0.42で、10データのうち6データが±0.1以内。間隔500では+0.09〜+4.82で、変化のあるRotMNIST4（+4.82）・RotMNIST2（+1.95）・CIRCLE2（+1.40）で大きい。
- 標準指標（1 runあたり、10データ・seedの平均）: 上り・下りの通信は3つの版で同じ（間隔50で上り3,193MB・下り3,311MB、間隔500で317MB・335MB）。clientの前向きMACは、混合が1つの版だけより1.4%（間隔50）〜1.3%（間隔500）多い（2つの版を計算する）。逆向きMACは同じ。経過時間はrunごとに保存されていない。

## まとめ（数値をそのまま述べる）

- 同期が頻繁なとき（間隔50）、版の混合の利得（手元の版だけに対して+1.57pp）のほぼ全部（+1.53pp）は、同期の版で予測するだけで得られる。混合と同期の版だけの差は+0.05pp。単純な設定（[定理の記録](linear-concept-pool-theorems-20261124.md)の8・10章）で、同期の版が良い理由をclient間のばらつきの平均による低下と見た説明と合う（神経網でばらつきを直接は測っていない）。
- 同期の間隔が長いほど、同期の版は古くなり、変化の直後に手元の版が良くなる（間隔500の変化の直後で同期−手元−0.62）。そのとき混合は、2つの版のどちらよりも良い（間隔500で混合−同期+1.05、混合−手元+0.83）。付録の命題7（2つの版の良い方に追いつく）の形と合う。
- 指摘「1モデルで予測しても同程度以上」との関係: 版の混合については、同期が頻繁なら「同期の版1つ」でほぼ同じ精度が出る（指摘のとおり）。同期の間隔が長い（通信を減らした）ときは、混合が1つの版より約1pp良い。
- 限定: 同期の版だけの構成は、モデルの間の重み付け（Fixed-Share）は残したまま、版だけを1つにしたもので、「モデル1つで予測する」比較（固い予測）とは別。神経網でのばらつきの分解は未実施。
