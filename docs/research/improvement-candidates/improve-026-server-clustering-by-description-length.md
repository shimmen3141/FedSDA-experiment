# IMPROVE-026: サーバのクラスタリングの判定も、符号長の比較で行う

- 日付: 2026-10-21
- 対象: サーバのクラスタリングの判定（`methods/fedsda/consolidation/model_clustering_calculations.py`、`runtime/model_clustering_and_consolidation.py`）、判定の閾値`maximum_same_cluster_decision_score`（最終構成の定数`_MAXIMUM_TOLERATED_MEAN_LOSS_INCREASE = 0.1`）、クロス評価の集計（`runtime/model_cross_evaluation.py`の`CrossEvaluationLossSums`）
- 基準commit: `c21a240`（基準版9。研究ツールの変種`default-detector-gated-segment-assignment`まで）
- 関係: [IMPROVE-021](improve-021-statistical-test-for-held-model-reuse.md)（clientの再利用の判定）、[IMPROVE-025](improve-025-simplify-clustering-decision-to-loss-distance.md)（クラスタリングの判定の単純化）、[帰属を1つの推論にまとめる案](../fedsda-unified-concept-assignment-inference.md)の8〜10
- 種別: アルゴリズムの変更（判定の考え方をclientとサーバでそろえる）
- 状態: 検証中（2026-10-21にユーザーの指示で記録し、同じ日に手元の診断を始めた。下の1・2）

## 前提（なぜ取り組むか）

- 2026-10-21、clientの警報の後の判定（変化点と行き先）を、固定の閾値（区間の平均損失≦履歴の基準＋0.1）から、符号長の比較へ替える形（研究ツールの変種`default-detector-gated-segment-assignment`）を、ユーザーが既定にすると決めた（10 seedの本規模で、24条件のうち17で既定との差が0以上、崩れなし）。
- 同じ値0.1は、サーバのクラスタリングの判定（モデル対の判定の値≦0.1で同じクラスタ）にも残っている。clientの判定だけを替えると、「固定の閾値を使わない」という手法の説明が、サーバの側で崩れる。
- IMPROVE-025の診断: クラスタリングの判定の値（既定はクラス別の正誤の信頼下限、損失の距離でも同等の区別の力）よりも、**閾値の位置**が統合の見逃しを決めていた（損失の距離では、MNISTで同じ概念の対の距離が0.1をまたぐ）。閾値を固定しない検定（差の検定）や分布の境目は、対ごとの見積りで今より悪かった。

## 方針（案）

- 2つのモデルA・Bを1つにまとめるか（同じ概念か）を、clientの判定と同じ「符号長」で比べる:
  - 別のまま: Aの標本をAが、Bの標本をBが説明する（それぞれの自分の標本での対数損失の合計）。
  - まとめる: 両方の標本を、1つのモデル（例: AとBのうち、両方の標本の合計が短い方、または統合後のモデル）が説明する。
  - まとめた方が短ければ（＝別々に持つ分の符号長＝モデル1つ分の記述の罰を上回るほど説明が悪くならなければ）、同じクラスタにする。モデル1つ分の罰に何を使うかが設計の要点（clientの判定では、新しい学習者の学び始めの損失が罰として働いた。サーバでは、それに当たる量を決める必要がある）。
- 必要な変更: クロス評価の集計は今、有界の損失（1−真のクラスの確率）の件数・和・2乗和だけを返す。対数損失の和も返すように、clientの評価とメッセージを変える（通信の数え方は、値が1つ増えるだけ）。

## 懸念

- 精度への効果は小さい見込み。基準版9のablationでは、クラスタリングの判定の方式を替えても、MNIST4の短い間隔を除き、±0.25pp以内だった。主な意味は、手法の一貫性（固定の閾値を使わない）。
- 「まとめる」側の説明に使うモデルの選び方と、モデル1つ分の罰は、新しい設計の判断。罰を固定の値で与えると、閾値を別の名前で置くことになる。
- 統合が変わると、その後の学習・通信・帰属が変わる（基準版を上げる変更）。

## 必要な比較と採否の基準

- 比べる相手: clientの判定を符号長の比較へ替えた既定（採用後の既定）。
- 指標: 精度（データ×間隔ごと）、統合の正しさ（IMPROVE-025の数え方: 正しい統合・誤った統合・見逃した統合）、最終のモデル数、通信量。
- 採否: 精度と通信を落とさずに、サーバの閾値も無くせるなら採用を検討する。
- 次の一手: 既定のrawの記録（`model_pair_clustering.*`、`client_cross_evaluation.*`）から、まず対ごとの判定で見積もる（有界の損失の集計から、近似で始められるか確かめる）。

## 1. 今の判定が同じ概念の対を統合しない割合（2026-10-21、基準版9・10の本規模のraw）

`method-comparison-v9`・`method-comparison-v10`の`fedsda`の240 runずつのraw（記録の表`model_pair_clustering`の、真の概念が同じか・判定の値・同じクラスタにしたか）で数えた（Git管理外の一時script）。

- CIRCLE2では、同じ概念の対のうち統合されるのは、版9・10とも約半分（間隔100で0.49→0.49）。統合されなかった同じ概念の対の判定の値は、中央値0.16〜0.21で、閾値0.1を超える。違う概念の対の判定の値は、中央値0.32〜0.40。閾値の位置がCIRCLE2では低い（IMPROVE-025でMNISTについて見たことと同じ形）。版10のCIRCLE2の通信の増加（間隔100で下り1.19倍）は、サーバが持つモデルの数の増加（同期の後の平均4.38→5.65、統合5.2→2.6回）による（[設計の18](../fedsda-unified-concept-assignment-inference.md)）。
- MNIST2・MNIST4・SINE2では、同じ概念の対の統合の率は0.7〜0.95。SEAは、違う概念の対の多くも統合される（SEAの概念は、機能の上でほとんど区別できない）。

## 2. 符号長で判定する規則の見積り（2026-10-21、手元）

`results/fedsda-provisional-candidate-expert/20261021_clustering-description-length-diagnosis`（`diagnose_clustering_description_length.py`・`analyze_clustering_description_length.py`・`diagnosis.json`・`analysis.txt`）。基準版10の既定で、CIRCLE2（seed 0・1）・MNIST2・SINE2・SEA4・MNIST4（seed 0）、間隔100、各5000標本を実行し、クロス評価のたびに、配布したモデルXの、対象Yの標本（clientあたり最大50標本）での対数損失の和と、候補と対象が同じ評価では、その標本で概念ごとの部分を初期化し直した学習者の予測的符号長（clientの最小記述長の選択の「新しいモデル」と同じ計算）を記録した。包まない実行と値が同じことを、小さい条件で確かめた。

ℓ(X|Y)をYの標本でのXの1標本あたりの対数損失、f(Y)をYの標本で新しく学ぶ1標本あたりの予測的符号長として、記録したモデル対ごとに計算し直した（その後の軌跡は替えない近似）。

| 条件 | 今の判定（同じ概念の対の統合／違う概念の対の誤統合） | 規則0: 片方がもう片方の標本をそれ自身と同じくらい説明する | 規則MDL（両側）: ℓ(A\|B)≦f(B) かつ ℓ(B\|A)≦f(A) |
|---|---|---|---|
| CIRCLE2・seed 0 | 2/9 ／ 0/15 | 6/9 ／ 1/15 | 5/9 ／ 0/15 |
| CIRCLE2・seed 1 | 3/8 ／ 0/18 | 6/8 ／ 1/18 | 3/8 ／ 0/18 |
| MNIST2・seed 0 | 7/7 ／ 0/4 | 0/7 ／ 0/4 | 7/7 ／ 1/4 |
| SINE2・seed 0 | 29/29 ／ 0/47 | 17/29 ／ 0/47 | 27/29 ／ 0/47 |
| SEA4・seed 0 | 2/2 ／ 2/2 | 2/2 ／ 0/2 | 2/2 ／ 2/2 |
| MNIST4・seed 0 | 5/5 ／ 0/5 | 1/5 ／ 0/5 | 5/5 ／ 0/5 |

- **規則MDL（両側）**は、「どちらのモデルも、相手の標本を、新しく学ぶより短く説明できるなら、同じ概念とみなす」。clientの最小記述長の選択と同じ考え方で、固定の閾値を持たない（新しく学ぶ費用が、モデル1つ分の罰として働く）。今の判定とほぼ同じ区別の力で、CIRCLE2のseed 0では同じ概念の対の統合が2/9→5/9に増え、誤統合は増えない。MNIST2で誤統合が1件増える。
- 規則0（片方がそれ自身と同じくらい説明する）は、MNISTで同じ概念の対をほとんど統合しない（自分の標本で学んだモデルが有利なため）。片側だけの規則MDLは、MNISTで違う概念の対を誤統合する。
- 対の数が少ない（CIRCLE2で24〜26対）ので、結論は暫定。新しく学ぶ費用は、クロス評価の標本数（最大50）に依存する（標本が多いほど、新しい学習者が良くなり、統合が厳しくなる）。
- 次（未実施）: 研究ツールで、サーバのクラスタリングの判定を規則MDL（両側）に替え、実際の軌跡で精度・通信・モデル数を比べる。clientのクロス評価の返信に、対数損失の和と、新しく学ぶ符号長の2つの値を足す必要がある（通信は値が2つ増えるだけ）。

## 3. 規則MDL（両側）を実際の軌跡で試す（2026-10-21、手元）

研究ツールの変種`default-description-length-clustering`（`_description_length_clustering_policy`）。基準版10の既定の上で、サーバのクラスタリングの対の判定の値を max(ℓ(A|B)−f(B), ℓ(B|A)−f(A))＋閾値 に置き換える（average linkageの後に閾値と比べるので、対の平均で「どちらも相手の標本を新しく学ぶより短く説明できる」なら同じクラスタ）。`results/fedsda-provisional-candidate-expert/20261021_description-length-clustering-n5000`（間隔100、seed 0・1、各5000標本・10 client、8 run）。既定は`results/fedsda-provisional-candidate-expert/20261021_recalibrated-detector-baseline-n5000`の`default`。

- CIRCLE2では、統合が増え、最終のモデル数が減り、下りが13〜20%減る（版10の通信の増加の分を戻す程度）。精度は−0.25・+0.03pp。

## 4. 罰をモデルの一生の予測的符号長にする2つの形（2026-10-21、手元）

3の崩れ（新しく学ぶ費用がMNISTで大きすぎる）を受け、ユーザーの判断で、罰を、クロス評価の標本数に依存しない「モデルの一生の予測的符号長」にした。clientが、各標本で、学習の前の現在のモデルの損失（検出器へ渡す有界の損失）を対数損失にして、そのときの現在のモデルへ足す（登録と統合でIDが変わったら、計数の置き場と同じように移す）。c(Y)を、保有するclientの合計を件数で割った1標本あたりの値とする。研究ツールの`_description_length_clustering_policy`の`learning_cost_source`で選ぶ。条件は3と同じ（間隔100、seed 0・1、各5000標本、既定は`results/fedsda-provisional-candidate-expert/20261021_recalibrated-detector-baseline-n5000`の`default`）。

- (a) 両側（`default-lifetime-description-length-clustering`、`results/fedsda-provisional-candidate-expert/20261021_lifetime-description-length-clustering-n5000`）: ℓ(A|B)≦c(B) かつ ℓ(B|A)≦c(A)。
- (b) 件数で重み付け（`default-pooled-lifetime-description-length-clustering`、`results/fedsda-provisional-candidate-expert/20261021_pooled-lifetime-description-length-clustering-n5000`）: まとめる（代表Rが両方の標本を説明する）N_A·ℓ(R|A)＋N_B·ℓ(R|B)と、別々に持つN_A·c(A)＋N_B·c(B)を比べる（Nは一生の件数、Rは短い方）。

| 条件 | 精度（%）: 既定 → (a) → (b) | 下りの比 (a) / (b) | 最終のモデル数: 既定 → (a) → (b) |
|---|---|---|---|
| CIRCLE2・seed 0 | 97.63 → 97.38 → 96.94 | 0.87 / 0.52 | 9 → 7 → 2 |
| CIRCLE2・seed 1 | 97.40 → 97.44 → 97.34 | 0.85 / 0.66 | 10 → 8 → 5 |
| MNIST2・seed 0 | 95.00 → 95.00 → **88.49** | 1.00 / 0.98 | 2 → 2 → 1 |
| MNIST2・seed 1 | 94.73 → 94.73 → **87.25** | 1.00 / 0.98 | 2 → 2 → 1 |
| SEA4・seed 0 | 85.36 → 85.65 → 85.36 | 1.30 / 1.00 | 1 → 2 → 1 |
| SEA4・seed 1 | 85.37 → 85.66 → 84.89 | 1.32 / 1.06 | 2 → 5 → 4 |
| SINE2・seed 0 | 98.41 → 98.44 → 98.38 | **1.60** / 1.18 | 2 → 8 → 4 |
| SINE2・seed 1 | 98.72 → 98.69 → 98.67 | **1.74** / 1.07 | 2 → 9 → 2 |

- (a) はMNISTで崩れず、CIRCLE2の下りが13〜15%減るが、SINE2で統合が減り（46→24、69→46回）、下りが1.6〜1.7倍になる。若い重複モデルAの一生の符号長は、学び始めの損失を含んで大きいので、「成熟したBの標本を、AがBの一生の符号長以下で説明する」側が成り立たない。
- (b) はMNISTの2 seedとも崩れ（違う概念を統合し、最終のモデル数1）、CIRCLE2でも精度が下がる。若いモデルの一生の符号長が大きいので、「別々に持つ」側が高くつき、何とでもまとまりやすい。
- **判定の仮説と、統合の操作が合っていない**: 符号長の比較は「代表Rが両方の標本を説明する」という仮説を調べるが、統合の操作は、メンバーのパラメータを件数で重み付けして平均する（代表のパラメータを保つのではない）。違う概念のモデルをまとめると、平均したモデルはどちらの仮説の説明とも違うものになり、崩れる。符号長で統合を決めるなら、統合の操作も「代表のパラメータを保ち、メンバーの標本を代表へ移す」に合わせる必要がある（未検討）。
- 判断（暫定）: 3つの形（新しく学ぶ費用、一生の符号長の両側、件数で重み付け）とも、どこかのデータで崩れるか通信が増え、今の判定（閾値0.1）より安全な形は見つからなかった。サーバの判定は、当面、今の閾値のまま。
