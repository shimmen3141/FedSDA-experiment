# IMPROVE-027: 警報を出す時点も、誤警報の率を抑えた符号長の比較で決める

- 日付: 2026-10-21
- 対象: clientの変化の検出（`methods/fedsda/loss_change_detection/`の損失の監視、e-SR、`_E_SR_FALSE_ALARM_CONTROL_ALPHA = 0.001`）と、警報の後の判定（研究ツールの変種`default-detector-gated-segment-assignment`の区分けの比較）
- 基準commit: `c21a240`（基準版9。研究ツールの変種まで）
- 関係: [帰属を1つの推論にまとめる案](../fedsda-unified-concept-assignment-inference.md)の7・8・10、[IMPROVE-021](improve-021-statistical-test-for-held-model-reuse.md)
- 種別: アルゴリズムの変更（検出と判定を1つの逐次の検定にまとめる）
- 状態: 未検証・未採用（2026-10-21。ユーザーの指示で記録。研究段階で、設計が難しい）

## 前提（なぜ取り組むか）

- 2026-10-21に試した2つの形の結果:
  - **毎標本、窓の中の区分けの符号長を比べて警報を出す形**（研究ツールの変種`default-unified-assignment-inference`、設計の7）: 警報が多すぎ（SEAで既定の8〜18回に対し408〜765回）、SINE2以外で下がった（SEAで−1.4〜−1.9pp）。一方、**SINE2では4間隔とも+0.32〜+0.84pp**と、今の既定より大きく上がった。急な変化を、検出器より早く捉えたためとみる（検出の遅れは未確認）。
  - **警報は今の検出器（e-SR、α=0.001）に任せ、警報のときだけ区分けを比べる形**（`default-detector-gated-segment-assignment`、設計の8〜10）: 崩れず、多くの条件で既定と同じか上回った（2026-10-21、ユーザーが既定にすると決定）。SINE2の改善は+0.10〜+0.18ppで、毎標本の形の+0.3〜+0.8ppより小さい。
- 毎標本の形が崩れた理由は、切り替わりの符号長（−ln(1/T)＋ln(行き先の数)≈5 nats）だけで警報にするため、雑音や近い概念での偶然の差と、毎標本・全部の位置と行き先を比べる多重の比較で、誤警報が増えたこと。今の検出器は、誤警報の率をα=0.001で抑えるように作られている。
- つまり、「早く・正しく切り替わりの位置と行き先を捉える」力は符号長の比較にあり、「誤警報を抑える」力は検出器にある。両方を1つの判定に持たせられれば、SINE2で見えた改善を、ほかのデータを崩さずに取り込める可能性がある。

## 方針（案）

- 区分けの符号長の差（現在のモデルのまま−最良の切り替わり）を、尤度比（e-値）として扱い、検出器と同じαで、誤警報の率を抑えて判定する。候補:
  - 尤度比のe-過程: 現在のモデルを帰無の予測分布、切り替わり先（別の保有モデル、または新しい学習者の予測）を対立の予測分布として、予測可能な（各標本の前に決まる）対立の混合で尤度比を積み上げる。e-過程の最大が1/αを超えたら警報（Villeの不等式で、誤警報の率をα以下に抑える）。
  - 位置と行き先の多重の比較は、対立を事前の重みで混ぜる（混合のe-値は、e-値のまま）ことで扱う。
- 警報の後の判定（変化点と行き先）は、今の区分けの比較のままでよい（同じ量から出るので、説明がそろう）。
- 試作は研究ツールの変種として作り、手元で、今の既定（検出器に任せる形）と比べる。

## 懸念

- 設計が難しい: 新しい学習者の予測は、標本ごとに学習で変わるので、尤度比の対立の予測分布が予測可能であることを確かめる必要がある（予測してから学ぶ形なら満たすはず）。クラス別の監視（ClassESR）がCIRCLE2・MNISTで効いていた（ablation）ので、全体の対数損失の尤度比だけでは、検出が弱くなる恐れがある。
- 計算量: 毎標本、保有モデルの数と、新しい学習者の数（位置の候補の数）の計算が要る（毎標本の形の試作は、既存の変種の2〜4倍の時間だった）。
- 改善が見込めるのは、急な変化のデータ（SINE2）が中心かもしれない。ほかのデータで改善するかは不明。

## 必要な比較と採否の基準

- 比べる相手: 検出器に任せる形（採用後の既定）。
- 指標: 精度（データ×間隔ごと）、警報の回数・誤警報・検出の遅れ（`change_response_metrics`）、変化点の推定の誤差、通信量、所要時間。
- 採否: 誤警報を増やさずに、検出の遅れが縮み、精度が上がるなら採用を検討する。
