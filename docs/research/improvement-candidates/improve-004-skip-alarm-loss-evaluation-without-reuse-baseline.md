# IMPROVE-004. 履歴基準が使えないモデルの警報区間評価を省く

- 記録日: 2026-10-08。種別: 計算効率。状態: 未検証・未採用。
- 固定旧基準: `748c3aa`。新実装の確認commit: `45bef9a`。発見時: alarm-training-interval-preparationの境界調査。

## コードで確認した事実

旧`clients/fedsda.py::_resolve_drift`と新`runtime/alarm_interval_model_reuse_assessment.py::evaluate_held_models_for_alarm_interval_reuse`は、保有モデル全件について警報区間の標本損失と平均を評価した後、履歴基準の有無を調べる。履歴件数不足または平均0で基準を使えないモデルは、再利用候補だけでなく候補の初期値選択へ渡す評価済み候補列からも除外される。そのモデルの区間平均は新実装の返却結果には使われない。

## 変更案と仮説

履歴基準を先に調べ、基準を使えないモデルのforwardと区間平均計算を省く。ただし入力検査は省略せず、全モデルが除外された場合にも不正標本を黙って受理しない契約を別途設計する。

履歴の短いモデルが多い警報では、除外モデル数×区間件数に対応するforward計算を削減できる見込み。該当モデルが実験中にどの程度存在するか、時間削減率は未測定。履歴基準が全モデルにある場合は削減効果がない。

## リスクと比較

- 旧の計算量診断とverboseログの内容が変わる。単なる構造整理には含めない。
- 評価を省くと分類器・特徴・ラベルの不正の発見箇所や例外順が変わりうる。共通入力と分類器別入力の検査を検討する必要がある。
- 現行の評価は乱数を使わないが、将来の分類器に状態更新や乱数を伴う評価を許す場合、この案の適用条件を再確認する。
- 比較対象: 基準なし/履歴1件/平均0のモデルを含む条件と、全モデルに基準がある対照。区間評価時間、forward標本数、返却候補列・再利用ID・初期値ID・全体runの精度/切替列/乱数状態、拒否入力時の挙動を確認する。

IMPROVE-003は警報後検証の固定参照をまとめて評価する案。本件は警報区間の評価対象を減らす案であり、対象と変更箇所が異なる。採否基準の具体的な許容差は未定。現リファクタリングでは全モデル評価を維持し、採用時には別specと回帰・診断の扱いの承認を必要とする。
