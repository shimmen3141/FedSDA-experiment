# IMPROVE-002. 参照モデルの固定で不要なランダム初期化を省く（候補・未検証）

種別: 計算効率・簡略化。旧実装の固定基準: 748c3aa。発見spec: post-alarm-reference-model-fixation（2026-10-07、記録は2026-10-08）。torch乱数の消費が変わるため、挙動を維持する整理ではない。

- 記録日: 2026-10-08。対象は旧clients/fedsda.pyの_snapshot_reference_models、移植済みのruntime/post_alarm_reference_model_fixation.pyのfix_reference_models_at_alarm。
- 確認した事実: 旧は保有モデルごとに_new_model()で新しい分類器を生成し、直後にset_params(model.get_params())で全parameterを上書きする。生成時のランダム初期値は一度も使われない。生成は保有モデル1件ごとにtorchのグローバル乱数を消費する。新実装は旧との一致のため、同じ順序・同じ回数で分類器を生成している（参照specのtestで処理後の乱数状態を旧と照合している）。
- 確認した事実（影響範囲）: 参照の固定は候補の生成・学習の後に実行される。したがって消費が変わるのは固定より後の乱数で、警報後の学習のshuffle等に波及しうる。保有モデル数が違うと後続の乱数列も変わるという結合が現状にはある。
- 変更案: 乱数を消費しない方法で参照を作る。例: 初期化を伴わない複製、または乱数状態を退避・復元する範囲内での生成（learning/models/torch_random_state_scope.pyに既存の退避手段がある）。
- 期待する利点（仮説）: 保有モデル数に比例する初期化計算を省ける。保有モデル数と後続の乱数列の結合がなくなり、条件間の比較で乱数由来の差が減る可能性がある。計算時間の削減量は未測定で、モデルが小さいため小さい可能性がある。
- 悪化・トレードオフの懸念: 乱数列が変わるので旧11・最終3goldenの値が変わりうる。性能の期待値を変える理由はないが、seed単位の値は一致しなくなる。golden更新を伴う変更になる。
- 必要な比較: 変更前後で、参照の値が同一であること（parameter全値）、乱数消費の有無、全体runの指標分布（複数seedの精度・モデル数・切替数）に系統差がないこと、計算時間。採否の数値基準とseed群は未定。
- 現在の扱い: 未検証・未採用。リファクタリングでは旧と同じ乱数消費を維持する。採用する場合はgolden更新の扱いを含む別specで承認する。
