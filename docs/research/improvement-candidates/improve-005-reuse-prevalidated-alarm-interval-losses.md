# IMPROVE-005. 前区間の事前検査と吸収で損失評価を共用する

- 記録日: 2026-10-08。種別: 計算効率・処理簡略化。状態: 未検証・未採用。
- 対象は新実装、確認commit `d6cc32d`。発見spec: alarm-training-interval-preparation。固定旧基準は`748c3aa`。

## 確認した事実

`runtime/alarm_training_interval_preparation.py::prepare_alarm_training_intervals`は、全前区間標本が吸収契約を満たすことを評価保存より前に確認するため、現行分類器で各標本の有界損失を評価する。保存後、`runtime/assigned_training_sample_absorption.py::absorb_assigned_training_samples_into_held_model`が同じ分類器・標本を再評価し、損失統計へ反映する。

対象testの`test_alarm_preparation_saves_evaluation_before_real_absorption`は、3標本の実損失評価→保存→吸収中の同じ分類器での3回の実損失評価を記録している。現行CPU分類器では、この間にparameter/乱数の更新はない。これは旧実装の不具合ではなく、新実装の「不正末尾標本でも保存を含む状態を変更しない」契約を既存の公開吸収APIだけで守るために追加したコストである。

## 案と効果の仮説

前区間全件の検査で得た損失を、保存後の吸収へ明示的に受け渡して再評価を省く。検査済み標本と損失の対応、分類器の同一性・parameter世代、損失件数・有限性を保証する公開契約を別specで設計する。単に検査loopを消すと不正入力で評価保存や部分吸収が残るため、今回の契約を満たさない。

前区間m標本では、準備＋吸収に含まれる当該forwardを2m回からm回へ減らせる可能性がある。全実験の時間削減率、メモリ増加、実装の単純化効果は未測定。損失配列の保持と新しい契約が必要になり、APIがかえって複雑になる可能性もある。

## 検証とリスク

- 全件の入力検査を状態更新前に終えること、保存→吸収の順を維持すること、不正先頭/末尾で全状態・乱数不変であることを再検証する。
- 準備と吸収の間にモデルが変わる、標本Tensorが外部から変更される、将来の分類器が評価時に乱数・内部状態を更新する場合、損失の共用は同値とは限らない。適用範囲や所有者の設計が必要。
- 単独吸収など他の呼出しでは既存APIを保つか、評価と反映を分けた共通APIへ移すかを比較する。内部/private窓口の追加だけで解決しない。
- 測定: forward標本数、準備時間、ピークメモリ、拒否契約、保存標本順、学習標本/統計/概念計数、全parameter/grad/optimizer、3乱数、実旧対照と後続共同更新、全回帰/golden。計算量診断への影響も確認する。
- 採否の閾値は未定。未検証の候補であり、現移植のsource・goldenには適用していない。

IMPROVE-004は履歴基準を使えないモデルを区間評価から省く案。本件は前区間の入力検査と吸収にある同一損失評価の共用で、対象も拒否契約上のリスクも異なる。
