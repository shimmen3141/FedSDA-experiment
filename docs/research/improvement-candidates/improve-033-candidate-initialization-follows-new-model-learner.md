# IMPROVE-033: 新しいモデルの候補の初期値を、MDLの選択で短かった学習者の種類に合わせる

- 日付: 2026-10-30（ユーザーの指摘から）。状態: 研究ツールで比べた（手元の2500標本・5 seed、2026-10-31）。既定にする根拠は得られなかった（製品の経路は変えない）。
- 対象: 警報の後に「新しいモデル」を選んだときの候補の初期値（`methods/fedsda/candidate_model_selection/candidate_parameter_initialization.py`の`select_candidate_initial_parameter_snapshot`、設定`candidate_parameter_initialization_source=lowest_evaluated_mean_loss_model`）と、MDLの選択の学習者（[IMPROVE-032](improve-032-reverse-order-prequential-code-for-all-change-intervals.md)、[NEW-006](../implementation-findings/new-006-minimum-description-length-keeps-partially-changed-concept-in-current-model.md)）。

## 今の扱い（基準版16）

- MDLの選択は、「新しいモデル」の仮説の記述長を、初期化し直した学習者とwarm startの学習者の予測的符号長の短い方＋ln 2で測る。どちらが短かったかは、選択の記録`alarm_interval_assignment_selection.new_model_learner_name`に残る。
- 候補は、どちらの学習者が短くても、区間の標本で平均損失が最も小さい保持モデルの写し（adapterと出力層を含む全部のパラメータ）から学習を始める。特徴抽出器を固定し、adapterと出力層だけを最大30エポック学習する（検証は区間の2割、3回続けて改善しなければ止める）。
- この初期化は、MDLと2つの学習者を入れる前の実装から引き継いだもので、学習者を足したとき（基準版11）に見直した記録は無い。
- そのため、判断（どちらの学習者で説明できるか）と、実際の候補の作り方がつながっていない。コンセプトの全体が変わって初期化し直した学習者が選ばれた場面でも、候補は既存のモデル（多くは現在のモデル）から始まる。区間は最大31件、検証は6件ほどなので、早期終了が早く効くと、出発点の偏りが残る可能性がある。

## 案

候補の出発点を、MDLの選択で短かった学習者の種類に合わせる。

- 初期化し直した学習者が短かった: 現在のモデルの写しの、adapterと出力層を初期化し直したものから始める。初期値は、その警報のMDLの選択で「初期化し直した学習者」が最初に持っていた値と同じにする（同じ初期化の手順と、そのrunの探し方が実際に使うseedの関数。基準版16の既定の1件刻みなら`derive_reinitialized_learner_single_pass_initialization_seed`、5件刻みなら選んだ変化区間の長さを含む`derive_reinitialized_learner_initialization_seed`）。警報ごとに、学習者の最初の概念固有部と候補の初期値の概念固有部が一致することを実行中に確かめ、一致しなければ止める。runの乱数を変えない。
- warm startの学習者が短かった: 現在のモデルの写しから始める。
- 候補の学習の手順（特徴抽出器の固定、エポック数、早期終了）は変えない。学習者の学習後の状態は使わない（学習者は変化点より前の標本まで学んでいて、1回ずつしか学んでいないため。2026-10-30の会話）。

論文での説明もしやすくなる: 「新しい概念を説明する学習者の種類を記述長で選び、その種類で候補を作る」。

### MNIST系で下がる原因の手がかり（2026-10-30、途中まで（190 run）の結果から。scratchpadの`improve033_cause.py`）

- 候補の学習のエポック数（案の変種、初期値の種類ごとの平均。上限30、検証の損失が3回続けて改善しなければ止まる）: 初期化し直した候補は、MNIST2で24.2、MNIST4で19.9、fmnist2で30.0（5件すべてが上限まで学んで止まった）。現在のモデルの写しから始めた候補は、MNIST2で8.6、MNIST4で11.1、fmnist2で9.0。合成データでは、初期化し直した候補でも13.5〜13.7エポックで止まる。MNIST系で一から学ぶ候補は、30件ほどの区間と上限のエポックでは学びきれていない（上限で止まり、検証の損失がまだ下がっている）とみる。
- 概念ごとの精度の差（案−今）: MNIST4・200で概念0は−0.0、概念1〜3は−0.86〜−1.06。MNIST2・50で概念0は−0.11、概念1は−0.47。下がるのは新しく作られる概念のモデルで、元の概念は変わらない。CIRCLE2・50では逆に概念1が+0.94。
- 解釈（未確認）: MNISTの新しい概念は、2つの数字のラベルを入れ替えたもので、残りの8つの数字は元の概念と同じ。現在のモデル（または区間の損失が最小のモデル）から始める候補は、その8クラスの知識を引き継ぎ、入れ替わった2クラスだけを数エポックで直せる。初期化し直すと、10クラスの出力層とadapterを区間の30件ほどから学び直すことになる。MDLの記述長で初期化し直した学習者が短いのは、区間の中で1件ずつ予測と更新をするとき、写しの学習者が入れ替わったクラスを自信を持って誤り、大きい対数損失を払うからである。つまり記述長は「区間の中で、その場で予測しながら学ぶときの符号長」を測っていて、「複数エポック学んだ後の候補の出来」は測っていない。この2つは、一部のクラスだけが変わる概念で食い違う。
- 全部の結果での追記（2026-10-31）: 初期化し直した候補のエポック数の平均は、fmnist2で22.6、fmnist4で20.4、rotmnist2で14.4、rotmnist4で16.3（写しから始めた候補は6.1〜10.2）。概念ごとの差（案−今）は、fmnist4・200で概念0が−0.09、概念1〜3が−0.58〜−3.13、rotmnist4・200で概念0が−0.06、概念1と3が−1.33と−1.78（概念2は+0.21）。rotmnist4・50では概念1〜3が+0.43〜+2.82。下がるのも上がるのも新しく作られる概念のモデルで、元の概念は変わらない点は、途中までの結果と同じ。

## 切り分けの診断の計画（2026-10-31、ユーザーの指示）

### 目的

手元の比較（runの全体の精度）では、次の4つが混ざって分けられない。runの経過を変えずに、警報ごとに候補の出発点と学び方だけを変えた候補を経過の外で作り、同じ評価の標本で比べて切り分ける。

- 問1: 画像でも、全体が変わるドリフト（rotmnistの回転）なら、初期化し直した出発点の候補が良いか。合成データ（CIRCLE2、SINE2）では良いか。
- 問2: エポック数を増やせば、初期化し直した候補が、既存モデルの写しから始めた候補に追いつく・上回るか（エポックの不足か、標本の数の不足か）。
- 問3: MDLの選択で短かった学習者の種類は、警報ごとに、どちらの出発点の候補が良いかを予測するか。
- 問4: 一部のクラスだけが変わる概念で、初期化し直した学習者の符号長が短くなるのは、写しの学習者が変わったクラスで自信を持って誤り大きい対数損失を払うためか（2026-10-31の会話の推論、未確認）。
- 付随: 低下の原因が、候補そのものの出来か、その後の経過（統合の減少、同じ概念のモデルが残る）か。この診断は前者だけを測る。

### 方法（研究ツールの診断用の変種。製品の経路は変えない）

- 変種`product-default-candidate-start-diagnostics`: `product-default`と同じ経過で、候補を作る警報ごとに、経過の外で次の候補を作って評価し、記録だけを足す。runの経過（予測、学習、通信、計算回数の指標、選択）は`product-default`と完全に同じにする。
- 出発点（3つ）:
  - A: 製品の既定（区間の平均損失が最小の保持モデルの写し。`select_candidate_initial_parameter_snapshot`の戻り値）。
  - B: 現在のモデルの写し。
  - C: 現在のモデルの写しの概念固有部（adapterと出力層）を、その警報のMDLの「初期化し直した学習者」と同じ手順・同じseedで初期化し直したもの（IMPROVE-033の研究ツールと同じ。学習者の最初の値とのdigestの一致を確かめる）。
- 学び方（3つ）: 製品の候補の学習の関数を使い、設定だけを変える。
  - T30: 製品の既定（最大30エポック、検証は区間の2割、3回続けて改善しなければ止め、最良の検証の時点のパラメータに戻す）。
  - E100・E300: 最大100・300エポック、止めない（続けて改善しない回数の上限を最大エポック数以上にする）。検証の分け方と最良の時点に戻す扱いは同じ。
- 乱数: 製品の候補の学習の直前に、torch・Python・NumPyの乱数の状態を保存し、診断の候補を1つ作る前ごとにその状態へ戻す（どの候補も、検証の分け方とミニバッチの順が製品と同じ）。全部の診断が終わったら状態を戻してから製品の学習を行う。A・T30の候補の学習後のパラメータが、製品が実際に学んだ候補と一致することを警報ごとに確かめる（一致しなければ例外）。
- 評価の標本（経過の外。runの乱数を使わない）: 警報の標本の真の概念（`observed_concept_id`）から、`(runのseed, client_id, alarm_sample_index)`から作った別の乱数で、新しい標本を生成する。
  - 静的評価: 500件。各候補の精度、平均の対数損失（製品と同じ下限）、クラスごとの正解数と件数。
  - 逐次評価: 別の200件。各候補の写しで、1件ずつ予測してから概念固有部を1回更新する（MDLの学習者と同じ学び方`_accumulate_prequential_code_length`の更新）。累積の精度と対数損失。採用後にそのclientで学び続ける場面に近い。
- 学習者の符号長（問4）: その警報で選んだ変化区間について、初期化し直した学習者とwarm startの学習者の、標本ごとの対数損失（学習者が処理した順）、ラベル、真の概念を記録する。製品の選択の値（`new_model_learner_name`、`description_length`）と、記録から足し上げた符号長が一致することを確かめる。
- 警報ごとの付随の記録: client_id、alarm_sample_index、選んだ変化区間の長さ、短かった学習者、区間の標本の真の概念の列、区間の直前の標本の真の概念、警報の標本の真の概念に既に保持モデルがあったか（あれば理想は再利用で、新しいモデルは誤り）、A・B・Cの各候補の完了エポック数・最良の検証の損失・最後の訓練の損失。
- 計算量: 診断の候補の学習と評価は、runの計算回数の指標に入れない。

### 条件

- 10データ（SINE2、CIRCLE2、SEA2、SEA4、MNIST2、MNIST4、fmnist2、fmnist4、rotmnist2、rotmnist4）×間隔50・200×seed 0〜4、各client 2500標本、10 client、手元（Windows）12 workers。100 run。
- 経過が変わっていないことの確認: この変種の100 runの精度、予測の記録のdigest、最終のパラメータのdigest、通信、計算回数の指標が、手元の比較（`results/improve033-candidate-init/20261030_local-n2500/results.json`）の`product-default`と許容誤差なしで一致すること。

### まとめ方

- 警報を、データ、間隔、真の変化の種類（区間の直前の概念と警報の概念の組。概念が同じなら誤った警報）、短かった学習者で分ける。
- 問1・問2: 出発点×学び方の9候補の、静的評価と逐次評価の精度の平均（警報の対で、A・T30との差）。ラベルを入れ替えるデータでは、変わったクラスと変わらないクラスに分けた精度も出す。
- 問3: 出発点を選ぶ規則を経過の外で比べる。いつもA（今の既定）、学習者に合わせる（IMPROVE-033の案、AかC）、いつもB、いつもC、検証の損失が小さい方（T30のAとC）、後から見て良い方（上限）。
- 問4: 変わったクラスと変わらないクラスの標本ごとの対数損失を、2つの学習者で比べる。
- 限界: 経過の外の評価なので、採用の後の連合の集約と統合の影響は測らない。有望な規則があれば、別に全体のrunの変種で確かめる。その際、初期化し直すときに、別々のclientが別々の乱数で作ったモデルを統合で平均する問題（2026-10-31の会話。手元の比較で、案の変種は間隔50で統合の回数が減った: MNIST4 5.2→1.2、rotmnist4 8.6→2.2）も扱う。
