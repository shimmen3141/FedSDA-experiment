# IMPROVE-033: 新しいモデルの候補の初期値を、MDLの選択で短かった学習者の種類に合わせる

- 日付: 2026-10-30（ユーザーの指摘から）。状態: 研究ツールで比べる予定（製品の経路は変えない）。
- 対象: 警報の後に「新しいモデル」を選んだときの候補の初期値（`methods/fedsda/candidate_model_selection/candidate_parameter_initialization.py`の`select_candidate_initial_parameter_snapshot`、設定`candidate_parameter_initialization_source=lowest_evaluated_mean_loss_model`）と、MDLの選択の学習者（[IMPROVE-032](improve-032-reverse-order-prequential-code-for-all-change-intervals.md)、[NEW-006](../implementation-findings/new-006-minimum-description-length-keeps-partially-changed-concept-in-current-model.md)）。

## 今の扱い（基準版16）

- MDLの選択は、「新しいモデル」の仮説の記述長を、初期化し直した学習者とwarm startの学習者の予測的符号長の短い方＋ln 2で測る。どちらが短かったかは、選択の記録`alarm_interval_assignment_selection.new_model_learner_name`に残る。
- 候補は、どちらの学習者が短くても、区間の標本で平均損失が最も小さい保持モデルの写し（adapterと出力層を含む全部のパラメータ）から学習を始める。特徴抽出器を固定し、adapterと出力層だけを最大30エポック学習する（検証は区間の2割、3回続けて改善しなければ止める）。
- この初期化は、MDLと2つの学習者を入れる前の実装から引き継いだもので、学習者を足したとき（基準版11）に見直した記録は無い。
- そのため、判断（どちらの学習者で説明できるか）と、実際の候補の作り方がつながっていない。コンセプトの全体が変わって初期化し直した学習者が選ばれた場面でも、候補は既存のモデル（多くは現在のモデル）から始まる。区間は最大31件、検証は6件ほどなので、早期終了が早く効くと、出発点の偏りが残る可能性がある。

## 案

候補の出発点を、MDLの選択で短かった学習者の種類に合わせる。

- 初期化し直した学習者が短かった: 現在のモデルの写しの、adapterと出力層を初期化し直したものから始める。初期値は、その警報のMDLの選択で「初期化し直した学習者」が最初に持っていた値と同じにする（同じ初期化の手順と、そのrunの探し方が実際に使うseedの関数。基準版16の既定の1件刻みなら`derive_reinitialized_learner_single_pass_initialization_seed`、5件刻みなら選んだ変化区間の長さを含む`derive_reinitialized_learner_initialization_seed`）。警報ごとに、学習者の最初の概念固有部と候補の初期値の概念固有部が一致することを実行中に確かめ、一致しなければ止める。runの乱数を変えない。
- warm startの学習者が短かった: 現在のモデルの写しから始める。
- 候補の学習の手順（特徴抽出器の固定、エポック数、早期終了）は変えない。学習者の学習後の状態は使わない（学習者は変化点より前の標本まで学んでいて、1回ずつしか学んでいないため。2026-10-30の会話）。

論文での説明もしやすくなる: 「新しい概念を説明する学習者の種類を記述長で選び、その種類で候補を作る」。

## 検証の計画（研究ツール、製品の経路に組み込まない）

- 変種（どちらも基準版16の既定の上）:
  - `product-default-candidate-init-follows-new-model-learner`: 上の案。
  - `product-default-candidate-init-current-model`: 補助の対照。学習者に関係なく、いつも現在のモデルの写しから始める。
- 比べ方: **主な比較は、案と`product-default`（今の扱い）の差**。補助の対照は、warm startの学習者が短かった警報では案と同じ初期値になるので、案との差は「初期化し直した学習者が短かった警報」でしか生じない。そのため補助の対照は、今の「損失が最小の保持モデル」と「現在のモデルの写し」の違いを見るためにだけ使う（2026-10-30の計画レビューの指摘）。3つとも同じ研究ツールの実行で流す。
- 選択と初期化の結び付け: 製品では、警報の後の選択（`select_alarm_interval_assignment`の戻り値。短かった学習者の名前を含む）が、そのまま候補の初期化を呼ぶ`resolve_alarm_change_interval`に引数`alarm_interval_assignment_selection`で渡る。研究用の差し込みは、(a) 選択の関数を包み、戻り値（選択のオブジェクト）ごとにclientの番号・警報の標本の番号を表に覚え（クライアントをまたいで警報が交互に来ても区別できる）、(b) 解決の関数を包み、渡された選択が覚えたものと同じオブジェクト（`is`）で、警報の標本の番号も一致することを確かめてから、学習者の名前とclientの番号を初期化に使う。合わなければ例外にし、使った後は消す。
- 記録（警報ごと）: clientの番号、警報の標本の番号、選んだ変化区間の長さ、短かった学習者、使った初期値の種類（初期化し直し／現在のモデルの写し）、使ったseed、初期値の概念固有部のdigest（と、学習者の最初の値との一致の結果）、今の扱いなら選ばれたモデルのID、候補の学習で止まったエポック。runごとの精度と合わせて、意図した分岐が実際に働いたかを後から照合できるようにする。

- 本規模（研究室サーバ、64 workers）: 6データ（SINE2、CIRCLE2、SEA2、SEA4、MNIST2、MNIST4）×間隔50・100・200・500×seed 0〜9、3変種で720 run。見るもの: 同じseedの対の精度の差（平均±SD、勝ち/負け）、新しいモデルの採用の回数、概念が取り込まれたrun（概念0以外の精度が88%未満、NEW-006の指標）、通信とMAC。
- 結果のまとめ方: データ×間隔のセルごとに、対の差の平均・SD・勝ち/負けを並べる。全体の値を添えるときは、24セルの平均を等しい重みで平均する（runの対の単純平均ではない）。データをまたぐ平均で、あるデータの悪化を別のデータの改善で打ち消さない（[構成要素比較の判断手順](../../experiments/fedsda-component-ablation-analysis.md)と同じ）。初期化し直した学習者が選ばれた警報の数と、その警報を含むrunの結果も、セルごとに分けて示す。許容する低下の幅は事前に決めず、ユーザーが判断する。
- 締め切り（2026-11-20）前に既定を変えるかは、本規模の結果を見てユーザーが判断する。

### MNIST系で下がる原因の手がかり（2026-10-30、上の途中までの結果から。scratchpadの`improve033_cause.py`）

- 候補の学習のエポック数（案の変種、初期値の種類ごとの平均。上限30、検証の損失が3回続けて改善しなければ止まる）: 初期化し直した候補は、MNIST2で24.2、MNIST4で19.9、fmnist2で30.0（5件すべてが上限まで学んで止まった）。現在のモデルの写しから始めた候補は、MNIST2で8.6、MNIST4で11.1、fmnist2で9.0。合成データでは、初期化し直した候補でも13.5〜13.7エポックで止まる。MNIST系で一から学ぶ候補は、30件ほどの区間と上限のエポックでは学びきれていない（上限で止まり、検証の損失がまだ下がっている）とみる。
- 概念ごとの精度の差（案−今）: MNIST4・200で概念0は−0.0、概念1〜3は−0.86〜−1.06。MNIST2・50で概念0は−0.11、概念1は−0.47。下がるのは新しく作られる概念のモデルで、元の概念は変わらない。CIRCLE2・50では逆に概念1が+0.94。
- 解釈（未確認）: MNISTの新しい概念は、2つの数字のラベルを入れ替えたもので、残りの8つの数字は元の概念と同じ。現在のモデル（または区間の損失が最小のモデル）から始める候補は、その8クラスの知識を引き継ぎ、入れ替わった2クラスだけを数エポックで直せる。初期化し直すと、10クラスの出力層とadapterを区間の30件ほどから学び直すことになる。MDLの記述長で初期化し直した学習者が短いのは、区間の中で1件ずつ予測と更新をするとき、写しの学習者が入れ替わったクラスを自信を持って誤り、大きい対数損失を払うからである。つまり記述長は「区間の中で、その場で予測しながら学ぶときの符号長」を測っていて、「複数エポック学んだ後の候補の出来」は測っていない。この2つは、一部のクラスだけが変わる概念で食い違う。
