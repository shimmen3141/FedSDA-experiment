# IMPROVE-021: 保有モデルの再利用の判定を、固定のしきい値から統計的な検定へ替える

- 日付: 2026-10-20
- 対象: 警報の区間での保有モデルの再利用の判定（`runtime/alarm_interval_model_reuse_assessment.py`、`methods/fedsda/loss_statistics/loss_baseline_selection.py`）、最終構成の定数`_MAXIMUM_TOLERATED_MEAN_LOSS_INCREASE = 0.1`（`runtime/fedsda_final_configuration_run_settings.py`）
- 基準commit: `053fefc`（基準版7）
- 種別: アルゴリズムの変更（手法の軸との整合）
- 状態: 検証中（2026-10-20再開。ユーザーの方針: 上位互換でなくても、固定の閾値でない方法で同程度の精度・通信量を達成できれば手法として意味がある。検定で「棄却できなければ合う」とする案Bは再利用へ大きく偏る見積り。累積の対数損失で選ぶ案Aは、手元の3 seedで精度が既定と同程度、下りは0〜17%増）
- 優先: 4案の3番目（設計の検討が要り、波及が大きい）

## 前提（なぜ取り組むか）

手法の主軸の案は「概念の管理に使う硬い状態（統計的な検出と、データの帰属）と、予測に使う柔らかい状態（全モデルの適応的な重み付け）を分ける」こと。名前の案FedSTEP（Sequential-Test assignment and Expert-tracking Prediction）は、帰属を**逐次の検定**で行うことを表す（[位置づけ](../method-positioning.md)）。

ところが、警報の後に「どの保有モデルを使うか」を決める再利用の判定は、検定ではなく**固定のしきい値**で行っている。検出（ClassESR、e-検出）は統計的なのに、その直後の帰属の判定だけが経験的な閾値なので、軸の説明と合わない。候補検証を外した（2026-10-20）ので、警報の後の帰属は、この判定と「新しいモデルの採用」だけになり、判定の重みが増した。

## コードで確認した事実

- 警報の区間の標本で全保有モデルを評価し、各モデルの「区間の平均損失」と「履歴の基準の平均損失」を比べる。区間の平均損失が、基準＋`maximum_alarm_interval_mean_loss_increase`（既定0.1）以下なら「合う」とする。現在のモデルを優先し、合うモデルが無ければ、新しいモデルを作る（`alarm_change_interval_resolution.py`）。
- 同じ値0.1（`_MAXIMUM_TOLERATED_MEAN_LOSS_INCREASE`）が、次にも使われている。
  - 候補検証の参照モデルの再適合の判定（`maximum_tolerated_mean_loss_increase`。候補検証ありの構成だけ）。
  - サーバのクラスタリングの判定のしきい値（`ModelClusteringCriteria.maximum_same_cluster_decision_score`）。こちらは、クラス別の正誤の信頼下限（信頼水準0.95）と組み合わせた判定。
- 損失は[0, 1]の有界の値（1−真のクラスの確率ほか）。区間の長さは、最小5標本（`_MINIMUM_CHANGE_INTERVAL_SAMPLE_COUNT`）から帰属の保留の容量30まで。

## 方針

1. 再利用の判定を、「区間の損失が、そのモデルの履歴の損失の分布と比べて、有意に悪いか」の検定に置き換える案を設計する。候補:
   - 有界の損失の平均の差に対する、e-値やHoeffding/Bernstein型の信頼区間による検定（検出と同じ枠組み。区間が短いときは「棄却できない＝合う」に倒れやすい点に注意）。
   - クラスタリングと同じ、クラス別の正誤の信頼下限による判定（サーバとclientで判定の考え方をそろえられる）。
2. しきい値0.1の3つの使い方を分け、どれを替えるかを決める（クラスタリングは別の判定なので、まずはclientの再利用だけ）。
3. 研究ツールの変種として実装し、手元で比べ、効果があれば本規模で確かめる。

## 懸念

- 区間が短い（5〜30標本）ので、検定の検出力が低い。棄却できないときに「合う」とすると、別の概念へ古いモデルを使い続け、学習データが混ざる（以前のCIRCLE2の診断で、混ざりが精度を下げた）。逆に倒すと、新しいモデルが増えて通信が増える（IMPROVE-020と逆向き）。
- 有意水準などの新しい値が増え、論理が簡単になるとは限らない。軸との整合（説明の一貫性）と、精度・通信の両方で評価する。
- 判定が変わると、再利用・新規作成の回数、帰属、学習が変わる（基準版を上げる変更）。

## 必要な比較と採否の基準

- 比べる相手: 現在の既定（`fedsda`）。
- 指標: 精度（dataset×間隔ごと）、再利用と新規作成の回数、学習データの混ざり（概念の多数と違う割合。`20261019_sine2-validation-length-diagnosis/diagnose.py`の数え方を再利用できる）、通信量。
- 採否: 精度と通信を落とさずに、判定を検定で説明できるなら採用を検討する。

## 検証結果

### 1. 今の判定の実態（2026-10-20、手元、既定・基準版8、2500標本・10 client・seed 0〜2）

`results/fedsda-provisional-candidate-expert/20261020_held-model-reuse-decision-diagnosis/`の`diagnose.py`（記録）、`analyze.py`（集計）、`diagnosis.json`。mnist2・circle2・sea4・sine2、間隔100・500の24 runで、警報の区間の解決1,377回を記録した。

- 正しさの定義: 区間の概念＝区間の標本の観測概念の多数（区間の純度の平均は0.98）。モデルの概念＝そのモデルに取り込んだ標本の観測概念の多数（統合や混ざった学習データがあると不正確になりうる。この近似の限界は未確認）。
- 判定の内訳（全体）: 正しい再利用59.2%、誤った再利用（違う概念のモデル）15.9%、正しい新規作成11.8%、見逃した再利用（同じ概念のモデルがあるのに新規作成）13.1%。
- データ別: CIRCLE2は正しい再利用が77〜82%。MNIST2は正しい再利用が29〜34%で、誤った再利用26〜28%、見逃し26〜29%と悪い。SEA4は誤った再利用が23〜36%。
- 区間の長さ別: 30標本を超える区間（923回）は正しい再利用76%・見逃し3%。30標本以下（454回）は正しい再利用26%・見逃し34%（10〜19標本では45%）。
- 見逃した再利用（181回）: 同じ概念のモデルの増加量の四分位は0.14・0.19・0.27で、57%が0.2以下。**標本の少ない区間で、固定の閾値0.1が厳しすぎる**誤り。
- 誤った再利用（219回）: 選んだモデルの増加量の四分位は−0.09・−0.02・0.04で、正しい再利用（−0.02・0.00・0.03）と区別がつかない。区間の長さの平均25、純度0.97。63回は現在のモデル、89回は同じ概念のモデルも保有していた。**平均損失の増加量では区別できない誤り**（違う概念のモデルが、その区間ではよく当たる。モデルの概念の近似の誤りも含みうる）。

### 2. 区間の長さに応じて閾値を緩める規則の見積り（判定だけ）

`rule_replay.py`。記録した材料で、許容＝max(0.1, k/√n)（nは区間の長さ）として判定し直した。判定の後の学習・帰属の変化は含まない。

| 規則 | 全体: 正しい再利用 / 誤った再利用 / 正しい新規 / 見逃し | 30標本以下: 同 |
|---|---|---|
| 今（0.1） | 59.2% / 15.9% / 11.8% / 13.1% | 25.6% / 15.2% / 25.8% / 33.5% |
| k=0.5 | 60.6% / 16.6% / 11.0% / 11.7% | 30.0% / 17.4% / 23.6% / 29.1% |
| k=0.7 | 64.1% / 19.6% / 8.8% / 7.5% | 39.9% / 20.5% / 21.4% / 18.3% |

- k=0.7で、短い区間の判定の正しさ（正しい再利用＋正しい新規）は51%→61%、全体は71%→73%。見逃しは減るが、誤った再利用が増える（15.9%→19.6%）。誤った再利用は学習データを混ぜる（以前のCIRCLE2の診断で精度を下げた）ので、判定の正しさの改善がそのまま精度の改善になるとは限らない。

### 3. クラス別の損失と、モデルの概念の純度（同じ24 run）

`diagnose_classwise.py`（記録）、`analyze_classwise.py`（集計）、`diagnosis_classwise.json`。警報の区間を解決する直前に、保有モデルごとに、区間のクラス別の平均損失、クラス別の履歴の基準、取り込んだ標本の概念の純度を記録した（前向きの計算だけで、24 runとも精度が前の診断と同じ＝runを変えていない）。

- モデルの概念の純度: 平均0.948、四分位0.961・1.0・1.0、0.8未満が9.4%。
- 選んだモデルの概念の純度: **誤った再利用では平均0.714、正しい再利用では0.977**。誤った再利用の多くは、複数の概念の標本で学習した「混ざったモデル」を、別の概念の区間で再利用したもの。
- 区別の力（誤った再利用の方が大きい確率、AUC）: 全体の増加量は0.398（区別できない）、クラス別の増加量の最大は0.780（ある程度区別できる）。四分位は、誤った再利用0.095・0.195・0.521、正しい再利用−0.013・0.026・0.156。
- クラス別の条件を足した規則の見積り（判定だけ）: 判定の正しさは、今の71.0%に対して、「全体0.1＋クラス別0.2」61.9%、「全体0.1＋クラス別0.3」66.2%、「区間の長さで緩めた全体＋クラス別0.3」67.1%。クラス別の条件は、正しい再利用も落とし（59%→48〜55%）、誤った再利用はほとんど減らない（16%前後のまま。落とした後に、別の誤ったモデルが選ばれる）ので、**判定の条件として足すと悪くなる**。

### 判断（暫定）

- 再利用の判定の規則を替える効果は小さい。区間の長さで閾値を緩めると判定の正しさは+2pp（見逃しが減り、誤った再利用が増える）。クラス別の条件を足すと悪くなる。
- 誤った再利用の主な原因は、判定の規則ではなく、**モデルが混ざること**（純度の低いモデルが、別の概念にも当たる）。直す対象は、混ざりの出どころ（クラスタリングでの、違う概念のモデルの統合か、警報の区間・保留の標本の、違うモデルへの取り込みか）。
- 次の一手の候補: 混ざりの出どころの診断（モデルごとに、統合で混ざったのか、取り込みで混ざったのかを分ける）。混ざったモデルが精度をどれだけ下げているか（混ざったモデルの予測の正答率、その重み）も一緒に測る。IMPROVE-021は、この診断の結果を見るまで保留にする。

### 4. 混ざりの出どころ（同じ24 run）

`results/fedsda-provisional-candidate-expert/20261020_model-contamination-origin-diagnosis/`（`diagnose.py`、`analyze.py`、`diagnosis.json`）。clientの計数のownerの3つの操作（標本の取り込み、登録の確認での移し替え、統合でのまとめ）を、計数を変えずに観測し、標本がどの経路でモデルに入ったかを追った（追った計数は、ownerの計数とrunごとに一致することを確かめた。24 runとも精度は前の診断と同じ）。runの終わりの保有モデルについて、多数と違う概念の標本（混ざり）の経路:

- 全体: 標本587,134件のうち混ざりは94,104件（16.0%）。経路は、**帰属の保留（FIFO）からの解放が87.3%**、違う概念のモデルの統合が8.5%、再利用での区間の取り込みが3.7%、警報の区間の準備が0.5%。
- 条件別の混ざりの割合: SEA4は44%（34モデル中30が純度0.8未満）、CIRCLE2は9%、SINE2は3〜8%、MNIST2は5〜6%。CIRCLE2は、統合による混ざりも約25%。
- 解釈: 概念が変わってから警報が出るまでに保留の容量（30標本）より長くかかると、新しい概念の標本が、警報の前に、古い概念のモデルへ解放されて取り込まれる。SEA4は、概念どうしの違いが小さく、警報が出にくい（混ざっても害が小さい可能性もある。未検証）。
- 次の候補を[IMPROVE-024](improve-024-withdraw-released-samples-after-estimated-change-point.md)として記録した（警報の時点で、推定した変化点より後に解放された標本を、古いモデルの学習データから外す）。

### 判断（暫定、2の時点）

- 検定（区間の長さに応じた許容）で直せるのは「見逃した再利用」で、効果は判定の正しさで全体+2pp程度と小さい。誤った再利用を増やす代償もある。
- 主な誤りの1つである「誤った再利用」（16%）は、平均損失の増加量では区別できない。区別するには、別の量（例: クラス別の損失の比較。検出がクラス別の監視で効いたのと同じ考え方）が要る見込み（未検証）。
- 次の一手の候補: (a) モデルの概念の近似の正しさを確かめる（モデルに取り込んだ標本の概念の純度を記録する）。(b) 誤った再利用で、クラス別の損失なら区別できるかを、同じ記録の形で調べる。(c) k=0.7の規則を研究ツールの変種として実際に動かし、精度で確かめる。手元で試すなら(a)(b)が先（(c)は誤った再利用が増える分の影響が読めない）。

### 5. 固定の閾値を使わない判定の2案（2026-10-20、ユーザーの方針で再開）

ユーザーの方針: 「どの保有モデルを使うか」を固定の閾値で決めるのは手法として違和感がある。完全な上位互換にならなくても、固定の閾値でない方法で、同程度の精度・通信量を達成できれば意味がある（改善すれば最も良い）。

- 案A（累積の対数損失の比較）: 警報の区間で、履歴の基準を持つ各保有モデルの累積の対数損失と、「新しいモデル」の逐次（prequential）の累積の対数損失を比べ、最小のものを選ぶ。新しいモデルは、候補の初期値と同じ保有モデル（区間の平均損失が最小）から始め、区間を1標本ずつ、予測してから学習する（共有部は固定し、候補の学習と同じ損失・optimizerの設定で1標本ごとに1回更新）。学び始めの誤りの分が、新しいモデルを作ることの罰として働くので、閾値が要らない（MDL・ベイズ因子の考え方）。予測の側の専門家の重み付けと、同じ「予測の損失」の枠組みで帰属を説明できる。
- 案B（検出と同じ考え方の検定）: 各保有モデルについて「区間の平均損失≦履歴の基準」を検定し、棄却されなければ合うとする。

### 6. 案Bの見積り（判定だけ、2026-10-20、基準版9のコード、2500標本・10 client・seed 0〜2）

`results/fedsda-provisional-candidate-expert/20261020_reuse-test-diagnosis/`（`diagnose.py`、`diagnosis.json`、`replay.py`、`replay.txt`）。前回の診断の記録に、区間の標本ごとの損失と、モデルの損失の統計（件数・平均・偏差平方和）を足して記録した（24 runとも、精度は既定と完全に一致＝runを変えていない）。警報の区間の解決1,384回。合うモデルのうち区間の損失が最小のものを選ぶとして、判定し直した（判定の後の学習・帰属の変化は含まない）。

| 規則 | 正しい再利用 / 誤った再利用 / 正しい新規 / 見逃し | 判定の正しさ（30標本以下） |
|---|---|---|
| 今（0.1） | 58.1% / 17.5% / 11.5% / 12.9% | 69.6%（50.8%） |
| Hoeffding α=0.001 | 68.8% / 28.8% / 2.4% / 0.1% | 71.2%（63.1%） |
| 経験Bernstein α=0.001〜0.05 | 68.6% / 31.4% / 0.0% / 0.0% | 68.6%（55.6%） |
| Welch α=0.001 | 69.1% / 26.7% / 3.4% / 0.8% | 72.5%（65.1%） |
| Welch α=0.05 | 58.6% / 19.7% / 10.0% / 11.7% | 68.6%（52.8%） |
| e-過程 α=0.001 | 68.6% / 31.4% / 0.0% / 0.0% | 68.6%（55.6%） |
| Hoeffding α=0.05 | 69.3% / 26.4% / 3.8% / 0.5% | 73.0%（66.7%） |

- 「悪いと棄却できなければ合う」とする検定は、区間が短い（30標本以下）と許容が広く、ほとんど新しいモデルを作らなくなる（正しい新規11.5%→0〜4%）。見逃しは無くなるが、誤った再利用が17.5%→24〜31%に増える。誤った再利用は学習データを混ぜるので、判定の正しさの小さな改善（+0〜3pp）が精度の改善になる見込みは低い（精度は動かして確かめていない）。
- 今の規則に近い内訳になるのは、Welch α=0.05だけ（αという別の値の選び方に頼る）。
- 逆向き（「合うことを示せたら再利用する」同等性の検定）にすると、同等とみなす幅という、閾値に当たる値が要る。
- 判断（暫定）: 案Bは、閾値を無くす代わりに再利用へ大きく偏るので、今の形では採らない。
