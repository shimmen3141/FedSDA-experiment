# agrawal4・randomrbf4で誤警報制御値αを厳しくする（2026-11-21）

ユーザーの依頼（2026-11-21）: agrawal4・randomrbf4で、誤った警報を減らす設定を手元で小さく試す。
背景は[安定した期間の差の切り分け](stable-period-gap-recurring-synthetic-20261120.md)。そこでは「誤った警報が、学び途中のモデルを分断する」という説明を立てていた。この記録は、その説明を介入で確かめる。

## 条件
- 研究ツール`tools/research_false_alarm_control_alpha`（commit `531aacea`、基準版16、手元のWindows、14 workers）。損失の監視の誤警報制御値αだけを替える。e-SRの閾値はln(1/α)。製品の既定（α=0.001）は変えていない。
  - 設定は掃引の計画のときに組み立てられる。そのため、掃引のコマンドを呼ぶ間だけ定数を替える。runの記録の`e_sr_false_alarm_control_alpha`に、使った値が残ることを確かめた。
- 変種は`alpha-1e-4`（閾値9.2）と`alpha-1e-5`（閾値11.5）。2データ×間隔50・500×seed 0〜4×10 client×5000標本で、40 run・失敗0。
- 出力: `results/fedhasp-false-alarm-alpha-v16/20261121_agrawal4-randomrbf4-seeds0-4`。集計は同じ場所の`analysis_false_alarm_control_alpha.md`。
- 既定は`results/fedhasp-oracle-v16/20261120_recurring-synthetic-seeds0-4/product-default`を使う。手元の同じ基準版で、runの識別子が同じ。その後に製品のソースの変更は無い。
- FedDriftは、uraniumの手法比較のseed 0〜4（既定のδ0.10）を使う。

## まとめ（数値をそのまま述べる）
- 「誤った警報が、学び途中のモデルを分断する」という説明は、この2データでは支持されない。変化から離れた警報の大半は学習先を替えない。減らしても精度は変わらない。
- 真の概念で割り当てる版との差（間隔50で+1.7〜+3.4pp）が示す割り当ての誤りは、警報の数より、真の変化のときの行き先の選択（新しいモデルを作るか、どの保有モデルを再利用するか）にある可能性が高い。既定の新しいモデルの採用は10 clientの合計で12〜29（概念は4つ。サーバの統合の前の数）。ただし、標本ごとの学習先は記録に無く、行き先の正誤を直接は数えていない。
- 元のデータで変化の直後が下がらないかは、精度の改善が無いため確かめていない。

## 真の変化のときの行き先（2026-11-21、追加のrunなし、ユーザーの依頼）
研究ツール`tools/research_false_alarm_control_alpha/assignment_destinations.py`で、保存済みのrunから標本ごとの学習先を組み立てた（組み立て方と近似はscriptの冒頭）。
- 各モデルの系統（統合で吸収されたものは代表へたどる）に、そこで学んだ標本の真の概念の多数派を概念として付ける。学習先の系統の概念が真の概念と違う標本を「割り当ての誤り」とする。
- 検算: 真の概念で割り当てる版では、全条件で誤りが0.00%、初出の変化は全て新しいモデル、再来は全て正しい再利用になる。番号の対応を登録の順番だけで付けた最初の版では、この版の間隔500でも誤りが6%残った。そのため、次の切り替えの記録の番号を使う形に直した。
- 近似: 帰属保留のFIFOによる学習の遅れは無視した。系統の概念は多数派なので、2つの概念が混ざった系統では少数派の側だけが誤りに数えられる（誤りの下限に近い）。

- agrawal4・randomrbf4での割り当ての誤りは、主に、真の変化のときに新しい概念を既存のモデルへ入れることから来る（初出で多い）。警報の数からは来ていない。
