## 内容

旧は、候補検証の間、警報時点の既存モデルの複製（shadow）にも候補と同じ学習を適用し、検証の最後に候補とshadowを比べ、shadowが勝てばそのパラメータを元のモデルへ書き戻す方針を持つ。最終構成（`forward_persistent`）はこの経路を通らず、参照は警報時点のパラメータで固定する。goldenにもこの方針の値はない。

## 新実装の現状

新の候補検証（参照の固定、標本の観測、採否の評価、確定）は固定参照だけを扱う。候補検証の結果の値に、shadowの勝ちに当たるものはない。

## 後で移植する場合

参照の学習、shadowの書き戻し、結果の値の追加、実旧との対照、基準（golden）の作成が要る。固定参照の部品の契約（参照は読取りだけ）が変わるので、別specで扱う。

確認していないこと: 過去の実験成果にこの方針のrunがあるかどうか、旧の他の作成方針（`immediate`、`validated`）の移植の要否（最終構成では通らない。判断は未記録）。
