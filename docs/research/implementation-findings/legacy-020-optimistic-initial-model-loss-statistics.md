# LEGACY-020: 初期モデルの損失の統計が、学習に使った標本で取られ、最初の概念の間に誤警報を生む

- 発見日: 2026-10-21。対象: `src/federated_learning_experiments/runtime/initial_model_pretraining.py`の`pretrain_initial_model`（旧の事前学習と同じ扱いを移植したもの）。発見の経緯: 基準版10（最小記述長の選択）で、MNISTの警報が約2倍に増えた原因の調査（[設計の14](../fedsda-unified-concept-assignment-inference.md)）。
- 種別: 旧から引き継いだ扱いの不具合に近い事項（初期モデルだけで起きる）。状態: 検証中（2026-10-21、ユーザーの指示で手元の比較を始めた。下の「手元の比較」）。

## 内容

初期モデルは、runの最初に、概念0の標本（最終構成の既定で500標本、10 epoch）で学習する。その後、損失の統計を、**学習に使った同じ標本**で、1件ずつ評価して取る（`pretrain_initial_model`の(4)）。学習した標本の上の損失なので、統計は楽観的になる。MNIST2では、統計の平均が約0.018で、流れの新しい標本での損失（約0.23）の約10分の1だった。

検出器は、現在のモデルの統計の平均を基準にして損失の増加を監視し、警報の後もその平均を基準にやり直す。初期モデルが現在のモデルの間は、基準が実際の水準より低いので、流れの標本が統計に十分たまるまで（MNIST2・間隔100で最初の約1000標本）、10〜20標本ごとに誤警報が出る。

- 基準版9までの扱い（平均損失の許容量γ=0.1による再利用の判定）では、最初の警報（標本6前後）で、初期モデルが「合わない」と判定され、同じ概念の新しいモデルを作るので、新しいモデルの統計に置き換わり、誤警報が止まる。その代わり、余分なモデルの登録・統合が起きる。
- 基準版10（最小記述長の選択）では、毎回、正しく「現在のモデルのまま」を選ぶので、誤警報が続く（240 runの合計で、「現在のモデルのまま」の選択が21,845回）。

## 影響

- 精度は下がらない（基準版10の本規模で、MNIST2の全間隔で基準版9より高い）。
- 警報の精度の指標が下がる（MNIST2・間隔100で0.64→0.31）。誤警報ごとに、最小記述長の選択の計算が走る（計算回数の指標に含まれる。小さいrunの実測で、学習の約1%、推論の約10%）。
- 基準版9までは、最初の警報で余分な新しいモデルを作る原因でもあった。

## 直す方法の案

- (b) 初期モデルの統計を、学習に使っていない標本の損失で取る（例: 事前学習の標本の一部を評価用に取り分ける、または、流れの最初の標本の予測的な損失から取る）。全部の構成の初期の動作が変わるので、基準版を上げる。
- 「現在のモデルのまま」の後に検出器の基準を選択の列での損失に合わせ直す案は、手元で試したが、本当の変化への感度が落ち、精度が下がった（[設計の16](../fedsda-unified-concept-assignment-inference.md)）。

## 初期モデル以外での同じ問題の有無（2026-10-22、基準版10の本規模のraw）

損失の統計は、次の3つの場面で作られる。

- 初期モデル: 事前学習に使った500標本で、学習の後に評価する（楽観的。この記録の問題）。
- 採用した候補: 候補を学習した警報の区間の標本（最大31標本）で、学習の後に評価する（`runtime/alarm_change_interval_resolution.py`→`adopted_candidate_initial_local_registration.py`。同じく学習に使った標本）。
- 流れの途中の取込み: 帰属の保留から現在のモデルへ取り込む標本を、取り込む前（まだ学習していない）に評価する（`assigned_training_sample_absorption.py`。予測的な損失で、楽観的でない）。

## FedDriftとの公平さ（2026-10-22）

- 新実装のFedDrift（`methods/feddrift/detection_batch_assessment.py`）は、検出に、初期モデルの損失の統計を使わない。検出のバッチごとに、全部の保有モデルの平均損失の最小を、前のバッチの最小（学習の前に評価した予測的な値）＋閾値と比べる。最初のバッチは前の値が無いので、検出しない。したがって、この記録の誤警報は、FedDriftでは起きない。初期モデルの統計は、FedDriftでは統合の損失の統計（件数で重み付けした平均）にだけ使われる。
- 公式のFedDriftの実装（`FedDrift/`に置いた公式レポジトリ、`fedml_experiments/distributed/fedavg_cont_ens/main_fedavg.py`と`fedml_api/distributed/fedavg_ens/FedAvgEnsAggregatorSoftCluster.py`・`FedAvgEnsDataLoader.py`）は、事前学習をしない。最初の時刻（`curr_train_iteration == 0`）に、モデルを乱数で初期化し（`torch.manual_seed`）、全部のclientを1つのモデルに割り当てて（`cluster_init`）、その時刻のclientの標本でFedAvgで学習する。検出の基準（`mmacc_acc_dict`）は、最初の時刻の**学習の前に**、乱数で初期化したモデルの、その時刻の標本での正解率で初期化し、以後の時刻では、各時刻の学習の前に、新しい時刻の標本での最良のモデルの正解率で置き換える。正解率が基準−δより下がれば、ドリフトとする。基準は、いつも学習の前の予測的な値。
- 新実装の実験では、比べる方式の全部（FedSDA・FedDrift・FedAvg）が、同じ事前学習の初期モデル（概念0の500標本）から始める（`pretrain_initial_model`を共有する）。これは公式のFedDriftとは違う、実験の枠組みの選択。
