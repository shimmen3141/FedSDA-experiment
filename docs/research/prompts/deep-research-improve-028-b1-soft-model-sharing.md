## 1. 背景（私たちの手法の現状）

私たちは、ストリームの連合学習で概念ドリフトに適応する手法（作業名FedSDA）を研究しています。

- 設定: 10程度のclientが、それぞれ1標本ずつラベル付きのストリームを観測する（予測してからラベルを見る、prequentialな評価）。概念（入力からラベルへの関係）は、client・時刻ごとに切り替わり、過去の概念が再来する。真の概念IDは手法に与えない。サーバは一定の標本数ごとに同期する。
- モデル: サーバは、概念ごとに1つのグローバルモデルを持つ（複数）。モデルは、全モデルで共通の共有部（バックボーン）と、モデルごとの概念固有部（residual adapterと出力層）から成る。
- client: 損失の逐次の検定（e-値による変化検出）で概念の変化を検出し、最小記述長（予測的な符号長）の比較で、標本を「今のモデル／保有する別のモデル／新しいモデル」のどれに帰属させるかを決め、帰属したモデルを学習する。予測は、保有する全モデルの確率を、累積の損失から作る指数の重み（Fixed-Share）で混ぜて行う（帰属と予測を分離する設計）。
- サーバの集約: モデルごとに、そのモデルを学習したclientのパラメータを件数で重み付けして平均する。そのうえで、モデルの対をクロス評価（相手の標本での正誤・損失）し、判定の値が固定の閾値以下ならクラスタにまとめ、パラメータを平均して1つのモデルへ統合する（取り消せない二択）。

## 2. 解きたい問題（実験で分かったこと）

- 統合の判定は、少ない標本（対で約100〜150件）で、登録の直後に1回だけ行われ、二択で取り消せない。「同じである証拠」を求めると同じ概念の重複が残り（データが分かれて精度が下がる）、「違う証拠」を求めると違う概念が統合される（ある概念の精度が数pp下がる）。
- clientの利用の実績（clientが予測のために毎標本計算している、各保有モデルの予測の前の対数損失）から、モデルの対ごとの累積の差を作ると、標本が多く、時間とともに違う概念を区別できるデータもある。ただし、若いモデル（学び始め）と成熟したモデルの違いが、概念の違いと混ざる。また、機能的にほとんど区別できない概念の対（1標本あたり0.01〜0.03 natsの差）もある。
- どちらとも言えない対が多いので、二択ではなく、部分的に共有する方が、誤りの損が小さいのではないかと考えた。

## 3. 調べてほしい手法案（案B1）

モデルmの概念固有部を集約するときに、他のモデルkの集約の和も、重み π(m←k) で借りる:

θ̃_m = (S_m + Σ_{k≠m} π(m←k) S_k) / (N_m + Σ_{k≠m} π(m←k) N_k)

（S_k・N_kは、そのラウンドのモデルkの件数で重み付けしたパラメータの和と件数。π(m←m)=1。共有部は従来どおり全モデルで1つ）

- 重み: π(m←k) = 1 / (1 + exp(D_m(k) − ln 2))。D_m(k)は、mを学習していたclientの標本（mの標本）で、kで予測したときの対数損失と、mで予測したときの対数損失の差の累積（どちらも学習前の予測なので予測的）。「kがmの標本をmと同じくらい説明できるなら、mはkから借りる」。2つの仮説（mの標本はkで足りる／mが要る）の符号長の差に、モデル1つ分の事前の差ln 2を置いたベイズのモデル平均の重みで、clientのFixed-Shareの指数の重みと同じ形。
- 非対称: 若い重複モデルは成熟したモデルから多く借り、成熟したモデルは若いモデルからほとんど借りない。違う概念の若いモデルは、学ぶにつれて借りなくなる。
- 証拠の集め方: clientが、保有モデルの対ごとに損失の差の累積（件数・和・2乗和）を持ち、同期で報告する（計算の追加はなく、通信はモデル数の2乗個の数値）。
- 案B2（後段）: 両方向の重みが十分に1に近い対だけを実際に統合し（通信を減らす）、それ以外は共有する。固定の閾値によるクロス評価の判定を外す。
- 狙い: clientの予測の重みと、サーバの共有の重みを、同じ種類の量（予測的な符号長の累積）から作り、手法の軸をそろえる。

## 4. 調べてほしいこと（優先順）

### 4.1 連合学習での、モデル・クラスタの間の重み付きの集約（最重要）

次のような手法を、一次資料（論文本文、著者のコード）で確かめ、私たちの案との異同を整理してください。以下は候補の例で、網羅ではありません。ほかに近いものがあれば加えてください。

- client間の類似度で重み付けして集約する個別化の連合学習（例: FedAMP（attentive message passing）、FedFomo（他のclientのモデルを自分の検証データでの損失から重み付けする）、APPLE、FedALA、pFedGraph、その他のgraph・attention型の集約）
- clientを複数のクラスタ（モデル）へ軟らかく割り当てる手法（例: FedSoft、soft clustered FL、FedEM（混合分布の連合学習）、FedRC、IFCA・CFLなど硬いクラスタリングとの対比）
- 多タスクの連合学習（例: MOCHA、Ditto、正則化で個別モデルを共通モデルへ引き寄せる形）
- 連合の概念ドリフトの手法で、概念・クラスタの統合や共有をどう扱うか（例: FedDrift（クラスタの統合）、Flash、FedCCFA（クラス単位の分類器のクラスタリング）、FedDAA、FedDCA、FL-HVD、その他2023〜2026年の手法）

それぞれについて知りたいこと:
1. 混ぜる単位（client／クラスタ／概念のモデル／層）
2. 重みの根拠（パラメータの距離、勾配の類似度、検証データの損失、事後確率、学習した注意など）と、対称か非対称か
3. 重みが時間とともに積み上がる証拠（累積・割引）を使うか、その時点の値か
4. 概念ドリフト・概念の再来への対応の有無
5. 統合（モデルを減らす）と共有（モデルを残して混ぜる）の関係
6. 理論的な保証の有無と内容
7. 通信の費用

### 4.2 連合学習以外の関連（理論と設計の根拠）

- 多タスク学習の縮小推定・階層ベイズ（似たタスクのパラメータを共通の平均や互いへ引き寄せる。James-Stein型、タスクのクラスタリング、負の転移の扱い）
- ベイズのモデル平均・予測的MDL（prequential MDL）によるモデル比較と、その重みでパラメータを混ぜることの妥当性
- オンライン学習の専門家の助言（Fixed-Share、指数の重み）を、予測ではなくパラメータの共有・集約へ使った例
- 継続学習・モデルの統合（model merging、weight averaging、task arithmetic）で、混ぜる重みを損失や証拠から決める例
- 2つのモデルが同じ分布から来たかの逐次の検定（e-process・anytime-validな検定）を、統合や共有の判断に使った例

### 4.3 リスク・懸念（知りたい）

- **正のフィードバック**: 共有するとモデルが似て、「同じ」と見える証拠が増え、さらに共有が進んで、違う概念が1つへ潰れる（モデルの崩壊）。連合のクラスタリングや多タスク学習で、この現象と対策（重みの上限、温度、証拠を共有の前のモデルで測る、など）は知られているか。
- 負の転移（違う概念から借りることの損）の大きさの評価法。
- 非対称の重みで、成熟したモデルが若いモデルに引きずられない設計の先例。
- 累積の証拠を、概念の変化・再来の下でどう割り引くか。

### 4.4 新規性のリスクの評価

案B1の要素ごとに、既知か、新規性があり得るかを、根拠の文献とともに評価してください。

- (a) 連合学習で、モデルの間をclient単位ではなく「概念のモデル」単位で、連続的に共有する
- (b) 共有の重みを、clientの予測的な符号長（予測の前の対数損失）の累積の差から、ベイズのモデル平均の形で作る
- (c) 重みを非対称（借りる側の標本で測る）にして、学習の進み具合の違いの混同を避ける
- (d) clientの予測の重み（Fixed-Share）とサーバの共有の重みを、同じ量から作り、帰属と予測の分離の設計と合わせる
- (e) 共有の重みの極限として統合を位置づけ、固定の閾値の判定を置き換える（案B2）

「史上初」とは書かず、「we are not aware of prior work that ...」と言える範囲かどうかで評価してください。
