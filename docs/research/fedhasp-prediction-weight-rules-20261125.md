# モデルの混合の重みの規則の改良（2026-11-25）

ユーザーの依頼「順番にやってください」（理論の改良の余地の3案）の記録。製品のコードは変えていない。理論の側は[付録の下書き](theory-appendix-draft-20261124.md)。

## 1. 重みの規則の変種（研究ツール、uranium の結果待ち）

研究ツール[`tools/research_prediction_weight_rules`](../../tools/research_prediction_weight_rules/README.md)（commit `0cce0e8c`）。基準版16の既定 `fedsda` の、モデルの混合の重み（Fixed Share）の更新だけを、workerの中で差し替える。

- `log-loss-weights`: 重みの更新を log loss（−ln p_y、p_y = 1 − ℓ、下限 1e−12）・学習率1（ベイズの更新）にする。log loss は混ぜられる損失なので、比べる列に対する後悔が ln N ＋ 切り替えの費用の形になり、今の √(C·L) の程度（定理9の系9a）より強い。
- `alarm-share-boost`: そのclientの警報の後の1回の更新だけ、共有率を 1/T から 0.25 に上げる（集約の後の再生の中では使わない）。時間で変わる共有率の Fixed Share で、切り替えの費用を本当の切り替えの所だけ小さくする。
- `log-loss-weights-alarm-share-boost`: 両方。`product-default` は差し替えない対照。

手元の smoke（sea4・sine2、600標本、間隔50、seed 0、4変種×2 run）は失敗0で、予測と重みの診断を除く全列（通信量、計算量、検出・適応、モデルの数）と概念の変化が、3変種とも既定と全対で一致した（学習が同じ）。精度の差は sine2 で log loss の側が +0.067pp（変化の後100標本で +2.5pp）、共有率の側だけは −0.017pp（1 run の smoke なので判断に使わない）。

uranium の 800 run（10データ×間隔50・500×seed 0〜9×4変種、5000標本）のコマンドはツールのREADME。結果が届いたら `analyze.py` で、学習が同じことの確認、精度の差（全体・変化の後・それ以外・概念別）、通信量・MAC、経過時間の比を出す。

## 2. 既存の結果の、変化からの経過での切り分け（再実験なし）

基準版16の既定の 400 run（6データは `fedsda-component-ablation-v16/20261029_231413_core-components-v16-seeds0-9/fedsda`、4データは `fedsda-every-sample-change-interval-search/20261029_172159_new-datasets-seeds0-9`。[一致の確認](fedsda-component-ablation-v16-20261030.md)）の標本ごとの正誤を、各clientの直前の概念の変化からの経過で分けた。研究ツールの `selection_versus_mixture.py`、出力は `results/fedhasp-prediction-weight-rules/analysis_existing_v16_selection_versus_mixture.md`。

比べたのは、どれも同じ run・同じ標本・同じ同期の版のモデルで、重みが最大の1モデル（最大重み）、Fixed Share の重みでの混合（FS）、AdaHedge の重みでの混合（診断）と、実際の予測（同期の版と手元の版を混ぜたもの）。

|---|---|---|---|---|---|
| 最初の変化の前 | 18.1% | 89.07 | +0.010 | −0.000 | +0.001 |
| 変化から 0〜50 | 4.8% | 82.29 | **+0.270** | **−2.933** | −0.155 |
| 50〜100 | 4.7% | 88.85 | −0.011 | −0.523 | +0.243 |
| 100〜200 | 9.3% | 89.55 | +0.008 | −0.005 | +0.807 |
| 200〜500 | 24.3% | 90.64 | +0.012 | +0.019 | +0.811 |

保有モデルが2つ以上の標本だけでも同じ形（0〜50で FS − 最大重み +0.302、AdaHedge − FS −3.111）。

- **柔らかく混ぜる利得（FS − 最大重み）は、変化の直後の50標本にほぼ限られる**（+0.27pp。間隔50〜500で +0.23〜+0.32、rotmnist2・4 では +1.0 前後、sine2 だけ −0.38）。それ以外の期間はほぼ0。理論の見通し（混合は割り当ての遅れ・誤りを補う保険で、割り当てが正しく落ち着けば固い予測と同じ）と合う。
- **重みを移す速さが大きく効く**。同じモデルで AdaHedge（共有なしで学習率が下がっていく）の重みにすると、変化の直後の50標本で −2.9pp（MNIST系で −4.7〜−6.0）、50〜100でも −0.5pp。重みの規則で差が出るのは変化の直後で、節1の変種（特に警報で共有率を上げる案）が狙う所と一致する。
- **版の混合（実際 − FS）は変化の直後だけ負**（−0.16pp）で、100標本以降は +0.8pp。手元の版は変化の直後には古い概念へ学習が進んでいない／誤った割り当てで学習した分だけ不利で、落ち着いた後は同期の版との平均の利得が出る（[同期の版の比較](synchronized-prediction-v16-20261124.md)の、間隔500で混合が同期の版を +1.05pp 上回る結果と合う）。

標準指標: 再実験をしていないので、通信量・計算量・経過時間は元の run のまま（比べた4つの予測は同じ run の中の同じモデルの確率から作るので、学習・通信は共通）。診断の予測の組み立ての計算は、計算量の計数（MAC）に含まれていない。

## 3. 切り替えの事前分布と、モデルの集合が変わるときの扱いの設計（未実装）

節2で、重みの規則の差が出るのは変化の直後の数十標本だと分かった。そこで効く案を、理論の扱いやすさと、過去の試みとの関係で整理する。

1. **新しいモデルが入るときに重みを一様へ戻さない（眠る専門家・specialists）**。今はモデルの集合が変わるたびに重みと分散を一様・0へ戻し（定理10(b)の再出発の費用 ln N）、集約の後は保留の損失を再生する（ln N ＋ ln T）。代わりに、入ってきたモデルに初めの重み α_new を与えて他を (1 − α_new) 倍し、統合で消えたモデルの重みはその代表へ足す（統合の対応は既にある）。理論は specialists の枠組み（Freund, Schapire, Singer & Warmuth 1997、Chernov & Vovk 2009）で、再出発の費用が「新しいモデル1つにつき ln(1/α_new)、統合は0」に置き換わる見込み。E1a は配り直しの先を変えたが、集合が変わったときの初めの重みは一様のまま（E1b は未試行）で、この案とは別。
2. **連合で学ぶ切り替えの行列**。Fixed Share の共有を、一様ではなく遷移の行列 Q で行う（w ← (1−α)·事後 ＋ α·Qᵀ事後。隠れマルコフの前向きの計算と同じ）。Q はサーバが各clientの割り当ての切り替え（どのモデルからどのモデルへ）を数えて配る。他のclientが経験した概念の再来の順序を、データを共有せずに使える（連合学習ならではの利点で、[付録の仮定(O)](theory-appendix-draft-20261124.md)の議論と同じ向き）。理論は一般の遷移の Fixed Share（Herbster & Warmuth 1998 の拡張、Koolen & de Rooij の切り替えの事前分布）で、切り替えの費用が −ln Q(i→j) になる。通信は N×N の小さな行列。
3. **Mixing Past Posteriors（過去の事後へ配り直す）** は E1a で試し、6条件中5条件で平均が下がり採用しなかった（[記録](fedsda-mixing-past-posteriors-e1a-20261024.md)）。節2の結果（重みの差は変化の直後に集中し、その時点で必要なのは重みを速く移すこと）からは、過去の事後への配り直しは、新しい概念への移行を遅らせる向きに働きうるので、低下と矛盾しない（原因の診断は未実施）。再び試すなら、案2の遷移の行列で「再来の所だけ」過去のモデルへ配る形にする。

順番の提案: 節1の uranium の結果を見てから決める。警報で共有率を上げる案が変化の直後で効けば、速く移すことが鍵だという見通しが強まり、次は案1（集合の変化の扱い）を研究ツールで試す。効かなければ、重みの規則より割り当て（警報の遅れ・誤り）の側が直後の損失を決めていると考え、重みの改良はここで区切る。案2 は理論の新しさがあるが実装の量が多いので、その後に回す。

## 4. 節1の uranium の結果（2026-11-25 追記）

結果は `results/fedhasp-prediction-weight-rules/20261125_094022_all-datasets-intervals50-500-seeds0-9`（commit `39b468c8`、基準版16、4変種×200 run、失敗0）。分析は同じディレクトリの `analysis_prediction_weight_rules.md`（`analyze.py`）と、変種ごとの節2の切り分け `analysis_selection_versus_mixture_<変種>.md`。

学習が同じこと: 3変種とも、予測と重みの診断を除く全列（上り・下りの通信量、client・サーバの MAC、検出・適応、モデルの数）と概念の変化が、既定と全200対で一致した。

変種 − 既定（pp、条件（10データ×2間隔）の等重みの平均）:

| 変種 | 全体 | 変化後100標本 | それ以外 | 全体が正の条件 | 全体の正解数の差が正/負/0の run の対 |
|---|---|---|---|---|---|
| `log-loss-weights` | **+0.214** | **+1.980** | +0.029 | 19/20 | 178/18/4 |
| `alarm-share-boost` | −0.000 | +0.017 | −0.002 | 13/20 | 76/80/44 |
| 両方 | +0.212 | +1.973 | +0.028 | 19/20 | 176/21/3 |

概念の変化からの経過で分けた差（pp、同じ平均）:

| 変種 | 初期 | 0〜50 | 50〜100 | 100〜200 | 200〜500 | 500以上 |
|---|---|---|---|---|---|---|
| `log-loss-weights` | −0.016 | **+3.876** | +0.063 | +0.132 | +0.054 | +0.012 |
| `alarm-share-boost` | −0.000 | +0.033 | +0.000 | −0.004 | −0.002 | −0.002 |

- **log loss の更新は、変化の直後の50標本で +3.9pp**（Fixed Share の混合の正解率は 81.79 → 85.65）。全体の差が負なのは sea2・間隔50 の1条件だけ（−0.005pp）。それ以外の期間で下がる条件は rotmnist4（間隔50 −0.11、間隔500 −0.17）・rotmnist2 間隔50（−0.09）・mnist 系 間隔50（−0.03〜−0.04）で、どれも変化の直後の利得より小さい。重みの1位の入れ替わりは17/20条件で増え（+13〜+418回。circle2・fmnist2・fmnist4 の間隔50 では −26〜−106回）、有効なモデルの数は19/20条件で減る（最大 −0.24。sea2 間隔500 だけ +0.006）。重みを鋭く、速く移す規則。
- **警報で共有率を上げる案は効かない**（全体 −0.000pp、正負がほぼ半々）。共有率を上げた回数は警報の数とほぼ同じ（sea2 は保有1つの警報が多く、回数が少ない）。log loss と組み合わせても log loss 単独と同じかわずかに下。一様へ 25% 配り直しても、その後の更新の学習率が小さいままでは重みが移らない、log loss では元から速く移るので配り直しが要らない、と読める（直接の切り分けはしていない）。
- **log loss でも、版の混合（実際 − FS）は変化の直後の0〜50で負のまま**（既定 −0.187、log loss −0.167）。log loss の変種では「FS − 最大重み」が 0〜50 で +0.27 → +0.13 に縮み、重みが1つのモデルへ早く集まる。
- 学習率の扱いとの交絡: 製品の学習率は min(1, √(2 ln N / V))（V は重みつきの損失の分散の累積、モデルの集合が変わると0に戻る）で、run が長いと1より小さくなる。`log-loss-weights` は損失の形（−ln p_y）と学習率1の両方を変えているので、利得が「混ぜられる損失」から来るのか「学習率が下がらないこと」から来るのかは分けられていない。対照 `bounded-loss-unit-learning-rate`（損失は製品のまま、学習率だけ1）を研究ツールに足した。600標本の smoke（sine2・sea4、seed 0）では既定と全列が完全に一致した（短い run では製品の学習率も上限の1のまま。研究ツールの更新の複製が製品と同じ値を出すことの確認にもなる）。

標準指標: 精度は上の表。上り・下りの通信量と MAC は全対で既定と同じ（例: mnist4 間隔50 で上り 5.35e9・下り 5.57e9 byte、client MAC 1.07e13、server MAC 1.34e9。条件ごとの値は分析の表）。重みの計算の追加の費用は MAC の計数に入らない（モデルの数 N に比例する数回の演算／標本）。経過時間は run ごとには記録が無い（掃引の表示の `(<秒>s)` は掃引の開始からの累積で、run の時間ではない。分析の初版はこれを run の時間として比を出していたので直した）。変種ごとの掃引の開始〜終了は 59.4〜59.7 分（どれも 120 workers・同じ200 run）で、差は無い。

判断と次の順番:
1. 節3の案のうち、警報で共有率を上げる案は捨てる。案1（集合が変わるときに一様へ戻さない）と案2（連合で学ぶ切り替えの行列）は、変化の直後の差の大部分を log loss が取った後に残る余地が小さい見込みなので、log loss を固めた後に、その上で必要かを見る。MPP は再び試さない。
2. 次は対照 `bounded-loss-unit-learning-rate` の200 run（uranium、既存の出力先に足す）。結果で、(a) 学習率1だけで同じ利得 → 製品の学習率の下がり方が原因（理論は付録の定理9の学習率の扱いの見直し）、(b) 学習率1では利得が小さい → log loss（混ぜられる損失）が原因（理論は Fixed Share の log loss の後悔 ln N ＋ 切り替えの費用を付録へ足す）、を分ける。
3. どちらでも、製品へ入れるなら cc-sdd の spec で基準版17として行う（重みの規則が変わるので golden が変わる）。

## 5. 対照 `bounded-loss-unit-learning-rate` の結果（2026-11-25 追記）

結果は同じ出力先の `bounded-loss-unit-learning-rate/`（commit `4da8f460`、基準版16、200 run、失敗0、59.4 分）。分析は `analysis_prediction_weight_rules.md`（5変種で作り直した）と `analysis_selection_versus_mixture_bounded-loss-unit-learning-rate.md`。ユーザーが出力先の全体を uranium から送り直したので、節4でまとめた後のトレースのファイル（4変種×200）が戻っていた。まとめたファイルと全件一致することを確かめてから `traces.py` で消した。結果の README も送り直しで上書きされていたので、結論の参照を書き直した。

学習が同じこと: 予測と重みの診断を除く全列と概念の変化が、既定と全200対で一致した。

| 変種 − 既定（pp） | 全体 | 変化後100標本 | それ以外 | 変化から0〜50 | 全体が正の条件 | 正/負/0のrunの対 |
|---|---|---|---|---|---|---|
| `bounded-loss-unit-learning-rate` | +0.009 | +0.108 | −0.002 | +0.214 | 10/20 | 76/23/101 |
| `log-loss-weights`（節4） | +0.214 | +1.980 | +0.029 | +3.876 | 19/20 | 178/18/4 |

- **利得のほぼ全部は損失の形（log loss）から来る。** 学習率だけ1にした対照は、変化の直後の0〜50で log loss の利得の約6%（+0.21 対 +3.88pp）。
- 間隔50では、対照は10条件とも既定とほぼ同じ（差 |·| ≤ 0.001pp、101対は正解数が完全に同じ）。集約のたびにモデルの集合が変わって重みと分散 V が戻るので、製品の学習率が上限の1のままの時間が長いためと読める（V の値は記録していないので直接は確かめていない）。対照の利得は間隔500にだけ出る（SEA2・SEA4 を除く8条件で全体 +0.006〜+0.042pp、変化後 +0.06〜+0.48pp。SEA2 −0.001、SEA4 −0.011）。
- 読み: 有界の損失 1 − p_y は、学習率1でも1標本で重みの比を最大 e 倍しか変えない。log loss はモデルの確率の比 p_i/p_j で重みを変えるので、変化の後に自信を持って外すモデルの重みが1標本で大きく下がる。これは log loss のベイズの更新（混ぜられる損失、学習率1）の性質そのもので、節1で理論から出した理由と合う。理論の上界の比較（√ の形 対 ln N ＋ 切り替えの費用）だけでは実際の差を言えないので、この対照で実験として裏付けた。
- 標準指標: 上り・下りの通信量と MAC は全対で既定と同じ（節4と同じ値）。掃引の経過時間は 59.4 分（既定 59.5 分、同じ120 workers）。

判断:
1. 重みの更新は log loss（学習率1）が有望。理論では、付録の定理9の学習率の扱いを見直すのではなく、log loss の Fixed Share の後悔の定理と誤りの回数の系を足す方針にする。
2. ここまでの結果は製品の既定（e-SR の検出、MDL の割り当て、共有部・adapter あり）の上のもの。ユーザーの指摘によれば、担当教授の指摘を受けて、より単純な構成（共有部・adapter・MDL などを外した形。[積み上げの記録](core-component-ladder-v16-20261119.md)の節3の最小形）で実験し直す方針になっている。そのため、最小形の柔らかい予測（`minimal-soft-prediction`）の上でも、同じ重みの規則の比較を流す。

- 学習が同じことの確認: 200対で不一致0。上り・下りの通信量と MAC は既定と同じ。
- 精度（条件の等重みの平均）: 既定 88.610 → log loss 88.875（+0.265pp）。変化の後100標本 +3.98pp、それ以外 −0.12pp。全体が正の条件 14/20、run の対は正120・負54・0が26。
- 経過からの期間別の差: 初期 −0.03、0〜50 **+7.51**、50〜100 +0.41、100〜200 −0.11、200〜500 −0.19、500以上 −0.13pp。製品の既定の上（節4）より変化の直後の利得は大きい（+3.88 → +7.51）が、安定した期間に小さな損が出る（製品の上では、それ以外 +0.03pp）。
- 条件別: SINE2（+0.95〜+1.14）、CIRCLE2（+0.62〜+0.97）、ROTMNIST2（+0.33〜+0.57）は大きく正。SEA2・SEA4 はほぼ0。MNIST・FMNIST の間隔500と FMNIST4 の間隔50は負（−0.01〜−0.22）。負の条件は、どれも「それ以外」が −0.14〜−0.43pp で、変化の後の利得を食っている。
- 診断: log loss で1位の入替が画像のデータで1 run あたり +240〜+893 回増え、有効モデル数が −0.10〜−0.42 減る（SINE2・CIRCLE2 は入替が減るか少し増えるだけ）。保有2以上・500以上の期間では、診断の AdaHedge の混合が log loss の FS を +0.29pp 上回る（既定の重みでは −0.33pp）。
- 読み（仮説、直接は確かめていない）: 学習率1の log loss（ベイズの更新）は、同じくらいの質のモデルの間で、神経網の確率の比の揺れをそのまま重みに映すので、安定した期間に重みが1つのモデルに寄って入れ替わり、混ぜることの利得を失う。定理16の保証は「1つのモデルを選ぶ列」との比較なので、この損とは矛盾しない。モデルごとの確率は記録していないので、再実験なしの切り分けはできない。
- 警報の数の列は、トレースが e-SR の警報の記録だけを数えるため、最小形（ADWIN）では0になる（未測定）。検出の数は `run_summary.csv` で1 run あたり平均 25.0 回（両変種で同じ）。
- 経過時間: run ごとは記録なし。掃引の開始〜終了は既定 97.7 分、log loss 96.2 分（同じ120 workers）。

判断: 変化の直後の利得は最小形でも出る（理論の定理16・A.20 と合う）。安定した期間の損を除けるかを、学習率を下げた log loss（η < 1）と、学習率の候補をベイズで混ぜる変種で確かめるのが次の候補。

## 8. 安定した期間の損を除く変種と、確率の記録（2026-11-25 追記、uranium の結果待ち）

ユーザーの依頼（「すべてやりたい」、記録の有無の問いに「1と合わせて」）。節7の仮説（学習率1の log loss が重みを1つのモデルへ寄せすぎる）を確かめ、変化の直後の利得を保ったまま安定した期間の損を消せるかを見る。

- 変種（研究ツール、最小形の基点、節7と同じ出力先へ足す）:
  - `tempered-log-loss-weights-0.5`・`-0.25`: log loss の学習率を下げる（付録の定理18、費用 C_α(S)/η）。
  - `learning-rate-mixture-log-loss-weights`: 学習率 1・1/2・1/4 の層を、上の層の log loss の Fixed Share で混ぜる（付録の定理19。学習率を警報や手作りの条件なしに選ぶ）。
  - `log-loss-weights-log-loss-version-mixture`: 版の混合の重みも log loss・学習率1にする（節7の実際 − FS が変化の後の0〜50で −0.23pp だった点への対応）。
- 確率の記録（`--record-prediction-probabilities-for tempered-log-loss-weights-0.5`）: 重みの制御への呼出しの列と、予測ごとの同期の版のモデル別の確率を記録し、`replay.py` で別の重みの規則の混合FS の精度・log loss を再実験なしに計算し直す。どの変種も学習は同じ（対の確認）なので、1つの変種の記録から全ての規則を計算できる。同じ出力先の実際の run（`product-default`・`log-loss-weights`・新しい変種）との正誤の一致で、計算し直しの正しさを確かめる。版の混合は計算し直さない（手元の版の確率は記録しない）。
- 手元の試運転（sine2・sea4・mnist4、間隔50、seed 0、600標本、6変種）: 失敗0。学習は全対で既定と同じ。記録から計算し直した混合FS の正誤は、実際の run がある5つの規則（既定、log loss、学習率0.5・0.25、学習率の混合）で全18000予測が一致し、記録した重みとの差は0だった。記録の大きさは、mnist4 の600標本で 0.58MB（5000標本の本番で全体約750MBの見込み）。
- 付録の追加（[付録の下書き](theory-appendix-draft-20261124.md)の追加の節その4）: 定理18（η ≤ 1）、定理19（二段の混合）、命題20（区間の後悔、変化の直後の回復の速さ）、A.27（保証が「1つを選ぶ列」と比べるもので、混ぜることの利得は外にあること）。研究ツールの更新での数値の確認つき。
- uranium は4変種×200 run（約6.5時間、120 workers）。コマンドは研究ツールの README。
