# FedHASPを基盤から1段ずつ積む（基準版16、2026-11-19、主担当）

- 問い（ユーザー）: 手法が複雑で本質が分かりにくいという指摘が多い。標本を1件ずつ処理しFIFOで保持する基盤に絞ると、精度はどこから来るか。
- 基盤の定義（主担当の提案、2026-11-19）: 標本を1件ずつ予測→損失の監視→帰属の保留（FIFO）→警報でMDLにより留まる・再利用・新しいモデルを選ぶ→固い割り当てで学習。サーバはモデルIDごとに集約し、統合する。その上に「予測の上乗せ」（Fixed-Shareによるモデルの混合、同期・手元の2つの版の混合）と、「細部」（クラス別の監視、1件刻みの逆向きの探索、クラス別の機能的なクラスタリング、候補の共有部の固定、warm startの学習者、集約後の再較正。ほかにadapter）がある。

## 2. 細部を全部外した簡素版（計画と準備）

- 1つずつ外した効果は小さい（±0.4pp以内、adapterは約−0.6pp）が、全部を同時に外した効果は測っていない。
- 研究ツール`tools/research_simplified_fedhasp/`。既存の1つ外した構成（`fedsda-overall-loss-esr-detection`、`fedsda-minimum-interval-multiples-change-interval-search`、`fedsda-loss-distance-clustering`、`fedsda-without-candidate-validation`、`fedsda-without-warm-started-learner`、`fedsda-without-prediction-weight-recalibration`。変種`simplified-without-adapter`はさらに`fedsda-without-concept-specific-adapter`）の、`fedsda`とのrun設定の差（葉の単位）を全部重ねる。7構成の差は設定の葉9個で、重なりは無い。掃引の計画を作る関数だけを差し替え、製品のコードは変えない。
- 手元の確認: 研究ツールの検査34件（1つの構成だけを重ねるとその構成のrun設定と完全に一致する、2つの変種の差が外した構成の差の和と一致する、同じ設定を違う値に変える構成の組を止める、計画の差し替えは`fedsda`だけでrunの識別子が変わる）。SEA2・MNIST4・FMNIST4、間隔50、seed 0、10 client×600標本で2変種6 runが完了し、保存されたrun設定に外した値が全部入っていた。本規模の計画は2変種×10データ×間隔50・500×seed 0〜9の400 runで、既存の結果との重複は無い。
- 結果が届いたら、段3（FedHASP）・段1・段2と同じseedで対にして比べる。
- 追加（2026-11-19）: 簡素版でも予測の段をそろえるため、変種`simplified-local-model-mixture`（簡素版＋手元の版だけで予測＝モデルの混合だけ）と`simplified-hard-prediction`（簡素版＋今のモデル1つで予測＝柔らかい予測を全部外した基盤だけ）を足した。予測の構成の差（`fedsda-local-parameter-prediction`・`fedsda-single-model-prediction`）は細部の差と重ならない（再較正の葉は同じ値）。検査は50件（予測の段の変種が「簡素版＋その予測の構成の差」と一致することを足した）、SEA2・MNIST4の小さいrun 4本が完了した。本規模は2変種×200 run。

## 2の結果: 細部を全部外した簡素版（2026-11-19、主担当）

- 入力: `results/fedhasp-simplified-v16/20261119_simplified-seeds0-9`（uranium、commit `c3165415`、追跡するファイルの未commitの変更なし、4変種×200 run、失敗0）。各変種の全200 runの保存したrun設定に、外した構成の値が入っていることを確かめた（adapterの値は`simplified-without-adapter`だけ、予測の値は予測の段の2変種だけ）。集計は`research_core_component_ladder`に簡素版を足した（出力は同じ`analysis_core_component_ladder.md`）。各runで正誤の平均が要約の精度と一致した。
- 簡素版の積み上げ（10データの等重み、seed 0〜9）: 間隔50で、基盤89.20 → ＋モデルの混合89.37（+0.17）→ ＋版の混合91.02（+1.65）→ adapterも外す90.49（−0.53）。間隔500で87.77 → 88.05（+0.27）→ 88.96（+0.92）→ 88.46（−0.51）。単一モデル（81.10／80.40）からの基盤の増分は+8.1／+7.4。
- 簡素版−細部を残した同じ段（pp、95%区間、簡素版が上回ったseed）: 簡素版−FedHASPは間隔50で−0.67 [−0.87, −0.47]（0/10）、500で−0.57 [−0.78, −0.36]（0/10）。基盤の段どうしは−0.53・−0.60、モデルの混合の段は−0.75・−0.65。間隔50の差は変化の直後（間隔50件）に集中し（簡素版−FedHASPで直後−4.93、それ以外−0.46）、間隔500では直後−0.88・それ以外−0.33。
- データ別（簡素版−FedHASP、間隔50）: FMNIST4 −2.80、FMNIST2 −1.15、MNIST4 −0.71、CIRCLE2 −0.55、MNIST2 −0.44、ROTMNIST2 −0.41、ROTMNIST4 −0.25、SINE2 −0.18、SEA2 +0.05、SEA4 −0.30。
- 資源: 簡素版の通信はFedHASPの0.99倍（6,441対6,504 MB、間隔50）、MACは約0.91倍（1.08e8対1.19e8）。adapterも外すと通信0.94倍・MAC0.87倍。
- まとめ（数値をそのまま述べる）: 細部を全部外すと、1つずつ外したとき（±0.4pp以内）より大きく下がり（−0.6pp、10/10 seedで下）、差は変化の直後とFMNIST（一部のクラスだけが変わる概念）に集中する。細部は全体としては変化の直後の適応に効いている。どの細部の組合せが効いているかは切り分けていない（候補: warm startの学習者はFMNISTの新しいモデルの約6割で選ばれる、クラス別の監視）。基盤（+8pp）と版の混合（+1.6pp）が精度の大半を担う形は、細部が無くても変わらない。
