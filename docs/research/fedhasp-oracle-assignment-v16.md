# FedHASPの固い割り当ての上限（FedHASPを土台にしたOracle、基準版16、計画 2026-11-01）

- 目的: FedHASP（基準版16）の固い割り当て（検出・帰属先の選択・統合）を真のコンセプトで正解にしたときの精度を測り、(1) 固い割り当ての誤りで失っている精度（伸びしろ）、(2) その内訳（検出だけを正解にした分と、帰属先の選択・統合まで正解にした分）、(3) FedDriftを土台にしたOracle（`feddrift-oracle-concept-assignment`）との差（割り当てが正解のときの、柔らかい予測と標本ごとの学習の寄与）を示す。論文の5.5節（固い割り当ての分析）の診断に使い、比較手法の表には載せない。
- 背景: 2026-11-01のユーザー判断。基準版13のときに、SEA2・SEA4だけで同じ診断をし、Oracleが+1.1〜+1.8pp上だった（[IMPROVE-030](improvement-candidates/improve-030-split-partially-changed-concept-on-client.md)の2026-10-27の節）。

## 使う研究ツール

既存の`tools/research_oracle_concept_assignment`（基準版13のときに作成）。製品の構成`fedsda`をそのまま動かし、実行中だけ次を差し替える。

- `product-default-oracle-concept-assignment`（Oracle）: (a) 警報: 監視器の合図を使わず、clientごとに真のコンセプトが変わった標本から5標本目（変化区間がちょうど最小の5件になる標本）で警報とする。次の変化がそれより前に来たら、前の変化の警報は出さない。(b) 帰属先: 警報の後のMDLの選択の結果を、変化区間＝5、行き先＝そのclientが持つ、割り当てた学習標本の多数派のコンセプトが新しいコンセプトと同じモデル（複数なら学習標本の多いもの）、無ければ新しいモデル、に置き換える。(c) 統合: クラスタリングの対の判定の値を、多数派のコンセプトが同じ対だけ統合する値に置き換える。ほかの部品（モデル、学習、予測の混合、候補の学習と初期値、通信、監視器の計算）は製品のまま。
- `product-default-oracle-change-alarm`（検出だけOracle）: (a)だけを置き換え、帰属先の選択（製品のMDL）と統合は製品のまま。
- `product-default`: 差し替えなし（製品の`fedsda`と全記録が一致することを、既存の検査`test_default_entry_matches_direct_product_all_records`が確かめる）。

2026-11-01に、基準版16の製品（HEAD `7874c449`）の上で既存の検査17件がすべて通ることを主担当が確かめた。

## Oracleの性質（論文で書く点）

- 「正解」でも、警報は変化から5標本目（最小の変化区間）で出るので、変化の直後の4標本は前のコンセプトの扱いのまま。予測は製品の柔らかい予測のままで、真のコンセプトのモデルを直接使うわけではない。したがって、このOracleは「固い割り当て（いつ・どこへ・どれを統合）が正解のときのFedHASP」の上限であり、予測の上限ではない。
- 基準版13の結果では、Oracleは新しいモデルの採用が多く、通信・計算が増えた。費用は比較の対象にしない。

## 必要な作業（実装担当）

1. 基準版16への確認と文書の更新: docstringと入口の説明（「基準版13」の記述、`--purpose`の既定のIMPROVE-030の文）を基準版16・本計画に合わせる。基準版16の既定（1件刻み・逆向きの変化区間の探し方、2つの学習者、候補の検証の削除）の下で、差し替えが意図どおり働くことを確かめる。とくに、(b)の選択の差し替えで、製品の選択の関数に渡る値（変化区間ごとの新しいモデルの符号長、学習者の名前）の形が基準版16で変わっていないか、変化区間5の値が必ずあるか。
2. 10データへの対応: 新しい4データ（fmnist2、fmnist4、rotmnist2、rotmnist4）で動くこと（Fashion-MNISTのデータの場所の環境変数`FDE_FASHION_MNIST_DATA_DIR`を含む）。真のコンセプトの多数派の判定・統合の差し替えが4コンセプトのデータでも働くこと。
3. 分析の追加: 既存の`analyze`（3つの精度、見逃し、混入、統合など）に、10データ×間隔の組ごとの、(i) 3変種の累積の精度（10 seedの平均±標準偏差）と対の差（Oracle−既定、検出だけOracle−既定）、(ii) 変化の直後の $I$ 標本とそれ以外の精度（`docs/research/feddrift-post-change-accuracy-20261101.md`と同じ定義）、(iii) 新しいモデルの採用の回数、通信、MAC、を足す。FedDriftを土台にしたOracleとの比較は、主担当が製品の結果と突き合わせて集計する（研究ツールには入れない）。
4. 検査: 既存の17件に加え、(a) 基準版16の`product-default`が製品の`fedsda`と全記録で一致する（既存の検査を基準版16で通す）、(b) 4コンセプトのデータ（MNIST4かrotmnist4）とfmnistで、小さい全体runのOracleの警報・帰属・統合の検査（既存の`test_small_run_alarm_assignment_and_consolidation`と同じ内容）が通る、(c) 分析の追加の項目の小さい検査。

## 条件（本規模）

- 10データ（SINE2、CIRCLE2、SEA2、SEA4、MNIST2、MNIST4、fmnist2、fmnist4、rotmnist2、rotmnist4）×集約間隔50・500×seed 0〜9、10 client×5000標本。3変種（`product-default`、Oracle、検出だけOracle）で600 run。研究室サーバ（uranium、64 workers）。`product-default`は製品の結果を流用せず、同じ実行で流す（研究ツールの経路の一致を本規模でも保つため）。
- 間隔は、論文の頑健さの主張の両端の50と500にする。

## まとめ方（事前に決める）

- データ×間隔の20セルごとに、Oracle−既定、検出だけOracle−既定の精度の差（10 seedの対の平均、95%信頼区間、勝ち/負け）。全体の値は20セルの等しい重みの平均。
- 内訳: 検出だけで取れる分（検出だけOracle−既定）と、帰属先の選択・統合で取れる分（Oracle−検出だけOracle）。
- FedDriftを土台にしたOracle（同じデータ・間隔・seed）とFedHASPのOracleの差（割り当てが正解のときの、柔らかい予測と標本ごとの学習の寄与）。
- 論文の文は、これらの数値をそのまま述べる（「固い割り当てを正解にしても精度はa〜b pp上がるだけ」または「SEAではc pp上がる」など）。「近い」「十分」などの二値の結論の基準は置かない。

## 計画レビュー（GPT-6 Luna、effort medium）の反映（2026-11-01。上と食い違うときは、こちらを優先する）

1回目FAIL（Major 3）。全部反映する。

- 分析（Major 1）: 今の`analyze`は既定と1変種の対だけを、データごとに間隔を平均して集計する。これを次のとおり拡張する（作業項目3の具体化）。同じデータ・間隔・seedの3変種がそろうことを確かめ（そろわなければ止める）、20セルごとに、各変種の累積の精度の10 seedの平均±標準偏差、対の差（Oracle−既定、検出だけOracle−既定、Oracle−検出だけOracle）の平均、対の差のt分布による95%信頼区間、勝ち/負け/同じの数を出す。全体の値は20セルの等しい重みの平均。変化の直後の $I$ 標本とそれ以外の精度、新しいモデルの採用の回数、通信、MACもセルごとに出す。出力はCSVとMarkdown。
- 検査（Major 2）: 小さい全体runの検査を、SEA2（既存）に加えてfmnist4（4コンセプト、Fashion-MNIST）で行う（間隔50、seed 0、10 client、各client 600標本程度。少なくとも1回のコンセプトの変化と1回のOracleの警報が起きることを先に確かめ、起きなければ標本数を増やして固定する）。検査の内容は既存の`test_small_run_alarm_assignment_and_consolidation`と同じ（警報が変化の5標本目、選択の区間が5、混入なし、統合が多数派の同じ対だけ）に加え、(a) 差し替えの中で、製品の選択の関数に渡る`new_model_code_lengths_by_change_interval_sample_count`と`new_model_learner_names_by_change_interval_sample_count`のキーが5から列の長さまでの全部の整数で、両方の辞書のキーの集合が一致し、区間5の値が有限であること、(b) 2つの学習者（初期化し直した学習者とwarm start）の両方の符号長が計算されていること、を実際のrunで記録して確かめる。
- 「上限」の表現（Major 3）: このOracleは、FedHASPの精度の数学的な上限ではない。「固い割り当て（警報の時期、帰属先、統合）だけを、決めた規則で真のコンセプトに合わせた診断の条件」であり、新しいモデルの候補の学習と採用、予測の混合、学習そのものは製品のまま。論文では「この割り当ての条件の下での比較」と限定し、モデルの学習や予測の上限ではないことを書く。上の「Oracleの性質」の「上限」は、この意味に読み替える。
