# 採用モデルの登録・統合・予測利用を追跡する（2026-10-24）

ユーザー指示により、uraniumの[共有部接続の計測](fedsda-shadow-feature-reconnection-20261024.md)の実行中に、手元で独立した追跡計測を準備する。製品srcと既存の採用コード・共有部接続計測ツールは変更しない。研究ツールなのでspecは不要という指示を維持する。

## 記録の範囲

採用ごとに、client内の一時ID（負）から正式ID（非負）への登録、集約時の概念固有部の更新の送信、クラスタ統合による代表ID、clientへの配布、実際の予測係数を記録する。登録は正式IDの採番・clientへの確認であり、パラメータの送信はその後の集約で行われる。追跡ではこの既存実装の順序を記録する。

IDのscopeは負IDがclient内、非負IDがrun全体。異なるclientで同じ負IDが使われても混同しない。統合では吸収されたIDだけでなく、代表IDとして残る側も他モデルと混ざるため「最初の統合」と数える。

予測結果が持つ正規化済みのモデル別重みを読み、統合前と統合後の代表に分け、client別に評価標本数・正重みで使われた標本数・係数の和・最大重みになった標本数・最初/最後の標本位置を保存する。同期側と局所側の混合重みはラベル観測による更新前に読み、両側への係数の内訳も残す。追加のモデルforwardや勾配更新を行わない。

**統合後に代表IDが予測で使われても、元の採用モデルの寄与率とは解釈しない。** 記録は概念固有部のIDの来歴で、FedAvg/統合の実際のパラメータ寄与率や、全モデルで共有される特徴部の来歴を復元するものではない。同じ代表に統合された採用は同じ予測をそれぞれ数えるので、採用モデル×client×標本の延べ数であり、uniqueな予測数として合算しない。

## 非介入の検査

同じ条件の計測なし採用runを参照し、baseline/measuredの全保存値（秒数以外）・MAC全計数・影の生成/採用の全記録を照合する。計測のためのモデル演算が無いため、MACを差し引かずそのまま比較する。時間は追跡のCPU処理を含む経過時間で、並列負荷にも影響される。

参照側は大きい掃引の一部を再利用できるため、余分な条件を許す。計測側の各条件には必ず対応する参照が必要で、欠落は辞書参照のKeyError、不一致はValueErrorで拒否する。参照側のキー重複も拒否する。対数は参照全件数ではなく、実際に照合を完了した計測側の条件数。専用testで、余分な参照を許す一方、欠落・値の変更・重複を拒否することを検査する。

## 検証中に分かったこと

最初のSEA4通常・seed1・600標本の専用実runでは、全保存指標・影の生成/採用経路の一致は通った。一方、「登録・統合イベントを必ず含む」というtestの仮定で失敗した。呼出しとID変化を別途記録して調べたところ、2件の採用は終了時も未登録のまま、送信保留と保有一覧に残り、局所の予測に使われていた。記録hookの欠落ではなかった。

既定の登録方針はregister_pending_model_after_waiting_as_current_modelで、現行の学習帰属である送信保留だけ待ちを進め、登録時にも現行である必要がある。従って、未登録を「即時統合された」と解釈してはいけない。testはこの打切り経路を確認するものへ修正し、登録・統合まで進む経路は別入力の実行で検証する。

正重み標本数は上記の延べ数。統合前には一時IDの局所利用も含む。正式登録4件は全て同じ同期回で初回統合され、その前にglobal IDでの正重み予測はなかった。ただし、それ以前の一時IDの利用はある。4件中3件は最終同期（round5、標本index599）で初回統合され、統合後の予測機会が無い。残るSEA4概念2固定の1件はround1（index199）で登録・統合され、以後の代表IDに正重みの予測4000件があった。これは元の採用モデルが単独で4000件に寄与したという意味ではない。

SEA4通常の未登録2件は、採用index217/505から終了までそれぞれ382/94件で正重みの予測に使われた。両者の統合前の平均係数は延べ評価標本に対して0.063988。「未登録なので予測に使われない」という説明は、この実装・入力には当てはまらない。

この600標本・1seedの結果だけでは、サーバの5000標本・10seedで同じ割合になるか、未登録や統合が精度低下の原因かは分からない。未登録や最終同期での統合は、観測期間の打切りを含めて扱う。
