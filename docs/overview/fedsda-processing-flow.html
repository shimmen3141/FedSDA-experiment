図の読み方と前提

薄い部分は背景、濃い部分はこのコマの対象です。中央の菱形は、MDLで変化点と帰属先を選ぶ一つの判定です。標本やモデルの保存場所ではありません。★は予測の最大重みではなく、現在の学習帰属を示します。

配布時と更新用は、同じモデルIDの2状態です。配布はまず更新用へ反映し、その直後の全状態を配布時側へコピーして固定します。追加学習するのは更新用だけです。新規モデルに配布時の対がまだなければ、その固有部は更新用を使います。

混合するのは予測確率です。配布時・更新用を共通のモデル別重みwでそれぞれ結合し、その二つを重みvで混ぜます。wは配布時側の各モデルの損失、vは二つの結合予測の損失で、正解観測後に更新します。損失はいずれも1−正解確率です。分け合いの時間尺度Tはwとvで共用（既定120標本）。𝐩ₘと𝐩ₘ′は入力xₜに対する全クラスの予測確率ベクトルです。

FIFOは、学習データの帰属を保留する場所です。平時の容量は30件。新着標本を足してからMDLへ渡すため、警報時の評価列Wは最大31件です。FIFO左の枠外の標本は容量超過分の模式表示で、別バッファではありません。通常は超過分を現行ストアへ確定してFIFOから外します。警報応答では選んだ変化点より前を現行へ、末尾の選択区間を選んだモデルへ取り込み、FIFOを空にします。現在維持ではW全列を現行へ取り込みます。

警報の後は、MDLで変化点と帰属先を同時に選びます。検出器の合図を受けた時点の更新用モデルでW全列を評価し、「現在のまま」「変化点τで保持モデルへ」「変化点τで新しいモデルへ」の符号長を比べます。保持モデルへの切替候補は、現行以外で損失統計を持つモデル。基準版16では、変化区間長kは5件以上・Wの長さ以下の全ての整数を1件刻みで試し、保持モデルの区間損失和と、新しいモデルの予測的符号長を比べます。後者は学習者ごとに、新しい方（警報の標本）から古い方へ1本の流れで測り、途中までの和を各kに使います。全てのkと帰属先の組から最短を選ぶ時点で初めて変化点τが決まります。同率なら現在維持、短い区間、保持モデル、新モデルの順を優先します。現在維持を選んでも現行が履歴の基準を持たなければ新モデル作成へ進みます（図の現在維持は基準を持つ例）。固定の許容量γによる再利用判定ではありません。

格子と経路の読み方。列は1標本（通常のMDL拡大図は16件の模式例、件数不足は4件）、行は更新用の保持モデルです。単色の濃淡は対数損失 −ln p(真のクラス)を表します。各経路は区切りτより前を現行0′、後を行き先で説明します。右の棒は「τより前の損失和」＋「τ以後の損失和」＋「切替の符号長」。新モデルの後半は二つの測定用学習者の短い方＋ln 2です。切替の符号長は −ln(1/T)＋ln(保持モデルの行き先数＋1)、Tは予測のFixed-Shareと同じで既定120です。これは各標本で確率1/Tの切り替わりがここで起きたことと行き先を表す長さで、この分より多く損失を減らすときだけ切替の仮説が選ばれます。薄い経路は候補の一部です。棒の長さと色は模式値から計算しています。学習に伴う損失低下は模式例であり、実際の各標本で単調に下がる保証はありません。

新モデル仮説の学習者は、実際に作る候補とは別です。現在モデルの写しの固有部を初期化し直した学習者と、初期化せず学ぶwarm startの学習者を使います。共有部を固定し、標本ごとに予測→対数損失の加算→1回更新を行います。学習は学習者ごとにWの件数回（最大31回）。初期化seedはclientの番号と警報の標本の番号から決まり、kには依存しません。各kで予測的符号長の短い方にln 2を加えます。符号化の順序が受け手に分かれば逆向きでも正しく、同じ概念内の標本が交換可能なら順序によらず符号長の期待値は同じです。ln 2はどちらの学習者で符号化したかを一様選択として表す長さ −ln(1/2)で、新モデルの仮説だけが二度試して短い方を選べる有利さを補正します。測定用学習者は捨てます。実候補の初期値は、履歴基準を使える保持モデルのうち選択区間の有界平均損失が最小のモデルの写し（なければ現行モデル）です。

件数不足では、警報にせず通常処理を続けます。MDL選択後の区間長とFIFO件数の小さい方が5件未満なら、警報の記録・監視の再初期化を行わず、検出器の証拠を残します。MDLの切替候補は5件以上の末尾区間なので、Wが5件以上なら検出器の推定区間が短いことだけでは保留しません。件数充分の場合は、警報を記録し、選択済みの区間と帰属先に従って取り込みます。

監視基準は、損失低下に応じて引き下げます。低下側e-SRが損失低下を検出し、悪化警報がなく、現行モデルの履歴平均が現在の凍結基準より低い場合に、その平均で全体・正解クラス別の監視を再開します。初期モデルの損失統計は、事前学習標本の5分割交差検証で各標本を学習に使わない一時モデルの損失から作ります（実際の初期モデルは全事前学習標本で学習）。

コードでは監視が先だが、二つは互いの結果を使わないので順序を入れ替えて示す。

共同学習は、警報にならなかった標本の処理の最後に行います。変化の合図がない場合も、件数不足で警報を保留した場合も、FIFOの容量超過分を現行ストアへ確定した後、学習要求を1件記録します。既定の間隔（training_requests_per_update_interval = 1）では、毎標本1回、各モデルのストアから小バッチ（既定32件）を取り、更新用の共有部と固有部を共同学習します。小バッチの件数に満たないモデルは参加しません。FIFOが満杯でなく確定する標本がない間も、ストアに既にある標本で学習し、FIFO内の今の標本はまだ使いません。警報になった標本では要求を記録せず、取込み後の共同学習も行いません。取り込んだストアでの共同学習は、次の標本で通常の流れのN05へ進むときからです。新モデルを作る場合の候補の固有部の学習は、警報の処理の中で別に行います。学習要求をまとめる設定（間隔＞1）では要求が溜まり、間隔に達したとき・警報の前（MDL選択後、取込み前）・ラウンドの境界で消化します。既定では要求が溜まらず、警報の前とラウンドの境界での消化は何もしません。

新モデルの作成では、共有部を固定して固有部を学習します。MDLで選んだ変化区間を学習部分と早期終了用の検証部分へ分け、adapterと分類層だけを更新します。学習後は同じ警報応答で即時採用し、区間の標本を新モデルの学習ストアへ追加します。将来標本を使った候補の採否検証や、そのための待ちはありません。通常の共同学習では、標本のある各モデルの損失を標本数で重み付けし、共有部と固有部を更新します。

クロス評価は、先行配布済みのモデルで行います。登録可能な新モデルがあり、集約対象IDが複数あるラウンドでは、共有部1個と全モデルの固有部を先に全clientへ配布します。対象モデルの標本を返せるclientだけを選び、上限がclient総数なので候補全員へIDで依頼します。全候補モデル×全対象モデルの組を評価し、異なるIDの組では手元の対象モデルも同じ標本で推論して正誤を比較します。⇔は予測比較の関係です。

返信するのは評価結果の統計です。損失や正誤の集計を返し、生の標本は返しません。受信済みモデルは評価後も反映まで保持し、その間は手元の更新用・配布時モデルを置き換えません。クラス別の片側だけ正解の割合の信頼下限で階層クラスタリングし、学習ストアの標本件数を重みに平均して代表IDへ統合します。統合時だけID対応と変更された代表の固有部を再送し、共有部も変わった場合だけ再送します。その後、受信内容を更新用へ反映します。

評価用ストアは、学習用ストアとは別に保持します。警報応答の変化点より前の標本から、非負のモデルIDへ1回最大20件を無作為抽出して追加し、最新50件を保持します。評価ストアに6件以上あれば使い、足りなければ対象が現行モデルかつ学習ストアに11件以上ある場合だけ学習標本を代用します。評価時は最大50件を抽出します。更新用側も過去の予測値を流用せず、その場で推論します。

手元への追加とサーバへの登録は別です。新モデルはすぐに手元で採用しますが、サーバIDの登録には現行モデルとして待つ処理が残ります。現行である同期の後だけ待ちを1回進め、既定1回の待ちを終えた次の登録機会で、現行であるモデルだけを登録します。別モデルが現行の間は停止し、戻れば再開します。段6は後のラウンドの例です。新モデル作成の分岐では登録待ち済み・集約対象複数、他の分岐では登録可能な新モデルがない状況を示します。サンプル分岐だけでサーバ条件が決まるわけではありません。

共有と再較正は、ラウンド境界で行います。登録ではIDだけを割り当て、集約でパラメータを1回だけ送ります。非負IDかつ学習ストアが非空のモデルが参加し、共有部はclientごとの参加標本件数の合計で、固有部はモデルIDごとの件数でFedAvgします。配布反映直後の状態を予測用に保存し、FIFOを更新用の各モデルで再評価してモデル別重みwを時系列で再構築します。モデルの値と二者重みvは保持します。FIFOが空、またはモデルが1個以下なら再生しません。モデル数・標本の絵は模式例です。
